## Scope

In scope:

1. **The preload question is answered by a run, and the run is recorded.** The run asks whether a skill whose frontmatter carries `disable-model-invocation: true` still reaches an agent through that agent's `skills:` list on Claude Code as installed when the run is made. The orchestrator takes the run before it spawns the crafter for phase 1, by the method of `frame/plan.md` *The measurement step, before phase 1*, and writes `frame/questions.md` Q1's `Status` where the run answers it. Where the run is made, the phase 1 crafter writes its record as a new file under `docs/experiments/` in the shape G13 gives, dated by the day of the run, from the transcripts the orchestrator names. Where the run cannot be made, Q1 stays open and the build continues on the default Q1 states.
2. **`core` and `agent-contract` keep their preload and carry a short description.** Each frontmatter keeps `user-invocable: false` and takes no `disable-model-invocation`, whatever the run of item 1 shows (`frame/plan.md` *Alternatives considered*, rows A1 and A2). Each description becomes at most two sentences that say what the file holds and that an agent receives it preloaded, and, for the core, that the plugin's `SessionStart` hook prints it into a session. Neither description keeps a `Use when:` line or a `NOT for:` clause.
3. **A `NOT for:` clause stays only where G10 records the confusion it names.**
   - code-review keeps one item, the person typing `/code-review` by name, which runs Claude Code's built-in command. Its items on implementing fixes and on style-only linting go.
   - commit-pr-convention keeps one item, the prose and structure of a PR body or review comment, which belong to writing-style. Its items on code comments and docstrings and on a project's response language go.
   - writing-style keeps one item, commit, PR-title and branch format, which belong to commit-pr-convention. Its item on code comments and docstrings goes.
   - implement, legacy-parity, settle and verify lose their `NOT for:` clause whole.
   - The `Use when:` lines and the opening sentences of these seven descriptions do not change.
4. **The cases follow the descriptions.**
   - `tests/behaviour/test_chain_hooks_hardening.py#test_auto_firing_skills_declare_when_not_to_fire` goes (`## Removes`).
   - A new case in `tests/behaviour/test_chain_hooks_hardening.py`, beside `#skill_groups`, fails where a skill that some definition under `agents/` lists in its `skills:` carries `disable-model-invocation: true`, and names each such skill. It reads the sets `#skill_groups` already builds. It replaces the contract-only assertion of G9 (`## Removes`), so the core is held by the same case as the contract.
   - The module docstring of `tests/text/test_the_agent_contract_holds_the_universal_rules.py`, lines 39 to 42, and the comment above the assertion that goes, stop citing the 2026-09-03 record for `disable-model-invocation`. The docstring cites the documentation of G7 and, where it exists, the record of item 1.
5. **The totals stand in the work item's records.** The total before is 4,860 characters at `24c5276f` (G5). The total after is M1's output at the commit that closes phase 1. The phase 1 record states both totals with M1's command, and `changelog.md` states both.

Out of scope:

- The `Use when:` lines and opening sentences of code-review, commit-pr-convention, implement, legacy-parity, settle, verify and writing-style. The issue proposes no cut to the triggers, and no run on record shows which wording makes a model choose a skill (G10).
- The descriptions of the agent definitions under `agents/`. The issue measures skills alone. A later issue can weigh them by the same method.
- The descriptions of `config`, `parity-setup` and `update`. G6 and G7 show that a skill with `disable-model-invocation: true` puts no description into the listing.
- A run of the model's choice of a skill for each removed clause. `frame/plan.md` *Alternatives considered* row A7 holds the grounds.
- A meter of the listing in `agentic payload`, and a case that holds a description's length. `frame/plan.md` *Alternatives considered* row A8 holds the grounds.

## Data & interfaces

Each change is to a `SKILL.md` frontmatter, the YAML block between the file's first two `---` lines.

- `skills/core/SKILL.md` and `skills/agent-contract/SKILL.md`: `description` is replaced as *Scope* item 2 states. `name` and `user-invocable: false` stay. A YAML plain scalar ends at a colon followed by a space, so a description that holds one keeps the literal block form `description: |` the files use now.
- `skills/code-review/SKILL.md`, `skills/commit-pr-convention/SKILL.md` and `skills/writing-style/SKILL.md`: the `NOT for:` clause keeps the one item *Scope* item 3 names, with the label `NOT for:` spelt as now, which `#test_the_writing_style_handoff_names_a_skill_that_ships` reads.
- `skills/implement/SKILL.md`, `skills/legacy-parity/SKILL.md`, `skills/settle/SKILL.md` and `skills/verify/SKILL.md`: the lines from `NOT for:` to the end of `description` go.
- No body of a `SKILL.md` changes, so `lib/core.py#rendered` prints the same core.
