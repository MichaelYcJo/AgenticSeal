**The approach.** The rename is cut by layer and family, one family a phase, as #1656 cut its rename. At `1790fab7` the lowercase `iadd` holds four senses, the product, the command, the place and the fence, and the uppercase `IADD` two, the method and the product. A phase renames the occurrences of its own family, reads the lines of D1 that none of E1 to E4 matches for its sense (`frame/design.md` G22), and leaves the others to their phase. The generated eval cases are written again with `python3 evals/scripts/rule_cases.py --out evals/behaviour` in each phase that changes what the generator writes.

**Where the root moves.** Phase 1 changes `lib/optin.py#HOME` and `#MARKER` and moves this repository's `iadd/` to `agentory/` in one commit, both work items' directories with it. No installed tool reads `iadd/` in this checkout (`frame/design.md` G10), so the move costs no later phase a reader, and the three exemptions of G8 go in the commit that makes each of them excuse nothing. #1656's directory moves with `git mv` and no byte of it changes in phases 1 to 4. Phase 5 rewrites its `changelog.md` alone, and its `routing.md` and `frame/design.md` stay exact moves to the last commit (`frame/design.md` G6).

**How each step runs.** The work item's directory is `iadd/threads/1795830609-iadd-is-the-method-and-a-product-only-expresses-it` until phase 1's commit and `agentory/threads/1795830609-iadd-is-the-method-and-a-product-only-expresses-it` from it. The parties are spawned as `routing.md` *Why this way* says, bound by this tree's `agents/<name>.md`, `skills/core/SKILL.md` and `skills/agent-contract/SKILL.md`. The installed release's `Stop` hook finds no `seal/` root here and draws nothing, so the orchestrator draws the stamp with `bin/agentic stamp --from <path>`, as #1656's run did.

**The failure scenario of the chosen approach.** A phase misreads a sense: it renames the fence's `iadd`, or a test's bare `"iadd"` that builds a root is renamed `agentic`, so the case builds no root, the code reads `agentory`, and the case passes on the wrong fixture. The searches find an `iadd` that stayed and cannot find one renamed into the wrong layer, so a wrong rename is found only by the round that reads the diff. In six months the likelier break is in a repository that moves later: one that moves `seal/` to `agentory/` and leaves its `hygiene.yml` pinned to 0.39.x reads no root, and its pull requests pass with no work item judged, which #1651 *How the repositories move* already names. *Operational impact* names the pinned tag for that reason.

- **The install updates in place.** The plugin and the marketplace return to `agentic` and `agenticseal`, the names the one install holds (`frame/design.md` G10), so `/agentic:update` takes the release that carries this work with no new registration.

The template clones into `$RUNNER_TEMP/agentic`.
- **An export archive is read under the root's name.** `agentic import` reads each member under `agentory/`, so an archive written under another root's name is refused at its first member.
- **#1656's entry in the release's note links to this pull request.** The note reads each fragment under `agentory/` and links it to the oldest commit that adds that path, which is this pull request's (`frame/design.md` G16). Questions row Q3 holds what is done about it.
