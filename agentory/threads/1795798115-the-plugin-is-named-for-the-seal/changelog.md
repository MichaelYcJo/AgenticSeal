### Changed

- **The plugin is IADD, Independent AI-Driven Development, and its identifier is `iadd` (#1651).** The plugin, its marketplace and the prefix of every agent and skill are `iadd`, so a spawn names `iadd:crafter` and the update command is `/iadd:update`. `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` and `README.md` describe it as *IADD, Independent AI-Driven Development: agents frame, build, review and inspect a change, no agent approves its own work, and it ends in an inspection bound to a commit.* The first line the `SessionStart` hook prints opens `IADD core from`. Each variable, file and directory where `agentic` named the plugin takes `iadd`: the variables `IADD_GATE_INVOKED_AS`, `IADD_RECORD_DIR` and `IADD_RECORD_KEY`, the pytest recorder `iadd_pytest_record`, the opt-out file `iadd-scratch`, the stamp's directories `iadd-stamp` and `iadd-stamp-refused`, the export's `iadd-last-export.json`, and the machine-local maps under `~/.claude/iadd/`. The routing question's first answer is still spelt `agentic`, because it names the answer that leaves each item's route to the orchestrator and not the plugin. The repository keeps its address, `MichaelYcJo/AgenticSeal`.
- **The final party is the inspector, and its record is the inspection.** `agents/sealer.md` is now `agents/inspector.md`. The inspector writes `inspection.md` from `templates/records/sdd-inspection.md`, whose title line is `# Inspection: <work-item-id>`, and `docs/forms/the-inspection.md` owns the form. A verdict reads `Verdict: cleared`, `Verdict: withheld reason: <reason>` or `Verdict: undecided question: <question>`. `chain_check.py` refuses `Verdict: sealed` at its line as a value that does not read whole, and no reader accepts the old spelling. `docs/forms/the-inspection.md` *The three states* says once when a work item is cleared, lapsed or not cleared, and the messages of `chain_check.py`, `pr_body.py` and the stamp use those words. The check's flag for the run before the verdict is `--inspecting`, the stamp's flag is `--inspection <path>`, and the named checks are `ready-needs-cleared`, `refused-cleared-leaves-a-record` and `parity-in-the-inspection`. The verify skill's evidence protocol is the Inspection Test. The Korean documents call the party 검수자, the record 검수 and the verdict 합격.
- **The command is `iadd`, the records root is `iadd/`, and each form a script reads takes the plugin's name.** `bin/iadd` and `bin/iadd.cmd` run `skills/implement/scripts/iadd.py`, and each subcommand prints its lines as `iadd <subcommand>: `. The root is `iadd/`, at the repository's top in shared mode and under the common git directory in local mode, and its `README.md` opens with `# What IADD keeps in iadd/`, written from `templates/setup/iadd-README.md`. A commit ends with the trailer `IADD-Routing:`, and a fenced block a script reads fields in opens with the info string `iadd`. The settle reads `Seal-Routing:` as the trailer of the commits of releases before the one that renamed the plugin, so no committed trailer is rewritten.
- **The stamp, the mark and the mark's keys take the inspection's names.** The stamp is `skills/verify/scripts/stamp.py`, its sprite `stamp-mark.txt`, and its panel reads `CLEARED`. The mark's alternative text is `Cleared`. The config keys are `Pull request inspection mark` and `Release note inspection mark`. The release's mark is drawn by `.github/scripts/release_mark.py` in the job `mark` of `.github/workflows/publish-release.yml`, and attached as `mark.png`. A release note already published keeps the `seal.png` it attached. The drawings under `assets/seals/` keep their names, and the owl in `README.md` still shows the word `SEALED`.
- **A repository that runs the plugin moves by hand, in one commit of its own.** No release ships a migration. The marketplace and the plugin are both registered anew as `iadd`, so an installed `agentic` does not update into `iadd`: add the marketplace again, install `iadd`, and remove the old plugin. In each repository, move `seal/` to `iadd/` with `# What IADD keeps in iadd/` as the first line of its `README.md`, `guarantee.md` to `inspection.md`, each `seal` fence to `iadd`, and `Verdict: sealed` to `Verdict: cleared`. Rename the keys `Pull request seal mark` and `Release note seal mark` in `config.json`, because a key left under its old name turns the mark off without a message. Move the tag `hygiene.yml` pins to the release that carries IADD; the template now clones into `$RUNNER_TEMP/iadd`. The files outside a repository keep their old names until they are moved by hand: `~/.claude/agentic/pact-paths.json`, `~/.claude/agentic/parity-paths.json`, `agentic-scratch`, the stamp's two `agentic-stamp` directories and `agentic-last-export.json`.

### Added

- **`docs/method/iadd.md` defines IADD.** It says what IADD is, with its line *Zero Self-Approval: no AI approves its own work*. It gives each principle in one sentence beside the section of this repository that states it, the names with one sentence each and the Korean names, and the documents that own each record form of a work item. The names moved there from the *Naming* section of `docs/layout/one-root-by-lifetime.md` and its Korean edition. `docs/README.md` opens with the group `docs/method/`, whose reader is a person who wants to know what IADD is. No agent acts on it.

### Removed

- **The second shared root `agentic-seal/` is gone.** The root is looked for at `<repo>/iadd/` and then under the common git directory, and nowhere else. A repository whose own `iadd/` belongs to something else keeps its root in local mode. `iadd import --into shared` now refuses where something of the project's own stands at `<repo>/iadd`, as `iadd mode shared` already did.
- **The marketplace's `renames` map is gone.** It mapped `specseal` to `agentic`, and no rename entry carries `agentic` to `iadd`.
