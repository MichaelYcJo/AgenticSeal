### Added

- **A search that is to print lines the design keeps compares them with a keep file, so a leftover in a file that holds a kept line is printed (#1659).** A phase has at most one search that keeps lines, its patterns joined into one where the design keeps lines of several. Where a phase's search keeps lines, `frame/keep-<N>.txt` holds each one, a line a later phase changes or removes among them, as `git grep --no-color --no-line-number` prints it, sorted under `LC_ALL=C sort`, and `frame/keep-<N>-paths.txt` holds each path a path search keeps where the old spelling stands in a path. The two commands of `skills/verify/SKILL.md` *An absence claim is only as good as the search behind it* run from the repository's top level, compare the tree with them by `diff`, and print nothing when the phase is done. A line that opens with `<` is one the tree holds and the keep file does not, and a line that opens with `>` is a kept line the phase changed or removed. The framer writes the keep files before the build, and the builder keeps them in step with the kinds of line the design keeps. A frame no longer accounts for a kept line by naming its file, by excluding the file or by narrowing the pattern, since each of those hid every other line the file or the pattern covered. A rename in a repository that keeps no census of old spellings is proved by the frame's commands for the old spelling printing nothing.
- **`agentic range` prints a keep file's changed lines alone.** A keep file of the work item, `frame/keep-<N>.txt` or `frame/keep-<N>-paths.txt` under its directory, prints under `==> <path>: keep file, each hunk at its own lines <==`, each hunk as `git diff -U0` prints it with no function line after its header. A keep file holds no blank line, so before this change one changed line printed the whole file into the range file the builder reads to its last line. Another work item's keep file prints as any other text path.

### Changed

- **A phase's set runs under the command of each suite that owns one of its files.** The *Phase boundary* row of `skills/verify/SKILL.md` *Scope: cheap and often, broad and once* runs its set with one command for each suite, the commands the phase's *Verified by* cell names, where it ran the set in one command. A suite is a command the repository runs test files with, such as a unit runner, a built-app or end-to-end runner or an eval harness, and a test file belongs to the suite whose command runs it. The framer names in each *Verified by* cell every suite the phase's set falls in, found in the contribution guide, the CI workflows and the runners' configuration. A crafter that meets a file of a suite the cell leaves out runs it under that suite and names the missing command in the phase record. A fix pass takes its commands from the *Verified by* cells of the phases whose paths its fixes change, and names a suite none of them names in the close block of the finding whose fix met it.
- **The orchestrator weighs routing an issue's parts as separate work items.** `skills/implement/orchestration.md` *Under agentic* weighs it for an issue whose parts differ in kind and each leave the tree whole at their own merge. A split shrinks what each round of each part reads, and each extra work item costs a broad run, an inspection and a pull request. The name families of one rename stay phases of one work item. A part that does not finish the issue carries `Part of #N` in its `pr.md`.
- **The records' overview names the keep files.** The tree of `## Layout` in `templates/setup/agentory-README.md`, which first setup writes as a repository's `agentory/README.md`, lists `frame/keep-N.txt` and `frame/keep-N-paths.txt` after the frame's other files.
