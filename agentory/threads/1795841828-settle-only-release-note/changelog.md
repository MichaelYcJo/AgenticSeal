### Fixed

- **A release of settles alone publishes its own note (#1655).** A settle writes no changelog fragment, so the publish workflow failed on a release that carried only settles, and the notes of v0.39.4 and v0.40.1 were written by hand. Now, where no commit of the release added a fragment and every commit in it other than a merge removes whole a work item directory that stood at its parent, `.github/scripts/publish_release_note.py` puts the body of the release pull request, the one merged from `release/vX.Y.Z` into `main` whose merge commit is the tagged commit, where the fragments stand. The note keeps the header, the theme, the folds by type and the update section of any other note, so the mark job draws on it as on any other. The job still fails for every other release that added no fragment, and its log now names each commit that is no settle, by its short hash and subject. A release of settles alone whose release pull request cannot be listed, is not found or has an empty body fails too, and creates nothing. Since the body is published as written, a sentence in it saying that the note is still to be written would reach the note.
