### Changed

- **A merge of the base owes a verifying round by what its resolution changed, read from the merge commit (#1583, #1631).** `skills/code-review/orchestration.md` *Orchestrator: the pull request opens once the work item is cleared* has the orchestrator run `git show --remerge-diff --ignore-submodules=none --format= --name-only <merge>` once the merge is committed. The command prints each path where the committed result differs from git's own merge of the two parents, so it names a path resolved by hand and no path for a clean merge. A round is owed where it names a path outside the work item's records, and where the command does not run. A resolution in the records alone is read by the inspector, and a clean merge owes no round. Before this change the rule named no reading of which files a resolution touched.
- **After a merge past the newest broad run, the open pull request's checks stand in for the local broad run where they read the same checks (#1583, #1631).** They stand in where the pull request is open, its `pull_request` run runs each check the `Broad gate` command runs, as the orchestrator judges in the workflow files at HEAD, and `agentic pr-wait <N>` exits 0 at the merge or at a commit after it that changes only the work item's records. The stand-in counts only while the base's tip is in HEAD, which the orchestrator reads with `git merge-base --is-ancestor <base> HEAD` after a fetch, before it treats the pull request as checked. Where the base has moved past the run, the orchestrator merges the base again. Under `stop before the pull request`, before the pull request opens, or where the pull request's run reads less than the `Broad gate` command, the local broad run is taken again, as before. A merge after the inspector's verdict still owes `agentic pr-body` on the body file and the inspector again, and the orchestrator records each merge after the newest broad run in a row of `frame/plan.md` *Judgments of the run*.
- **The core's row *No inspection without the broad run* names who holds the merged tree.** In `skills/core/SKILL.md` *Judgment is not licence to skip a party*, the row protects a tree the `Broad gate` checks passed, whichever run took them, and names as the holder after a merge of the base the orchestrator's broad run or `agentic pr-wait`, beside the inspector's step 1 and the broad gate arm, which read the branch's own commits alone. The row *A merge, or a dependency bump* of `skills/verify/SKILL.md` *The narrow command still has to be able to fail* names the broad gate's checks over the merged tree as what proves a merge, and cites the orchestration section for which run takes them.
