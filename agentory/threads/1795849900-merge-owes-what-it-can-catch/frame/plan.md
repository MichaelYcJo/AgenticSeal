**The failure direction.** The change makes the orchestration rule allow more: after a merge of the base past the newest broad run, a passing pull request run stands in for the local broad run. A wrong allow lets a merged tree reach the base on the pull request's checks alone. That is the cheaper mistake here because the pull request's run reads the same checks over the same merged tree (G11), on two platforms where a local run reads one, and `agentic pr-wait` stops the orchestrator at exit 1 before it spawns the inspector. The same rule blocks nothing that passed before.

**What breaks in six months.** A repository's workflow stops running one of the `Broad gate` command's checks on `pull_request`, for example a typecheck moved to a nightly schedule, while an orchestrator reuses the judgment it wrote at an earlier merge. The merged tree then passes without that check. D7 asks for the judgment at each merge, read in the workflow at HEAD, so the cause is a judgment row copied rather than read, and the proofer meets it at the round that reads that row. A second failure is a defect only the local platform shows: here the stand-in reads ubuntu and Windows and not macOS, which the release pull request reads, as it does for every pull request into the release branch (G11).

## Operational impact

No migration, environment variable or dependency. The change is to what the orchestrator owes after merging the base, in every repository that installs the plugin. A merge after the newest broad run no longer owes a local broad run where the open pull request's `pull_request` run reads the `Broad gate` command's checks and `agentic pr-wait` exits 0 at HEAD. That holds while the base's tip is in HEAD when the orchestrator hands the pull request over; where it is not, the orchestrator merges the base again. A repository whose pull request run reads less, or a route that stops before the pull request, takes the local broad run as before.

This pull request carries the release's version move: the orchestrator's spawn of 2026-11-28 names this work item as the one that carries it. Phase 1's commit that adds `changelog.md` also writes `.claude-plugin/plugin.json`'s `version`. The phase reads the number from the name of the release branch its spawn names as the base, `release/v<X.Y.Z>`, which the framer's spawn of 2026-11-28 named `release/v0.42.0`. `hygiene.yml`'s version step reads the same key at the release pull request (G23).
