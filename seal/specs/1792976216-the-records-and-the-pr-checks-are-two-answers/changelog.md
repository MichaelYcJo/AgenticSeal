### Changed

- **Where the records live and whether CI checks pull requests are two answers (#952).** Choosing shared mode no longer installs a workflow that judges every teammate's pull request.
  - **First setup asks three options, in this order:** `shared, records only` (the default) creates `<repo>/seal/` and writes nothing under `.github/`; `shared, with pull-request checks` does the same and then runs `seal pr-checks install`; `local` creates the root under the common git directory and touches nothing in the tree.
  - **The checks are a command of their own.** `seal pr-checks` reports whether `.github/workflows/hygiene.yml` is this plugin's and the release it pins. `seal pr-checks install` writes it from `templates/hygiene.yml`, pinned to the installed release, and stages it; it refuses, writing nothing, where `<repo>/seal/` is not in the tree or a file this plugin did not write is at that path. `seal pr-checks remove` takes out the file this plugin wrote and leaves any other file alone. No config row records whether the checks are installed: the file is the record.
  - **`seal mode local` and `seal mode shared` leave `.github/` alone.** They move the root, stage it and write the `Mode` row. After a switch to local where this plugin's workflow is in the tree, the switch says it stays and names `seal pr-checks remove`; after a switch to shared where no workflow is there, it names `seal pr-checks install`. The way back before the commit is `git reset -- :/seal`.
  - **A pull request that declares nothing passes every step of the workflow.** `unverified-check`, handed a `seal/` root's own `specs` path, exits 0 and names the state where no `seal/` directory is at the working tree's top level, and where every work item under `specs/` lacks an `overview.md` and nothing was deleted against the base. Both were exit 2 before. Any other path holding no `overview.md`, and a misspelt path, are still exit 2. `chain-check` reads nothing as declared where HEAD has no top-level `seal` entry, so the pull request that moves the root to local mode with the checks kept, deleting every `routing.md` with the root, passes it too; its commit trailers are still judged.
- **Compatibility (#952).** A repository that already has the workflow keeps it byte for byte, pinned to the release that wrote it, and is not asked again. The `unverified-check` fix reaches that repository's CI only when a person moves the pin: edit the `--branch v<old>` line, or run `seal pr-checks remove` and then `seal pr-checks install`, and commit.
