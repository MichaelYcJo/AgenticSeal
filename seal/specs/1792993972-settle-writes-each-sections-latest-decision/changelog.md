### Changed

- **`settle` shows the released specs by section and removes; the session running the settle writes each section's latest decision (#1033).** The literal apply in merge order refused a spec whose `from` had gone stale and held every directory with an open row, so a settle could stall on every spec behind one refusal.
  - **The dry run is the timeline.** `settle` groups the released specs whose `## Rule changes` name one section, a section holding its sub-sections, and lists each group in merge order: each operation with its spec's coordinate and whether its `from` and its `to` are in the section now. Two specs in one group that no ancestry orders are marked `unordered`. It lists the specs to read whole (a section that does not parse, or none), every open `## Not verified` row of every released record with the paths it names and whether each is in the working tree, and what `--apply` removes. It refuses nothing.
  - **`settle --apply` removes, and writes no document.** It removes every released work item directory whose record holds no open row in the working tree, with a `spec.md` or without, prints each row the removed records closed with what closed it, keeps and names a directory still holding a row, and exits 1 when it kept one. It no longer asks the merge base of `--released-at` and `HEAD`, and a `--released-at` sharing no commit with `HEAD` is no longer refused.
  - **`skills/settle/SKILL.md` is the settling session's procedure.** For each group it writes the section as the latest decision, checked against the code, the code winning where it has moved on; it decides each open row as moot, answered or a measurement re-homed to an issue, the first that fits where a row fits two, closes it, runs each rule's `check:` targets over what it wrote and the repository's broad gate after `--apply`, again after any fix, so the pull request opens on a passing run with no edit after it, takes a written default where the tree does not decide, and asks nobody. The owner reviews its pull request. The `## Rule changes` grammar is unchanged; `from` locates the text and is no precondition.
- **A work item directory a pull request removes whole reads as a settle where it stood at the merge base (#1033).** `unverified-check --baseline` and `chain-check` no longer ask whether its record was closed at the base or whether `docs/` holds its spec's texts, so a settle's pull request and the release pull request after it pass with the base holding the rows open. A memo removed from a directory that stays, and a row dropped from a table, still fail, and that error now says the directory still stands rather than that a renamed directory reads the same way. The `settled:` and `retired:` notices and the refusal of a `## Rule changes` section that does not parse say the new fact.
