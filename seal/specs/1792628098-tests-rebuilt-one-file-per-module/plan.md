## Summary

The checks go in first, then the modules are rebuilt in batches, heaviest first, each batch applying `spec.md`'s four rules and recording what it cut. Rule 4 is read before every module: a rewritten module builds its world once, judges a reading without git where it can, samples where it enumerated, and records its seconds before and after. The smith recomputes every count it acts on at the tree it builds on, with the command each phase names, because #988, #1009 and #1005 merge between this frame and the build and move cases, lines and citations.

## Technical context

- `tests/conftest.py` lines 817 to 856 hold the `repo` fixture copied from a session-scoped template, the pattern rule 1 extends to a module-scoped world. Lines 856 to 910 hold the failing ceiling phase 2 turns into a report.
- `.github/scripts/release_report.py#suite_seconds` reads `.test_durations` in a tree; phase 2 groups the same reading by file.
- `bin/mutation-check` runs one mutation under a bound and prints red or SURVIVED; phase 5 gives it the batch mode `spec.md` *Data & interfaces* states, and it is the instrument of every batch's proof. `seal/specs/1791876666-the-test-suite-is-held-to-a-budget/phases/phase-1.md` is the record shape for the timing table and the removed ids' seconds; the mutant table's columns are `spec.md` *The proof of equal protection*'s.
- `tests/test_the_commit_gate_decides_at_the_commit.py` builds three repositories per case (its docstring, lines 1 to 14). The flow moves to `tests/e2e/commit/` with the world built once per module.
- `hooks/cmdline.py` (3,097 lines) and the reading in `hooks/commit-review-gate.py` stay under `questions.md` Q1's default; `hooks/cmdline_base.py` stays whatever Q1 answers, because the worktree guard's switch arm reads it (`docs/the-commit-gate-inside-git.md` *The convergence argument is claimed for commits alone*).
- `skills/verify/scripts/test_layout.py` already walks a test file's classes and cases (`_test_classes`, `_cases`) and normalises a case body (`_body`, `_Normalised`); `--moved` adds a second normalisation beside the first, one that keeps every name and drops the docstring and `self`, and reads the base's files through `git show <base>:<path>`. The collection count at the base needs the base's tree on disk, so the mode adds a detached worktree of the base under a temporary directory, runs `python3 -m pytest --collect-only -q -p no:xdist` there and in the working tree, and removes the worktree before it exits; the pytest items are read, not the AST's parametrize lists, because an id can come from a value the AST does not hold. Failure scenario of this choice: a mode that runs git and pytest sits in the file whose `--check` runs as a suite case, so a defect in the worktree handling fails `test_test_layout.py`'s cases and not only a rebuild; the mode shares nothing with `--check` but the readers, and its own cases run on a fixture repository.
- Failure scenario of the chosen approach: a module rebuilt from the code reproduces the code's own blind spot, and a case the old file had for a bug the code fixed is cut because the mutation table did not include that bug. The mutants are chosen before the old cases are read, one or two per class at the function's decision points, and a cut case's line names the mutant that justifies it, so a reviewer can ask for the missing mutant.

A phase 6 module's record carries the move check's command and its last line; where the check exits 0, the record has no mutant table. Where it exits 1, or for a phase 5 module, what the record must show before a case is cut: every mutant of the sample killed by the new file, or, for a survivor, the old files' verdict on it: an old gap where they miss it too, or a case added and seen red on it where they kill it. Beside the table, the record states the module's seconds and cases before and after, and names the real-git rows it kept under rule 4. `broad_gate.py` and `seal_stamp.py` were proved under the earlier 100-mutant table and their records stay; the commit flow's record names the mutant at which it switched.

## Operational impact

- `SPECSEAL_CASE_CEILING_S` stops being read; a run that set it is unaffected.
- The suite's collected case ids change in every batch, so `.test_durations` is pruned per batch and refreshed from CI once at the end (`CONTRIBUTING.md` *A case has a budget*' successor paragraph says how).
- No new dependency. `bin/test-layout` is a launcher like the others under `bin/`.
