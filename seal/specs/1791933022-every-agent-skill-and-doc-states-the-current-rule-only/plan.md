## Summary

The rewrite is the work. Each phase takes one or two files an agent preloads and rewrites them to `spec.md` §*The shape of a compact file*: every rule once, a restated rule made one home and one link, every story out, each rule that a test holds given its `Enforced by:` line. The proof is a small set of real behaviour cases per agent run on both sides — outcome first (the defects found, the false findings, the shape the generator reads), then cost (tokens, spend, bytes) — taken once as a baseline and once per phase for the agents the phase touched. The check that holds the result is two rows every pull request already meets: `preload:<agent>` lowered to what each rewrite reached, and #930's `docs-history` family read over every rule file as `history`, at 0 for every rewritten file. Nothing new is read by CI, nothing asks a person, and no test in the tree makes a later edit owe a paid run.

**What breaks in 6 months with the chosen approach.** The eval set goes stale: a replay target at an old tag runs old scripts under a new definition, and the baseline JSON describes a tree releases back — so replay targets come from the last two tags, the seeded set is regenerated per release, and #941's frame re-takes the baseline when the merge base moves. A rule is lost that no output shows: the cases are few by design, so the phase record's rule list (S15) and review's stage 1 against the shape are what read the rest, and a rule lost there comes back as a `Budget raised:` line with its reason. The `history` regex under-counts: a story with no mark passes it, and the `preload` ceiling is what stops it growing. The `Budget raised:` line becomes boilerplate: #930's release trend line is the reader. The pass rule's cost clause fails a sound rewrite on a noisy day: N = 2 and a 10 % margin bound it, and a rerun costs one phase's runs, never the bar.

## Operational impact

- Phase 1 waits for #939 and #937 to merge into `release/v0.22.0` and rebases before the baseline; the three acts of phase 1 are three commits, and the rewrite commit is the one the warden set judges.
- Every later pull request that edits a rule file meets the `history` row and, for a preload file, its `preload:<agent>` row: a grown file needs its `Budget raised:` line, a cut one lowers its row. #915, #940 and #941 meet them after they rebase.
- The proof costs the orchestrator's account and never CI: ≈ 120 runs and ≈ $150 over the item (`spec.md` §*The proof*). A phase's record is written by `compare` from two JSON files and read by one test in under a second.
- The preloads change what every spawn reads from phase 1 on. A rule a rewrite dropped fails its phase's eval where an output shows it; where none does, it is a row in the phase record's rule list the round reads, and a later run that misses it comes back as a raise with its reason.
- No new job, step, dependency or scope; stdlib Python at the floor. `evals/behaviour/` loses 149 files and gains two cases.
