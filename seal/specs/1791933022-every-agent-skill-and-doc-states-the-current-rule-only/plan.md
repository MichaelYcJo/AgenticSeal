## Summary

The check lands first, in #930's checker and table so no new step, job or reader is added: two ratchet families over every file an agent reads (`bytes:<path>`, `history:<path>`), an enforcer-identity gate that fails two rule paragraphs held by one thing, a candidates list the warden's round reads for unenforced rules, and a paraphrase count reported. The non-inferiority harness lands second: a behaviour suite for `claude plugin eval`, a comparator, a test that refuses a rewritten preload without a passing record, and the baseline of all four agents on today's definitions. Then the warden's preload is rewritten to the shape one file per phase, each phase proving its before and after bytes and tokens, its eval pass, and moving the file's ledger rows and test pins. The smith's and the framer's preloads follow the same procedure. Everything an agent reads on demand (#940) and `docs/` (#941) is held at today's numbers here and rewritten on this check and this harness in the same release.

**What breaks in 6 months with the chosen approach.** The eval set goes stale: replay targets from old tags run old scripts in the clone under a new definition that names a flag the scripts did not have, and the baseline JSON describes a tree three releases back — so replay targets come only from the last two tags, the seeded set is regenerated each release, and `#941`'s and later frames re-take the baseline when the merge base moves. The eval passes while a rule rarely exercised is lost: pass rule 4 reads every rule grader, and the census refuses a rule with neither a grader nor a stated reason, so the hole is the `not exercisable` list, which review reads and which the rewrites should shrink. The enforcer gate is dodged by naming no enforcer: the paraphrase report and the census's `Exercised by:` requirement are what name that, and the second release makes `restated` a ratchet if it climbs. The `Budget raised:` line becomes boilerplate: the release trend line (#930 phase 4) is the reader. A rewrite satisfies `history:` by dropping issue numbers and `bytes:` by cutting a rule for a story: the suite catches the lost rule where an output shows it, and review's stage 1 catches the rest.

**How a cut is shown not to lose a rule the agent needed.** The suite (E1) on every agent whose preload the phase changed, with pass rule 4 naming a rule grader every old run satisfied and no new run did. Then three readers for what no output shows: the rule census mapping every bold-led rule of the old file to its new coordinate or its `## Removes` row with `Exercised by:` or `not exercisable — <why>` (S13); every ledger row anchored on the file re-read one at a time, a claim the new text no longer holds being a `Corrected ·` row somebody writes (S8); every test that pinned a sentence green on the new sentence or removed with a row (S14). The remaining gap is the `not exercisable` list of each census, stated per phase and read by the round. Merging two restated rules (phase 1's four pairs, and any pair a rewrite phase joins) runs through the same three readers and the suite, so a nuance one copy carried is a grader, a ledger row or a census row and not a silence.

**CI cost.** No new job or step: the rows, the gate, the candidates and the report ride #930's hygiene step (ubuntu, under a minute; the Jaccard pass over 1,176 paragraphs is under two seconds in stdlib) and its suite case on the three legs; the record test reads a few files. In a private repository that is ≈ 0.02 Linux-equivalent minutes per run at Windows 2× and macOS 10× — nothing against #929's 292-minute median per pull request (`read` from #930's `plan.md`; prices unverified). The eval runs cost tokens and wall clock on the orchestrator's account, never CI minutes: `spec.md` §*Non-inferiority* states them, Q6 asks the owner.

## Operational impact

- This branch rebases onto `release/v0.22.0` after #930 merges; `seal/budgets.md` and `budget_check.py` are #930's files edited here, and the ratchet asks for a `Budget removed:` line per renamed `docs-history` row plus one for the family in this pull request's body.
- Every later pull request that edits a file in scope meets two rows per file and the enforcer gate: a grown file needs its line, a cut one lowers its row, a rule held by a test another file's rule already names becomes a link. #929, #931, #940 and #941 meet them after they rebase.
- Every pull request that rewrites an `agents/*.md` or a preloaded skill owes a passing `evals/<agent>-phase-N.md`, which only the suite writes: the orchestrator runs it at the phase boundary on its own account (≈ 1 h and ≈ 7 M uncached tokens for a warden phase, ≈ 2.5 h and ≈ 25 M for the baseline and for the contract phase; Q6). CI never runs an agent.
- No new job, step, dependency or scope; stdlib Python at the floor. `evals/behaviour/` joins the tree with its generators; the five existing cases keep their flat layout and the layout test recurses.
- The preloads change what every spawn reads from phase 3 on. A rule a rewrite dropped fails its phase's eval where an output shows it, and where none does it is a `not exercisable` census row the round reads; a rule a later run misses comes back as a raise with its reason in a body line.
