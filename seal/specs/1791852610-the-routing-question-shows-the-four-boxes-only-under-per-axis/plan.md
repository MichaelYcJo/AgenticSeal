# Implementation Plan: the routing question shows the four boxes only under `per axis`

Approved 2026-10-13 by the orchestrating session, under the owner's `automation` answer, when `smith` was spawned.

## Summary

Three phases, each a vertical slice. Phase 1 pins the reader before any
document changes, so the pin is red against a reader that would refuse one of
the two shapes and green against the one shipped — the documents may then say
*both shapes read the same* on an executed fact. Phase 2 rewrites the
procedure, the block and the two pointers, with the tests that pin the one
spelling rewritten first. Phase 3 writes the records and runs the checks that
read them.

No code changes. `hooks/worktree_consent.py#_routing_preset` and
`hooks/routing.py` are untouched, and so is their place on
`tests/undeclared_readers.txt`: a touched unit would owe a `Reads:` line
(`docs/the-reader-registry.md` §*Who declares*), which is a cost this work
has no reason to pay.

**Failure scenario of the chosen approach.** The block reaches installed
`~/.claude/CLAUDE.md` files only at `/specseal:update`, so for a while
sessions on other machines ask the old shape and this repository's sessions
ask the new one. Nothing reads the asking's shape at the pull request (the
act table says so of the parent act), so the two coexist silently. That is
why the reader keeps both shapes (Q3) and why phase 1 pins it: the day the
old shape is dropped from the reader is the day an un-updated machine's
automation run meets the guard's prompt again, which is #894's failure.

## Alternatives considered

| Approach | Failure scenario | Verdict |
|---|---|---|
| **A. Question 1 alone; the boxes in a second call only under `per axis`** (the issue's proposal) | `per axis` costs two waits. Acceptable: the second call follows the first at once, before the first edit, and `per axis` is the rare answer (Q1) | **chosen** |
| B. Keep one call; put the boxes' labels under a prefix such as *only if per axis:* | The boxes are still on screen under `automation` and `no work item`, which is the defect | rejected |
| C. Fold the common `per axis` combinations into question 1 as presets | Question 1 has room for one more option, and #88's rule is that the question grows only where a decision is genuinely a person's; a combination preset is a guess at which combination, and the next one wanted breaks the cap | rejected (Q2) |
| D. Make the reader refuse a result that carries the boxes beside question 1 | Un-updated machines keep asking the old shape until `/specseal:update`, and every transcript written before this item holds it; refusing it brings the guard's prompt back under `automation` (#894) and the commit gate's deny-then-ask | rejected (Q3) |
| E. Keep the two headings and change only the prose under them | A heading that states the retired shape is the stale copy `tests/test_waiver_decided_at_start.py` describes: *a count the shape outgrew reads as the shape*. Renaming costs two act-table rows, one cross-reference and a re-read row in the fragment | rejected (Q4) |

## Operational impact

- No migration, no new dependency, no environment variable.
- **Installed blocks lag.** `~/.claude/CLAUDE.md` on each machine keeps the
  two-question bullet until `/specseal:update` is run there; until then a
  session on that machine asks the old shape, and the reader accepts both,
  so nothing stops. The changelog entry says so.
- **A session already mid-run** on an older block is unaffected: the press it
  holds is read from its transcript in the shape it was given.
