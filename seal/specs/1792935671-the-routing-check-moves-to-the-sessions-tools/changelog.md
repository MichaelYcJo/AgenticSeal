### Changed

- **The routing check moved out of git and onto the session's edit tools (#1027).** It governs a session, and inside git it also ran for a person's own terminal commits and held a hooks slot that husky, the pre-commit framework or lefthook need.
  - **What stops being installed into a repository's git hooks: everything.** No `pre-commit`, `reference-transaction` or `post-commit` stub is written, and the installer no longer runs at session start or in every Bash call. A person's commit from a terminal runs no SpecSeal code.
  - **What a session meets instead.** In an opted-in repository, the first `Write`, `Edit` or `NotebookEdit` on a branch no `routing.md` names is refused, with a reason naming two ways on: write the declaration, or run `seal no-work-item` for a change no work item owns. Every session commit ends with the trailer `SpecSeal-Routing: <work-item-id>` or `SpecSeal-Routing: no work item`, and `chain-check` fails a ready pull request whose commit names a work item no declaration names. Under `straight to the PR`, in a repository that declares `seal/parity.md`, the sealer records the comparison with the original as an `original:` line in `guarantee.md`.
  - **What an existing clone's stubs do after the upgrade.** Each stub runs the plugin copy whose absolute path it names, while that copy is on disk, and does nothing once it is gone. The first session of this release that starts in the clone removes every hook file whose second line is the marker `# specseal-git-hook`, says which, and leaves every other hook file byte for byte. A person can also delete them by hand: `.git/hooks/pre-commit`, `.git/hooks/reference-transaction` and `.git/hooks/post-commit`, where each carries the marker. `.git/specseal-reviewed`, `.git/specseal-parity`, `specseal-judged/` and `specseal-commit-choice/` are no longer read, and leaving them costs nothing.
- **The per-command waivers waive nothing (#1027).** `: '[no-review]';`, `[no-parity]` and `git -c specseal.waive=` are read by nothing in this release, so typing them is harmless and changes nothing. A change that belongs to no work item runs `seal no-work-item` before its first edit, and its commits carry `SpecSeal-Routing: no work item`. An instruction file that still names `: '[no-review]';` for `no work item`, such as a `CLAUDE.md` block installed by an earlier release, waives nothing after this release; SpecSeal does not rewrite anybody's `CLAUDE.md`, and `bash install.sh` puts the current block in place.
- **The stamp is queued when a `guarantee.md` reading `sealed` is written, in shared mode as in local mode (#1027).** The `post-commit` queue is gone with the git hooks, and the edit hook is the one writer of the refusal record for a `sealed` over a commit the branch does not hold.
- **Latency (#1027).** The edit hook adds a median 68 ms to each `Write`, `Edit` and `NotebookEdit` in an opted-in repository: 42 ms the check takes and 26 ms for the hook process the harness starts per edit, measured on macOS with Python 3.12. The installer's median 113 ms leaves every Bash call there.
- **Compatibility (#1027).** A repository's `hygiene.yml` that pins an older plugin release runs a `chain-check` without the trailer arm until a person moves the pin. A session on an older plugin writes no trailer, so its commits are not judged by the new arm.
- **Two defaults stand until the owner answers (#1027).** Both questions are open in the work item's `questions.md`, and this release builds the default of each.
  - Q1, who records the comparison with the original under `straight to the PR`: the sealer compares through `legacy-parity` and writes one `original:` line in `guarantee.md`, which `chain-check` reads.
  - Q2, whether the model may run `seal no-work-item` itself: any session may run it, and the record it leaves is an audit trail in the transcript and in each commit's trailer, not an authorization.
