# Implementation Plan: 1792935671-the-routing-check-moves-to-the-sessions-tools

Approved 2026-10-25 by the orchestrator under the owner's automation answer, when `smith` was spawned for phases 1 to 4.
Approved 2026-10-25 by the orchestrator under the owner's automation answer, when `smith` was resumed for phases 5 to 7.

## Summary

The routing check moves from git to the session. A `PreToolUse` gate on the edit tools refuses the first edit on an undeclared branch. `chain-check` reads a session-only trailer at the pull request. Every other job git's hooks did gets a session-side or pull-request home. Then the stubs, the installer, the commit gate inside git and the text reading are removed, and a remover takes old stubs out of existing clones. The work runs as seven vertical slices. The four that add something (settle, the edit check, the pull request, the stamp) land and close green before the three that remove anything.

## Operational impact

**What the release note tells a consuming repository.** The phase 7 fragment carries all three.

1. **What stops being installed into its git hooks.** Everything. No `pre-commit`, `reference-transaction` or `post-commit` stub is written, and the installer no longer runs at session start or in every Bash call. A person's commit from a terminal runs no SpecSeal code. A hooks slot that husky, the pre-commit framework or lefthook wants is left for them.
2. **What a session meets instead.** In an opted-in repository, the first `Write`, `Edit` or `NotebookEdit` on a branch no `routing.md` names is refused, with a reason naming two ways on: write the declaration, or run `seal no-work-item` for a change no work item owns. Every session commit carries `SpecSeal-Routing: <work-item-id>` or `SpecSeal-Routing: no work item`. `chain-check` fails a ready pull request whose commit names a work item no declaration names. Under `straight to the PR` in a repository that declares `seal/parity.md`, the sealer records the comparison as an `original:` line in `guarantee.md`. `: '[no-review]';`, `[no-parity]` and `git -c specseal.waive=` waive nothing any more, because nothing reads them. Typing them is harmless.
3. **What an existing clone's installed stubs do after the upgrade.** Each stub names the absolute path of the plugin copy that wrote it, and runs that copy while it is on disk. Once that version's copy is gone, the stub exits 0 and does nothing. The first session of the new release that starts in the clone removes every hook file carrying the marker line `# specseal-git-hook`, and leaves every other hook file alone. A person can delete them by hand: `.git/hooks/pre-commit`, `.git/hooks/reference-transaction` and `.git/hooks/post-commit`, where each carries the marker. `.git/specseal-reviewed`, `.git/specseal-parity`, `specseal-judged/` and `specseal-commit-choice/` are no longer read, and leaving them costs nothing.

**Compatibility.**

- A consuming `hygiene.yml` that pins an older plugin release runs a `chain-check` without the trailer arm until a person moves the pin.
- A session on an older plugin writes no trailer, so its commits are not judged by the new arm.
- **Latency.** The edit gate adds a `git` resolution to every `Write`, `Edit` and `NotebookEdit` in an opted-in repository. The installer's median 113 ms leaves every Bash call there. Phase 2 measures the first number (Q4), and the changelog states both.
- **The owner's own instructions.** The `Routing, decided at the start` block of the owner's global `CLAUDE.md` names `: '[no-review]';` for `no work item`. That file is the owner's, nothing here writes it, and after this release it waives nothing.
- **When the remover can go.** `hooks/stub-remove.py` is a mechanism with a sunset. A later release retires it once no clone that a supported release reaches still carries a stub. That moment is not this work's.

No new dependency and no new environment variable. One new CLI subcommand, `seal no-work-item`, and one new record under the common git directory, `specseal-no-work-item/`.
