## Summary

Four phases, the third and fourth the two reframes'. Phase 1 cut one module by a mutation table: the commit-gate test file replays a sampled set of each corpus subgroup instead of the whole corpus. Phase 2 built the regrowth check as it stood before round 6: every new or changed test function had to be its file's only killer of a mutant the check derived from the tree, and a CI job ran that proof. Phase 2 also built one launcher that holds the Python floor for every `bin/` command but `bin/test`, and recorded the sealer file's junit-twin cut with its table. The rows the cuts moved are lowered in `seal/budgets.md`. The rest of the cleanup — the enumeration files, the helper twins, the sealer file's inventory and every file not opened here — is #942's, under the same rule (alternative H).

Phase 3 exists because the review run stopped on a second fix of a fix (`rounds/round-3.md`). Rounds 1–3 each found the same class in `case_check.py#TRACER_SOURCE`, one spelling at a time: a case that did not run its body on ubuntu was named for killing nothing (a marker skip, round 1; a body skip, round 2), and round 2's fix dropped a stopped call's traced lines, which hid a sibling that asserts and then skips and turned a correct refusal into a false `proved` (round 3's 🟡 1) while still naming an imperative `pytest.xfail()` wrongly (🟡 2). Phase 3 decided the class once from pytest's own call report (alternative M), and rounds 4–6 then found three more spellings inside that one reader — the mark on a `TestCase` class, pytest's own stop inside an expected failure, a skipped subtest reported through the same hook while the call still runs (`rounds/round-4.md` to `round-6.md`).

**Phase 4 is a subtraction, and it is the owner's decision of 2026-10-15** (#929, *What this item ships, and where the rest went*, item 3): the per-case check — does each new or changed case kill a mutant its file's other cases do not — and the tracer's reading of whether a case ran its body leave the pull-request gate. What stays is the half the owner kept: a pull request's changed shipped lines are mutated, the test files that name the changed module run under each mutant, and a line nothing kills is listed. The frame decided one thing the decision left open, whether such a line fails the job or is reported, and chose report (alternative T against U; `spec.md` §*The changed-lines check*). Phases 1–3 keep their commits; what phase 3 built is history in `phases/phase-3.md`, and the three rounds after it are the record of why it leaves.

Q8 measures the new shape.

**What breaks in 6 months with the chosen approach.** First, the survivors line is a report, and a report is read only while somebody reads it: a changed line nothing kills ships, and what finds it later is #942's release sweep, a mutation table per file, or a defect. Second, the candidates are who names the module, so a module whose cases live in a file that does not name it — a case that reaches `gate.py` only through `bin/` and names the wrapper — has its kills unseen and its lines listed as survivors, and a reader learns to skim the list; #942's layout, one file per module, is what makes the candidate set exact, and the day it lands the heuristic can be replaced by the file's name. Third, the heavy modules: `gate.py`'s 48 candidate files are priced past any half of five minutes, so a change to the module this repository changes most often is counted `not run` on every pull request, and the check is read as a check of the small modules. Fourth, a pull request that changes 1,000 lines gets fifty verdicts and 950 `not run`, and nobody asks for the other 950 because the job is green either way. Each of the four is loud in the summary and silent in the exit code, which is the shape the report decision buys on purpose; alternative U says what the gate's shape would have cost instead.

## Operational impact

- One new script, one new CI job (ubuntu, `contents: read`), one launcher every `bin/` command but `bin/test` runs through, and three ceilings lowered in `seal/budgets.md`. No new dependency, no new row, no new measurer.
