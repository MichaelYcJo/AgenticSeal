## Summary

Four phases, the third and fourth the two reframes'. Phase 1 cut one module by a mutation table: the commit-gate test file replays a sampled set of each corpus subgroup instead of the whole corpus. Phase 2 built the regrowth check as it stood before round 6: every new or changed test function had to be its file's only killer of a mutant the check derived from the tree, and a CI job ran that proof. Phase 2 also built one launcher that holds the Python floor for every `bin/` command but `bin/test`, and recorded the sealer file's junit-twin cut with its table. The rows the cuts moved are lowered in `seal/budgets.md`. The rest of the cleanup — the enumeration files, the helper twins, the sealer file's inventory and every file not opened here — is #942's, under the same rule (alternative H).

Phase 3 exists because the review run stopped on a second fix of a fix (`rounds/round-3.md`). Rounds 1–3 each found the same class in `case_check.py#TRACER_SOURCE`, one spelling at a time: a case that did not run its body on ubuntu was named for killing nothing (a marker skip, round 1; a body skip, round 2), and round 2's fix dropped a stopped call's traced lines, which hid a sibling that asserts and then skips and turned a correct refusal into a false `proved` (round 3's 🟡 1) while still naming an imperative `pytest.xfail()` wrongly (🟡 2). Phase 3 decided the class once from pytest's own call report (alternative M), and rounds 4–6 then found three more spellings inside that one reader — the mark on a `TestCase` class, pytest's own stop inside an expected failure, a skipped subtest reported through the same hook while the call still runs (`rounds/round-4.md` to `round-6.md`).

**Phase 4 is a subtraction, and it is the owner's decision of 2026-10-15** (#929, *What this item ships, and where the rest went*, item 3): `case_check.py` and the `cases` job leave the pull request. The reframe after round 6 had kept a changed-lines check, and the owner chose removal over it: that check could only report, because a mutant that changes nothing observable is no defect, and within its five-minute bound it reached about fifty lines. Mutating code stays as the release sweep's tool (`mutation-check`, #942). Phases 1–3 keep their commits; what they built of the check is history in `phases/`, and the six rounds are the record of why it left.

A `one-sided` row's ceiling is 1.3 times its reading, rounded up, and a lowering needs no body line. This item adds no row and no measurer; it lowers `suite-seconds` and the two `slow-file` rows its cuts moved.
- `tests/test_the_commit_gate_decides_at_the_commit.py#SAMPLE` and `#test_every_corpus_family_has_a_sampled_row` — phase 1's pattern for an enumeration: a representative per subgroup, pinned against the corpus.
- `hooks/launch.py` — `FLOOR`, the refusal sentence, and the script run with `runpy` as `__main__`. `.github/scripts/run_tests.py` reads its `FLOOR`; `hooks/hooks.json` does not run through it, because exit 2 from a hook blocks the call (`docs/commit-review-gate-spec.md` §*Registration*).
- `Enforced by:` lines naming tests (#944): a rule names the case that holds it, and `budget_check.py`'s `enforced-unresolved` row, a gate at 0, names a target that is gone or renamed. A removed or renamed case an `Enforced by:` line names takes that line to the case that holds the rule now, in the same pull request.
- **How pytest reports a call that stopped short**, and what a changed-lines check would have cost, are history: `phases/phase-3.md` and `rounds/round-3.md` to `round-6.md` hold what was read and executed.

**What breaks in 6 months with the chosen approach.** A new test that guards nothing its neighbours do not is no longer refused on the pull request. What holds it is #942's layout (a function's tests in one group, likely duplicates named) and the smith's and warden's rules (#923), which a reviewer can miss; what finds a miss is #942's release sweep with `mutation-check`. A changed line no test exercises is likewise found by review or by that sweep, not by the pull request.

## Operational impact

- One launcher every `bin/` command but `bin/test` runs through, and three ceilings lowered in `seal/budgets.md`. No new script stays, no CI job is added, no dependency.
- A `bin/` command other than `bin/test` run on a Python older than 3.12 refuses with one sentence and exit 2 before its script is read. `bin/test` builds its virtualenv at the floor from an older `python3`, as before. The plugin's hooks do not go through the launcher and behave as before.
- `.test_durations` loses the 227 ids the cuts removed and no price is changed.
- An `Enforced by:` line naming a removed or renamed case moves with it in the same pull request; `enforced-unresolved` holds that.
- #943 (item B) and #942 (the rest of the cleanup) are issues the orchestrating session holds; nothing here posts.
