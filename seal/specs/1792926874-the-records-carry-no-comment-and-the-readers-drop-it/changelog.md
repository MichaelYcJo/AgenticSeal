### Changed

- **A record carries no HTML comment, and the readers of a record keep no comment state (#1012).** The 173 records under `seal/specs/` that still held template guidance in comments lost it; each `routing.md` keeps its comments, and its reader keeps the walk, because it runs in the commit gate. `unverified_check.py#readable` blanks fenced lines only and reads a comment as text, and `comment_scan` and `strip_comments` are gone. `chain_check.py#unclosed` refuses a fence that never closes and no longer a comment. A `<!--` later in a line is text, so a bare opener in an `answer:` line no longer hides the findings after it. `evals/scripts/replay_targets.py` reads a record from a release tag with the reader of the commit that judged it.
- **A record line that begins with `<!--` is refused at its line (#1012).** The line is one outside every fence whose text, leading whitespace removed, begins with `<!--`. `chain-check` refuses one in a round record, a `guarantee.md` and a `broad-gate.md`. `unverified-check` refuses one in an `overview.md`, and reports a base revision holding one as not compared. `settle` and `chain-check` refuse one in a spec's `## Rule changes`, which is now read with no comment state. The stamp is not drawn from a `guarantee.md` holding one.
- **After upgrading, a repository deletes the comments from its own records (#1012).** A record under its `seal/specs/` that holds a line beginning `<!--` outside a fence is refused at that line until the comment is removed:
  - `unverified-check` reads every `overview.md` under `seal/specs/` on every pull request, so an old overview in any directory turns every pull request red, not only one that touches it.
  - `chain-check` refuses a round record, `guarantee.md` or `broad-gate.md` of each work item the pull request declares, so an in-flight work item framed under the old templates is refused until its records are stripped.
  - `settle` keeps the directory of a released work item whose `overview.md` holds such a line, at the tree or at the merge base of `origin/main`, and holds a spec whose `## Rule changes` holds one.

  The comments are template guidance that nothing reads, and `routing.md` and `seal/config.md` are not affected. No command strips them: the refusal names each line, and a repository deletes the comments by hand or asks its own session to. Whether a later release ships such a command is open with the owner, and until it is answered none ships.
