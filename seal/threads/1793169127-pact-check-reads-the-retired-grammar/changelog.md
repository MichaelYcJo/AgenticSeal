### Changed

- **A pact anchor is a row of a `| Pact | Clause | Hash |` table in a signer's `frame/design.md`, and `seal pact` reads it with the same table walker as every other table (#913).** The `Pact` cell holds the origin URL of the pact's repository, as the signer's `Pact` row writes it, compared normalised. The `Clause` cell holds the clause's heading path, such as `## Order response shape / ### Fields`. The `Hash` cell holds eight lowercase hex digits, `00000000` until the first report names the real one. Every cell is written bare, and only a pipe inside a heading is escaped, as `\|`. A row naming another pact is passed over. `templates/setup/pact.md`'s comment, `templates/setup/config.md` *Pact* and `skills/implement/orchestration.md` state the table.
- **`seal pact` refuses an inline anchor, `pact:<name>/"<heading path>"@<hash>`, at exit 2 (#913).** Every `pact:` token outside a closed fenced code block in a signer's frame is refused at its line, and the line names the row to write in its place. `compact:` and `pact:` followed by a space are no token. A signer repository with a frame still in flight that cites the pact inline rewrites each anchor as one row. `seal pact` runs in no CI, so no pull request or hook changes its verdict.
- **`seal pact` refuses an anchor row it cannot grade, and a row it does not read, at exit 2 (#913).** Refused at the row's line: a `Pact` cell that holds a space or a backtick, or that reduces to no host and path. In a row naming this pact, also refused at its line: a `Clause` cell that opens with no heading, and a `Hash` cell that is not eight lowercase hex digits. Refused at the frame: every refusal of the table walk, and a second anchor table, because the walk reads the first table only.
- **`seal pact` names the pact by its origin URL (#913).** The `READ` line ends `— <n> pact anchors naming this pact`, and the summary line opens `seal pact: the pact at <origin URL> —`. Each line that is not `OK` names the frame, the row's line and the clause path in backticks. A repository with no origin is refused with `has no origin remote, so no pact anchor can be matched to the pact — set `origin` and run it again`.
- **A signer's `Pact` row may name two pacts whose URLs end in one segment (#913).** They were refused as ambiguous to the name an inline anchor carried, and are now two pacts.
- **`seal pact` reads the machine-local map `~/.claude/agentic/pact-paths.md` with the table walker, and refuses every line of it that it does not read, at exit 2 (#913).** Each refusal prints as `REFUSED ~/.claude/agentic/pact-paths.md — the map <sentence>`. The map is refused where it is there and will not read, holds no `| Remote | Path |` table, or has a line the walk refuses, such as a row below a paragraph. It is also refused where it has a row with an empty cell, a remote on two rows, of which neither is read, or a second header under a later heading. Before, the first line that was not a row ended the map with nothing printed, and every signer named below it was reported not found. The rows the walk did read are still used. A map written as `seal pact`'s remedy line teaches has none of these shapes.

### Removed

- **The near-miss grammar that named a mistyped inline anchor (#913).** `PACT_MENTION_RE`, `near_miss` and the quote classes in `skills/verify/scripts/pact_check.py` go, with the inline grammar `PACT_ANCHOR_RE` in `skills/verify/scripts/coordinates.py`. So do the pact's name and its rules in `hooks/lib/config.py`: `pact_name`, `PACT_NAME_RE` and the `named` parameter of `remote_entries`. `pact_declaration` answers `(as written, normalised)` pairs.
- **The unit resolver in `skills/verify/scripts/coordinates.py` (#913).** `resolve_unit` and every unit only it reached had no caller since the ledger left in 0.22.0 (#944). The module keeps the heading-path and hash units `seal pact` reads. The census `coordinate_grammar`, which guarded the resolver's hash grammar, goes with it.
- **`hooks/lib/config.py#CONFIG_SEPARATOR` (#913).** Its one reader was the map's own loop.
