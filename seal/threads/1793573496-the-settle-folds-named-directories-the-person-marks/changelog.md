### Added

- **A settle can fold decisions kept outside `seal/`: `seal settle --from <dir>` lists the documents of a directory a person names, and the settling session asks, before its first edit, which directories to name and which of their documents become policy (#1054).** A repository's decisions also stand outside `seal/`, in architecture decision records, RFCs and another tool's spec files, and nothing brought them into the policy root. The settling session now asks the person first which directories besides `seal/` hold decisions to fold, and passes each one named to the dry run as `--from <dir>`, which may be repeated. The dry run then lists every file git lists under each directory, tracked or untracked and not ignored, at any depth and of any extension. Each file is printed with the commit that added it and the commit that last changed it, each as a short hash and a date. A merge counts as the commit that added a file it wrote that no parent holds, and as one that changed a file whose conflict it resolved; a commit that deleted the file counts as neither. A line ends `changed in the working tree` where the working tree changed the file; a file no commit adds is listed last. The listing is what git answers about each file: `seal settle` reads no document's content and proposes nothing. The settling session reads each document whole with the code it bears on, and writes one row per document: the policy section it bears on, `promote` or `skip`, and the grounds. It puts the table to the person once, as a second question. Only a row the person leaves marked `promote` is written into the policy, as a released design's rule change is, and the section cites the document by its repository path. The settle's pull request body lists every row with the person's mark. Nothing writes, moves or removes a file under a named directory. `--from` exits 2 with one sentence for a path that names no directory of the working tree, a path outside the repository, the `seal/` root or a path under it, and `--from` beside `--apply`; a sentence about a path names it as read from the directory the command runs in. A directory above the `seal/` root, such as the repository's top, is accepted: its listing holds the root's own files, and the settling session proposes each of them `skip`. A run without `--from` prints what it printed before, and a session that cannot ask takes the answer "none" and settles as before. `skills/settle/SKILL.md` *Directories a person names* holds the rules, and `templates/setup/config.md` *Reference specs* says that `seal settle --from` reads a reference root only where a person names it. The rule is in force from this merge through the work item's rule changes. The settle after the release writes it into `docs/the-record-layout.md` *The fold, and what tells it from a deletion* and `docs/release-checklist.md` *2b. Settle what earlier releases left behind*. It also adds "on its own" to the sentence of both editions of `docs/one-root-by-lifetime.md` that says no code of the plugin opens a top-level `specs/`.
