### Fixed

- **What the orchestrator learnt in a run is written into the repository, and the rules it had kept in one machine's session memory stand in the files that read them (#1200).** The orchestrator of this repository's runs had kept lessons and the owner's decisions in its harness's session memory, which lives on one machine, so a run on another machine repeated the mistakes. Each of those entries was read and given a verdict: already in the tree, moved by this release, moved by the next settle, kept on that machine, or not kept. `skills/implement/orchestration.md` gains *Orchestrator: where a decision or a lesson is written*: a decision about the work item in progress goes into its records, a lesson into the file its act is read from or into an issue naming that file, and a reading of a segment's cost into the measurement log. Where that file ships with the plugin and the run is in another repository, the orchestrator names the lesson and the file in its report to you, for the plugin's tracker, and edits no installed copy. A lesson seen once is given a home or judged not worth one, with its grounds in the work item's records. A session's local memory keeps what belongs to its machine and how the person wants to be worked with. Contract rule 12 now asks for the method a class was listed by: a list built from what produces the defect, from every part of the artefact, or from a command that lists each thing holding the property, never the instances in view or a search for one wording. A list none of the three methods made is handed back as a sample, with where its open part stands, and a class over an unbounded domain of keywords, spellings or constructs has no whole list, so the hand-back says so and where its open part stands. Contract rule 19's search of a changed rule's words stays the least search for its other statements, and a list that search makes without one of those methods is handed back as a sample. The hand-back names the method, and the proofer judges it. The base comparison by hand in `skills/verify/orchestration.md` runs a failing file in a `git worktree add` of the base, never under `git stash`, whose one stack every worktree and session of a clone shares. In `skills/code-review/orchestration.md`, the orchestrator reads `gh pr view <N> --json state,mergeable` when the pull request opens, before each push and after each push, and stops a push to a pull request that is merged or closed. After a merge the repair goes on a new branch from the base; after a close the orchestrator pushes nothing and reports the pending repair. It waits on CI with `gh pr checks <N> --watch`, which reads every workflow's checks. The body of an open pull request is replaced through the REST call rather than `gh pr edit`, and the reason now stands in that sentence instead of a citation of a file that never gave it. The stall check on a running agent, the instruction that a spawn prompt handing over a local path says not to copy it into a record, the commit after `seal settle --apply` before any switch of the checkout, and the close of the release milestone after the tag are rule changes the next settle writes into `docs/`.
