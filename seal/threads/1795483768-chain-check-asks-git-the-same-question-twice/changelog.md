### Changed

- **One run of the pull request check, or of `seal settle`, asks git each question once (#1603).** Before, the check's arms each read the records they judge, so one run asked git the same read several times: the work item's `routing.md`, its design and its round records, and the reads of which commits follow the last round, the gate record and the guarantee. One run over #1581's branch started 105 git processes, and 85 of them were distinct. `seal settle` asked the same ancestry pair once per group of designs, `ls-files` twice where a released work item kept an open `gaps.md` row, and, under `--apply`, the three reads of the release tags twice. `lib/gitcmd.py#one_run` now holds the answers of one run. Inside it, `git` answers a command it already answered in that run, in the same repository with the same arguments, input, mode and environment, from the first answer, and starts no process. The answers are dropped when the run ends. A command that did not start or finish is never kept, and an exit code the caller checks is read on every ask. `chain_check.py#main` and `settle.py#main` run inside it. The module's docstring states which runs may enter: a run in which nothing the command writes changes what git answers it.
- **The pull request check reads the routing declarations HEAD carries through one git process (#1603).** `chain_check.py#tracked_declarations` started one `git show` for each work item's `routing.md` to find the declaration naming the branch. In #1581's run the declaration reads were 49 of the 105 processes, 48 of them distinct, one per `routing.md` its HEAD carries. It now reads them through one `git cat-file --batch`, given the blob ids its `git ls-tree` lists. Each text reads as `git show` read it. A batch that exits non-zero reads as no declaration, as a failed `show` did. Under `--worktree` each declaration is still read from disk.
- **`lib/gitcmd.py` holds `decoded` and `batch_texts` (#1603).** `decoded` reads the bytes git printed as `lib/gitcmd.py#git` reads its text output. `batch_texts` reads what `git cat-file --batch` printed by the size each object's header gives. Both came from `skills/settle/scripts/settle.py`, where `blobs` now reads its batch through `batch_texts`, and `chain_check.py` reads the declarations through it too.

No output, exit code or verdict of `chain-check`, `seal pr-body` or `seal settle` changes.
