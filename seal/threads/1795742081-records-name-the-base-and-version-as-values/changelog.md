### Fixed

- **Contract rule 19 has a change name a state outside the work item's branch by its role, or state its value of a named moment (#1633).** Records named the base branch, the version and what other work items had done as present values. A cut, a rename, another pull request's merge or a tag then made the sentence false with no commit on the work item's branch, so no change searched for it and no round was owed that would read it, until a later round raised it as a finding. Of the 120 findings of owlery releases 0.0.5 and 0.1.0 that #1632's comment counted on 2026-11-27, 12 were classified as stale after a release was renamed, merged or tagged. Rule 19 gains a paragraph: the text states what the work item decided and names each thing by the role it plays, names the file or the command that reads a value a reader needs, and may state a value of a named commit, a published release, a dated measurement, a date or a cut; a release still open is no such moment. A line of the plugin's forms that a check reads by value, the `Branch` row of `routing.md` and a `target:` line, keeps its value. So does a value the work item's own commit writes, such as the version the work item carrying the move writes to the version file and states in its `changelog.md`. The exemption for a named moment is now stated once for a count, a universal and a value. Rule 19 keeps its number.
- **The routing and plan templates cite contract rule 19 where the orchestrator and the framer write the release's state (#1633).** The placeholder under `## Why this way` of `templates/records/sdd-routing.md` asks the grounds to name the base, the version move and the merge order by what was decided and by role. In `templates/records/sdd-plan.md`, *Overlap with the release* asks for the date or the commit at which another item's state was read, and *Operational impact* asks whether the pull request carries the release's version move, which phase carries it and where that phase reads the version, in place of the move itself.

`docs/running/the-agent-set.md` *One contract every agent receives, and one definition each* states the rule from the settle after this release, which writes it from the work item's `## Rule changes`.
