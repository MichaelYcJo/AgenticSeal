### Fixed

- **`seal deferrals` no longer counts a workflow whose trigger it cannot read as answering a deferral (#1123).** A workflow that runs the deferred check on push only, with its trigger keyed `"on":` or its events indented four spaces, was printed as `answers ... (trigger unread)` at exit 0, so a deferral of the suite to CI read as answered by a run that comes after the merge. The command now reads `on`, `"on"` and `'on'`, an event block at any consistent indent, an event key that carries a value or a comment, and a flow list closed on its line. A trigger it still cannot read, such as a flow mapping, a list continued across lines, or a workflow with no `on` key, is printed as `unread <name> (trigger unread, not counted)` and does not resolve the deferral on its own. The limit line printed after the verdict now also says that an event's filters (types, branches, paths) are not read, so a `pull_request` trigger limited to closed pull requests still counts as answering.
