### Added

- **The settle's dry run now prints the judgments earlier settles removed, so a kind of judgment that recurs once per release can be seen (#1281).** The dry run read the *Judgments of the run* rows of the plans released in this settle only, and `--apply` removed each plan with its directory. A kind of judgment the orchestrator made once in each release never gathered enough rows in one settle to be rewritten, and the 0.27.x settle saw such kinds only because its own release held enough of them. `seal settle` now lists, after *The judgments*, the rows of every `frame/plan.md` a commit on `--released-at` deleted from a work item that has no directory in the tree. It reads each plan from the history at the parent of the newest commit that deleted it, with the reader the released plans use, so a heading near the section's and a table not under its exact header are named as not read there too. The rows are grouped by the `Judged against` cell as written. Each work item's line gives the release whose tag holds the commit that added its plan and the commit that removed it with its pull request number. The section counts nothing and matches no row to another: whether an earlier row is the same kind as a current one is the settling session's judgment, and the session rewrites the section a kind stands on where the kind recurs across releases. Nothing is kept beside the tree to carry the rows, because git's history already holds every removed plan whole. A run with no earlier settle prints what it printed before, and `--apply`, `--draft` and `--from` are unchanged. Replayed on this repository, the section lists 74 rows from 18 work items released in 0.26.0 to 0.27.2, which two earlier settles removed (#1214 and #1269). `skills/settle/SKILL.md` *What the dry run shows* holds the rules.
