## Data & interfaces

`tests/conftest.py#section(text, heading)`:

- `heading` is the whole heading line as the file spells it, such as `## Running the checks`. Its level is `lib/lines.py#heading_level(heading)`.
- The heading is found among `lib/lines.py#headings(readable(text))` by `lib/lines.py#sections`, so a line inside a fenced block is never found and a longer heading that begins with the same words is not taken for it.
- It returns the lines of `gfm_lines(text)` after the heading, up to the next heading of its level or above, or to the end of the text, joined with `\n`. The heading line is left out, so a phrase pinned in the body is never satisfied by the heading itself. Fenced lines are returned as written, since the readable lines only place the headings.
- It raises `AssertionError` naming the heading where `text` holds no such heading, or more than one.

A caller that wants lines splits the result on `\n`, and a caller that wants one line passes it to `tests/conftest.py#flattened`.

`tests/workflows.py#parse(text)` returns `yaml.load(text, Loader=yaml.BaseLoader)`, and `load(path)` returns `parse` of the file's text. A grader's front matter is the text between its first two `---` lines. A grader that names no `match` is read as `contains`, the runner's default, which `grader_from` supplied until now.
