## Data & interfaces

- **`lib/gitcmd.py#http_answer(stdout)`** returns `(status, body)`. `status` is the integer of the first line's second field where that line is `HTTP/<version> <three digits>` followed by a space or the end of the line, and None otherwise. `body` is the text after the first empty line, and `""` where there is none. It reads text as `gitcmd.gh` returns it, with line ends already LF (G10). It starts nothing.
- **`release_exists(repo, tag)`**: `gitcmd.gh("api", "-i", f"repos/{repo}/releases/tags/{tag}")`; False on 404; True on a 2xx status; `sys.exit` with the stderr line it prints now on any other status or none. A `gh` that gave no answer still raises `gitcmd.Unrun`.
- **`_issue_api(repo, number)`**: the same call on `repos/{repo}/issues/{number}`; `(None, False)` on 404; `(json.loads(body), True)` on 2xx; the same exit otherwise.
- **`seal deferrals`**: exit 0 where the path is a directory and the arguments parse, whatever it matched; exit 2 as now. The `--kind` choices and the outcome lines' order stay.
- **`deferral_check.py#RUNNERS`**: the same dict of three kinds, each a list of regular expression fragments, each fragment anchored on its own. `session_cost.py#FAMILIES` keeps its five names and their order.
