### Fixed

- **The release workflow reads GitHub's HTTP status to decide that a release or an issue does not exist (#1572).** `.github/scripts/publish_release_note.py#release_exists` and `.github/scripts/close_issues_on_release.py#_issue_api` read the words of gh's error line, and took any failure whose text held `Not Found` or `404` as "no such release" or "no such issue". So a 403 whose message held `Not Found` read as no release, and the publish job could publish a second Release at the tag. Both now ask `gh api -i` and read the status line it prints through `lib/gitcmd.py#http_answer`. A 404 is the not-found answer, and a 2xx status is the answer. Any other status, and an answer with no status line, stops the job with gh's error, as every other failure did before. The issue closer and the merged-label script read issues through `_issue_api`, so they read the same status.
- **`seal deferrals` reports what its runner words matched and exits 0 (#1572).** Where no CI line matched a runner word for a kind of check, it printed `NO RUNNER IN CI`, said that nothing runs the check, and exited 1. A CI that runs its suite through a script, a composite action or a reusable workflow matches no runner word, so a true `unverified; CI covers it` row read as refused. The command now exits 0 whenever it read the path, and exits 2 only where the path or an argument is unusable. A kind no line matched reads `tests: no CI or hook line matched a runner word`, or `tests: no CI line matched a runner word` where only the pre-commit hook matched. The closing sentence asks the reader to open the CI files and read what they run before deferring the kind to CI. `skills/verify/SKILL.md` *The answerer has to exist* says what the three outcomes match, and that a kind with no matching line is no finding that nothing runs the check.

### Changed

- **`seal deferrals` and `seal cost` read one list of runner words (#1572).** `skills/verify/scripts/session_cost.py` kept its own words for its `test` and `lint/type` families, and the two lists disagreed both ways. `seal deferrals` named no runner for a step running `nox`, `just test` or `bun test`, and `seal cost` charged `pylint src` or `go vet` to `other`. `seal cost` now builds both families from `skills/verify/scripts/deferral_check.py#RUNNERS`, which holds the words of both lists. A transcript that ran one of the added commands is charged to a different family than an earlier release charged it. `session_cost.py` loads `lib/sibling.py` and `deferral_check.py` when it starts, so a copy of it taken without them exits 2 with a sentence naming the missing file.
- **The suite's sweep for a contract citation in a near-miss spelling warns and passes (#1572).** `tests/behaviour/test_a_cited_section_stands_in_its_file.py` failed the suite on a spelling such as a capital `Rule`, a plural or a possessive beside the word `contract`. Whether such a spelling meant a contract citation is a reader's judgment, so the sweep now names each near miss in a warning, at its `path:line` with the one spelling to write, `contract rule <N>`.

### Removed

- **`seal pact`'s refusal of a `pact:` token in a frame (#1572).** `seal pact` refused at exit 2 every `pact:` token in a signer's frame outside a fenced block, as the inline anchor 0.23.x read. No release since 0.24.0 reads that anchor, and a frame leaves the tree at the settle after its release. A frame's anchors are now read from its anchor table alone, and a token anywhere else is read as nothing. The `READ` line's count of anchors shows a frame that cites none. `docs/layout/the-pact.md` *The pact anchor* states the refusal until the settle after this release rewrites it.
- **The suite's batch sweep over the agent definitions (#1572).** `tests/behaviour/test_chain_hooks_hardening.py` failed the suite where a batch phrase, such as `in one batch`, stood within 140 characters of a word for a person answering, such as `question` or `user`. It read words near a phrase, its own comments recorded the sentences it refused that were no instruction, and no agent definition holds a batch phrase. `tests/behaviour/test_waiver_decided_at_start.py` still fails a definition that names `AskUserQuestion` outside the sentence saying the tool is absent.
