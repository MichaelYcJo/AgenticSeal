### Changed

- **The rule on a release's size named a number of work items as a ceiling, and a reader took it as a limit; the rule will state no number, and the suite no longer pins that number or searches the tree with a word list for a second statement of it (#1289).** `docs/issues-and-milestones.md` *A milestone answers when, and takes three shapes* sizes a release by what has to be in effect before the next work item starts, and a paragraph below that criterion kept three or four work items as a ceiling. The settle after this release replaces that paragraph through this work item's rule change. The new paragraph states no number. Whoever places an issue in a `release:` milestone judges whether the release has grown past what its description can make clear. Once the description can no longer name the purpose its issues share, or the grounds for their order, an issue that does not have to be in effect before the next work item starts moves to the next release. The judgment counts work items rather than ticket numbers, and the criterion itself is unchanged. `tests/behaviour/test_a_release_is_sized_by_a_criterion.py` drops the case that pinned the number. It also drops the sweep that searched the tree's documents and tests with a regular expression for a second statement of a release's size, and the five cases that pinned the sweep's reach. Measured before the build, the sweep matched none of five sentences that state a count and matched both of two sentences that state the judgment. The module keeps its one case on what the criterion does not change. A row in `tests/behaviour/test_a_shrunken_corpus_declines_to_judge.py`'s registry, seven rows of `.test_durations` and the `seal/follow-up.md` row on the sweep's line reader leave with them.
