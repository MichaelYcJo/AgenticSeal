### Fixed

- **`seal settle` names a file it does not read because the file stands away from its record's place, and decides nothing on it (#1126).** The settle reads three records in a released work item's directory, each at one path: `gaps.md` at the directory's top, `frame/design.md` and `frame/plan.md`. A file with one of those names at any other path, such as `trail/gaps.md`, `frame/gaps.md`, a top-level `design.md` or `trail/plan.md`, was read by no part of the settle. `--apply` removed it with its directory and printed nothing about it, so an open row written there left without a word. The dry run now lists each such file in a section of its own, after the open rows, with the record it is named like. The section's heading says the settling session opens each file, and that `--apply` decides nothing on it and removes it with its directory. `--apply` names each file again on a `not read:` line under its directory's `removed` or `kept` line. Only the exact name is read, and no file's content. The directory still goes or stays on its record at its place alone, and no exit code or count line changes. The issue asked that `--apply` keep the directory instead. That would hold the settle at exit 1 on a guess, taken from the file's name, that the file holds open rows, which a script in this plugin does not do (`skills/core/SKILL.md` *The rule a mechanism is kept against*). The settling session reads what the file holds before `--apply` runs.
