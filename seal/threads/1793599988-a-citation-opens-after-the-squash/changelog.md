### Fixed

- **A citation of a file at a commit, written as the commit, a colon and the path, now has to name a commit that outlives the squash merge (#1270).** A feature branch squashes into its release branch, and the squash discards every commit the branch wrote. A citation of one of those commits opens in no fresh clone after the merge, so a reader sent to it finds no source. No check read the form, and three work items reached a release with such a citation in their frame, each through a sealed review chain. The new case `tests/text/test_a_cited_commit_outlives_the_squash.py` reads each such citation, as `tests/censuses.py#COMMIT_PATH` matches it, in every tracked text file. It refuses a commit that no `main` or `release/*` ref contains, local or remote-tracking, and a commit the clone lacks. The refusal names each file, line and commit, and says to cite the squash commit that holds the same file, or the path at HEAD where the file is the branch's own. Where a checkout's `main` or release refs are older than the cited squash, `git fetch` answers it. Three kinds of file are not read: anything under `evals/behaviour/`, a work item's `trail/` and its `guarantee.md`. Those record what a party ran at the branch's own commits, and they leave with the work item. A commit written without a path is not read either: a plan's Status cell and a round's `fixed` line name the branch's own commits by rule, and the reviewer still reads the rest. Where the checkout holds no `main` or release ref, the case skips and names the four ref patterns it looked for. The one citation at HEAD that it refused, in the frame of #1235's work item, now cites the squash commit that holds the same file. No shipped file changes.
