### Added

- **`seal cost --work-item <dir>` posts the segment readings of one work item that no session posted, so a measurement log no longer closes empty because a session forgot (#1439).** The session that watched a segment finish was the only party that posted its reading, and logs closed with no reading in them. The transcript stays on the machine that ran the segment, so the new mode reads it later. It reads the `Branch` row of `<dir>/routing.md` through `lib/routing.py`. It walks every agent transcript under every project directory of `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects`. It takes each transcript whose spawn prompt, the first user entry, names the directory's name or the branch as a whole token, so `fix/12-a` is not found inside `fix/12-a-b`. A prompt that names several work items is taken by each one asked about. The mode reads every comment of the open `flow-measurement` log, every page of them, and leaves out each transcript whose file name stands on a `# <file name>` line inside a comment's fence. It prints four counts: the transcripts walked, the ones that name the work item, the ones already in the log, and the ones in this reading. Under them come the `# <file name>` lines and one `--segments` row per segment, one per slice for a resumed agent, each named by its file. Where no transcript on the machine names the work item, the reading says so. With `--post --says <file|->` the reading is posted as one comment. Where every transcript that names the work item is already in the log, the mode says so, posts nothing and exits 0. The log's states end as `--post` ends them. `--work-item` refuses a transcript argument, `--latest`, `--spawns`, `--segments` and `--json`.

### Changed

- **A posted reading names each transcript it was read from, and carries no command text (#1439).** Inside its fence, `--post` now writes one `# <file name>` line for each transcript, before the report. For the plain reading and `--spawns` that is the file given. For `--segments` it is the file given and each agent file a row was measured from, named once even when a resumed file gives several rows. The line holds the file's name, never its path. In the posted body, the `slowest` list gives each call's seconds and family, and the `other` note keeps its sentence without the command it quoted, because a command can hold a path, a heredoc's body or a prompt. What `seal cost` prints locally does not change. `seal cost --json` gains a `family` key in each `slowest` row.
- **`skills/verify/orchestration.md` *Measure the segment, and feed the flow log* says that the release posts what no session posted, through `--work-item`.** The paragraph that said nothing removes the remembering is gone. So is the deadline for the in-run post, which held only while the watching session was the only party holding the transcript. "never as a question" stays. Both READMEs name the release step in the `seal cost --post` row and add a `seal cost --work-item <dir>` row to the command table. This repository's release checklist, `docs/releasing/release-checklist.md` *5. The release pull request*, and `docs/running/measuring-a-run.md` *Where a reading goes* take the step at the settle after this release.

Updating: nothing to do. A comment posted by an earlier release holds no `# <file name>` line, so `--work-item` posts those segments again into the log that is open when it runs.
