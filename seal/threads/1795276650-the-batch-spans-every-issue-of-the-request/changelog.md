### Changed

- **A request that names several issues, such as a milestone or a release, has one batch of questions, and it covers every issue (#1563).** Before, the orchestrator read one ticket for the batch, and `skills/implement/SKILL.md` had it open the batch section whenever it started a work item. A later item of a milestone or a release could therefore stop the run with a question asked at its own start, after the run was underway. Now `skills/implement/orchestration.md` *Orchestrator: what needs a person is asked in one batch, before the first edit* reads each ticket the request names and asks one batch before the first edit of the request's first work item. A later item asks nothing new when it starts. Its `routing.md` is written from the routing answer the batch got, an answer the batch gave for its issue is folded into that issue's body, and what surfaces later goes to `questions.md`, `seal/follow-up.md` or the closing memo as before. A new request still gets a batch of its own, with the routing question among it.
- **An issue's line that leaves a decision to a person is checked against the tree before its question enters the batch (#1563).** The line records what was open when the issue was filed. The orchestrator now checks it against the policy root, `seal/config.json`, the code and the records of the work items that came before. Where they answer it, nothing is asked, and the answer and its coordinate go in the item's `routing.md` *Why this way*, or for `direct` in the body of the commit that carries the change.
- **`skills/implement/SKILL.md` and `skills/core/SKILL.md` state the batch's scope and cite the section for it (#1563).** Each says the batch is asked before the first edit of the person's request, for every issue it names. `skills/implement/SKILL.md` adds that the section is not opened again when a later work item of the request starts.
- **A later work item of a request writes the language keys the request's batch gave (#1563).** `skills/implement/routing-question.md` *Orchestrator: the two language keys* had a later item of a release take the default language wherever its base lacked a key, because the routing answer was given for the release. Now that item's routing commit writes the answers the request's batch gave. The default, the titles' language or `English`, stays for a run with nobody there to answer.
- The version moves to 0.38.4.
