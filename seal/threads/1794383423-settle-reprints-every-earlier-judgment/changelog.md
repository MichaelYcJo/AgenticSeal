### Changed

- **The settle's dry run prints the judgments of the plans the two newest removing commits deleted, and `seal settle --all-earlier` prints the rest (#1481).** *The judgments earlier settles removed* printed every row of every plan an earlier settle had removed, so it grew with every release, and the settling session reads it whole at every settle. In this repository it was 247,730 bytes of a 308,261-byte dry run. A removing commit is a commit that deleted a plan the section reads. The section now reads the plans the two newest removing commits deleted, and ends with a line that counts the older removing commits it did not read and names `seal settle --all-earlier`. The line counts commits, never rows. Here the section is 47,844 bytes, and the line says that 8 older commits were not read. `seal settle --all-earlier` reads every removed plan, as the dry run did before, and prints no such line. It is refused beside `--apply` and beside `--draft`, which print none of the section, with exit 2 and one sentence each. Step 5 of `skills/settle/SKILL.md` sends the settling session to `--all-earlier` where a kind of judgment it reads may have come before the two newest removing commits.
- **The section's git calls no longer grow with the plans it reads (#1481).** The dry run read each removed plan with three git calls, 422 calls in all in this repository, and took 8.4 seconds in one measured run. One `git cat-file --batch` now reads the plans' texts and one `git log` their adding commits. Three calls read the releases that hold those: one lists the version tags, one peels each to the commit it names, a tag of a tag followed to the end on every git, and one walks their history. The dry run here makes 25 git calls with or without `--all-earlier`, and finished in 0.56 and 0.53 seconds in two runs. A plan whose text git no longer holds is named as not read at its coordinate, with what git answered, and so is a plan whose path holds a newline, which the batch would read as two names; the other plans' rows are printed. `seal settle --apply` reads the lowest release tag of each work item in three git calls per run, where it asked one `git tag --contains` per work item.
