# Implementation Plan: 1793688270-a-check-line-names-a-case-or-the-rule-carries-none

## Technical context

- `.github/scripts/rules.py` is the one reader of the `check:` line. `seal rules --check` runs it over every rule file `RULE_FILES` (`:74-80`) names and over every policy document, and the suite runs it through `tests/github/test_rules.py::Test_main::test_every_check_line_in_the_tree_holds`. `skills/code-review/scripts/chain_check.py` asks the same reader, through `refused_lines` and `unread_lines`, for each check line in a design's `add` or `change` `to`. The no-target form is `NO_TARGET` (`:82`), one branch of `parse` (`:201-209`), one line of `render` (`:495-496`) and half of `EXPECTED` (`:99`). Nothing else in the tree reads it (`frame/design.md` *Data & interfaces*).
- Once the branch goes, a `check: none reader: …` line resolves as a list of targets and is refused, because `none` is a marker no test carries and `reader:` is no file (executed in a clone at the base). So phase 1 has to take every form line out of the rule files before phase 2 removes the branch. In the other order the tree case goes red on 64 lines.
- Phase 1 is the only phase that touches a preloaded file: the contract and the five agent definitions. Phases 2 and 3 edit `skills/settle/rule-changes.md`, `skills/implement/SKILL.md`, the READMEs, `docs/` and `tests/`, which no agent preloads. So the preload measure is taken once, at phase 1's close, and holds for the build.
- Failure scenario of the chosen approach, six months on. A user repository's design was drafted under 0.30.x and carries `check: none reader: …` in an `add` or `change` `to`. If its pull request opens after the upgrade, `chain-check` refuses it at that line, naming `none` as a marker no test carries. The refusal names the line, and the fix is to delete the line. The release note's fragment states the change (*Operational impact*), so the person who meets the refusal can read why.

## Operational impact

- **A compatibility break in one line form.** `seal rules --check` and `chain-check` refuse `check: none reader: <who>`, which both accepted through 0.30.x. A repository whose unsettled design carries the form in an `add` or `change` `to` sees the refusal at that pull request. The fix is to delete the line. The changelog fragment states this under its user-visible changes.
- The hint every refusal prints changes from `` `check: <targets>` or `check: none reader: <who reads it>` `` to `` `check: <targets>` ``. Hygiene's `::notice` annotation carries the same text.
- `seal rules <doc>` prints no `no target, read by` line. A heading whose rules carry no line prints `(no check line)`, as before.
- A new `routing.md` drawn from the template has no `Answer pressed` row. An existing one that keeps the row reads as before (`frame/design.md` *Scope* 8).
- No new dependency, environment variable or migration. Case ids leave `.test_durations` unpriced or stale (`questions.md` Q1).
