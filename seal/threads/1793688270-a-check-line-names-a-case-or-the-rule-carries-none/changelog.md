### Changed

- **64 rules in 23 shipped files ended with a `check: none reader: <who>` line, which named who reads the rule and which no script acts on; each of those rules now carries no check line (#1277).** The lines left four skills, the agent contract among them, four agent definitions, `CONTRIBUTING.md` and fourteen documents under `docs/`. Each rule's paragraph reads as before, and review reads the rule. `tests/text/test_the_agent_contract_holds_the_universal_rules.py` no longer asks each contract rule for exactly one check line, because a rule no case holds now carries none. Every agent's preload is smaller, because the contract and four definitions lose their lines: the crafter's by 528 bytes, the framer's by 720, the proofer's by 528, the sealer's by 418 and the tracer's by 595, read with `.github/scripts/release_report.py` against v0.30.0.
- **`seal rules --check` and `chain-check` refuse a `check: none reader: <who>` line, which both accepted through 0.30.x; a check line now has one shape, `check: <targets>`, and a rule no case holds carries no check line (#1277).** A design drafted under 0.30.x whose `## Rule changes` carries the form in an `add` or `change` `to` is refused at that line when its pull request runs `chain-check`. The refusal names each word of the line as a marker no test carries or a path that does not exist, and the fix is to delete the line. The hint every refusal and every `not read` line prints, hygiene's annotation among them, now reads `` write `check: <targets>` `` and offers no second form. `seal rules <doc>` no longer prints a `no target, read by` line. `skills/settle/rule-changes.md` *A rule has one shape*, `skills/implement/SKILL.md` and both READMEs state the one shape.
- **Four check lines named a test module that reads no fact of the rule above it; three of them now go, and the fourth names only the module that reads its rule (#1277).** The rules *A suite that is not mentioned reads as a suite that passed* in `docs/running/the-broad-gate.md`, *A population floor over the records is replaced, never lowered* in `docs/checks/the-fold.md` and *The `target:` line in every `round-N.md` names a commit* in `docs/releasing/branch-and-release.md` carry no check line. For the third, `docs/forms/the-round-record.md` *The round record* is the rule's home and keeps its line. `docs/checks/the-stamp.md`'s paragraph on the message budget names `tests/hooks/test_sealer_stamp.py` alone. The three asserts that pinned a phrase of those rules leave `tests/text/test_broad_gate_rule.py`, `tests/text/test_settle_reads_before_it_removes.py` and `tests/text/test_a_rider_reaches_its_file.py`, and two cases that held nothing else go with them.
- **`routing.md` carried an `Answer pressed` row, which recorded whether the person pressed `automation` or answered `per axis` on the routing question, and no code acted on it; a new `routing.md` no longer carries the row, and the orchestrator no longer writes it (#1277).** The row leaves `templates/records/sdd-routing.md`, the table of `skills/implement/orchestration.md` *What the answer writes* and the paragraph of `docs/running/the-review-and-parity-arms.md` *The declaration, and where the check went*. `hooks/lib/routing.py` no longer reads it, and its declared answers carry no `pressed` key. A `routing.md` that still carries the row reads with the same answers as before, because the reader passes over a row it does not read. Whether the person pressed `automation` is still read from the session's transcript, as `hooks/question-gate.py` and `hooks/routing-edit-gate.py` read it before. The eval scaffolds that wrote the row no longer write it.
