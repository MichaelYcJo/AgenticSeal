### Changed

- **A release note's header is one paragraph and no longer an HTML table, so GitHub draws no grey border around the seal in dark mode (#1496).** GitHub draws a border around every table cell whatever the note's HTML asks. The note now opens with its counts in words, one per line, in one HTML paragraph on one source line. Once the release seal has run, that paragraph holds the seal's image floated left, the result badges beside it one or two to a line, and a line break that clears the float before the theme. Where the repository leaves the image off, the paragraph holds the badges alone. The seal job still finds the header by its whole text and replaces it only where it stands exactly once. The paragraph's opening and closing tags bound that text, so a note whose header holds one more count line or one more digit than the seal computes is refused and left as published. Notes published before this release keep their tables, because a published note is never rewritten.
- **A badge's colours follow its label, so a passing result no longer reads like a failure (#1496).** Every badge showed its label and its value in two of the seal's reds, a passing suite among them. Now every label is grey except `SEALED`'s, which keeps the seal's dark red under its bright red value. The suite's passed count is green, the skipped, capped and deferred counts are grey, and every other value is blue. A value that could not be read keeps its label's colours.
