# Implementation Plan: 1795439973-six-test-modules-cost-past-the-rewrite-bound

## Technical context

The tree as read at `5528a681f`.

What each module costs, where its seconds go and which seams the code already offers are in `frame/design.md` *Grounding*, and this section does not restate them. The constraints the build works under:

- The work changes test files only (`frame/design.md` *Scope*, out). A seam the build needs is one the shipped code already has: an argument such as `pins_and_copies_in`'s `sources`, a module flag such as `chain_check.WORKTREE`, or a function a case replaces with `monkeypatch`, such as `chain_check.read_record`, `chain_check.git` or `release_seal.gh`.
- A case that runs a shipped command in the process reads module state the command sets, such as `chain_check.WORKTREE`, which `main` assigns. A unit call that sets such a flag sets it through `monkeypatch`, so the next case starts from the module's own value.
- Under `-n auto`, each xdist worker builds a module-scoped world the first time it runs a case of that module. `frame/design.md` G5 says where that build is charged, so a module pays for each of its worlds once on every worker that runs a case of it. A world is worth building once per module only where the cases that copy it outnumber the workers.
- `bin/seal mutate` runs the module's new file once per mutant, with `-x`. A module rewritten to run in seconds makes its mutation table affordable. The old files' column runs only for a mutant the new file lets survive (`CONTRIBUTING.md` *The test layout*, the paragraph opening "A rebuilt module's record carries its move check or its mutation table").

**The failure scenario of the chosen approach, six months on.** A reading case calls an arm directly, and a later change to `main` stops passing that arm's input, or passes another. Every unit case stays green, and only the real-git `main` cases kept per arm can see the break. Scope items 2 and 10 to 13 keep such cases per arm for that reason, and the phase record names them (`frame/design.md` G4's third part). The second failure is a case that writes into a module-scoped world instead of its copy. That case passes alone and fails another case only under one order of workers. Design S5 runs each module in file order and under `-n auto`, and the proofer reads each writing case for the copy it writes into.
