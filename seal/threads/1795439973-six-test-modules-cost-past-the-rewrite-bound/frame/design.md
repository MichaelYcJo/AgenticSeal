## Scope

In scope, numbered for `frame/plan.md`'s *Delivers* cells:

1. `tests/skills/test_settle.py` is rebuilt by G1 to G4. Its repositories are built once per module, one for each kind of world its classes need, such as a shared root with a merge history or a local root whose `gh` the `gh` fixture answers in the process (phase 8; one case keeps a `gh` script on `PATH`). A case that writes takes a copy. The module's own `git`, `commit` and `repo` go, and so does the shadowing `local` where a module world replaces it.
2. `tests/skills/test_chain_check.py`, the arm classes: `Test_pins_and_copies_in`, `Test_rule_changes_read`, `Test_check_lines_in`, `Test_body`, `Test_originals_of`, `Test_guarantee` and `Test_broad_gate`. A case about what an arm reads calls that arm with its input given in the process: the design text, the `sources` dict, a working tree read under `WORKTREE`, or `read_record` and `git` replaced for the case. An arm keeps the cases that run `main` over a real repository where their fact is what `main` hands the arm, such as which design `Test_rule_changes_read` receives, and at least one where the base held one, to show that `main` reaches the arm and that the reading and git agree; `Test_broad_gate` ran no `main` at the base and runs none (`trail/phases/phase-2.md`). The `item` world is built once per module and copied per case, as `branch` copies `_branch_template`.
3. `tests/skills/test_chain_check.py`, every other class, `Test_main` and the git predicates among them, by the same rules, and the module's record for items 2 and 3 together.
4. `tests/github/test_release_seal.py`. The phase first measures where `Test_main`'s seconds go. Each case then gets the smallest suite record that holds its fact, and the cases that need a wide count keep it.
5. `tests/skills/test_test_layout.py`. A `Test_moved` case about which old case the new files hold calls `moved` with texts. The cases that run `main --moved` are the ones about the count `pytest` collects, the worktree's removal and the exit code.
6. `tests/skills/test_seal.py`. The cases of `main` that ask how input is read either become unit calls or keep `main` with the git it starts before the reading answered for the case, the top by `at_top` and the remote where it is not the fact (`trail/phases/phase-6.md` *Departures*). The real-git runs that stay are those showing that a command and git agree.
7. `tests/skills/test_broad_gate.py`. A case about how the gate reads a run's record reads a hand-built record (`a_record`, `jsonl`, `a_test`), except the cases of `Test_read_record` whose fact is what the recorder writes when a session stops or ends, which read a record a real `pytest` wrote in a directory with no git. A gate case whose fact is one arm has the other arms answered for it (`arms_answered`, `suite_alone`) and runs the row and the base's run for real. The real `pytest` runs that stay are one per kind of answer the gate gives a run, shared through module-scoped fixtures where cases only read them (`trail/phases/phase-7.md` *Departures*).
8. Each phase's record holds G4's four parts. The second part also gives the module's figure in run 45181872904's artifact, and the local figures come from `bin/test <module> -q -p no:xdist`. With xdist off, pytest's wall time is the sum of the cases' setup, call and teardown, the quantity G5 says the artifact sums. `CONTRIBUTING.md`'s `bin/test <files> -q` runs under `-n auto`, which divides that sum by the workers. The local figures show where the time went on the machine that built the phase, and are no evidence of a saving on the Windows leg (*Grounding*, *What a figure of the Windows leg can show*). The module's Windows figure after the phase is the orchestrator's, by S1.
9. Every name in *Data & interfaces* stays importable at its home with its behaviour.
10. `tests/skills/test_settle.py`, the further rebuild the orchestrator decided after run 45189798316 (`frame/plan.md` *Judgments of the run*). A case of `Test_main`, `Test_report`, `Test_apply` or `Test_module` whose fact is how `settle.py` reads its input calls the reader with that input given in the process, as item 2 does for `test_chain_check.py`, and moves into the class of the arm it reads through. Where the reader is `survey`, its git-asking readers are answered from the disk at `settle.py`'s own seams (`answered`), not git's output, and a case whose fact is one of them keeps that one real (`trail/phases/phase-8.md` *Departures from the frame*). The seams are `settle.py`'s own. `plan_rows`, `carries`, `work_items`, `misplaced` and `judgments` take text or records, and `report`, `draft` and `apply` take the result of `survey`, so cases that judge one world's report can share one survey of it (read: `skills/settle/scripts/settle.py:1168`, `:625`, `:279`, `:1092`, `:1119`, `:1725`, `:1863`, `:1940`, `:1474`). A reader that itself asks git, such as `adding_commits`, `versions`, `history` or `earlier_judgments`, keeps its cases over a real history, since those show that the reading and git agree. Each arm of `main` keeps runs over a real history, as many as item 13 states, and the phase record names each: the dry run's merge order, the release at a ref, the published note under `--apply`, the history earlier settles removed, `--from`, `--draft` and local mode. A change to `tests/conftest.py`, such as to `#tree` or `#commit_everything`, stays out, for the reason `gaps.md` *Not done* gives.
11. `tests/skills/test_chain_check.py`, the further phase the orchestrator decided after run 45203717820 (`frame/plan.md` *Judgments of the run*).
