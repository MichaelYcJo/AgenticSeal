### Fixed

- **`seal gate` passed a suite whose tests pytest stopped part-way with exit 0, so the sealer could guarantee tests nobody ran; the gate now fails it (#883).** A test that calls `pytest.exit()` with a return code of 0, or ends its process with `os._exit(0)`, stops the pytest session there. The tests after it never run, and the `Broad gate` row still exits 0. The gate decided the suite on that exit alone. It printed `BROAD GATE PASSED` with the counts of the tests that did run and wrote `trail/gate.md`, and the sealer reads that file as a passed broad run. The gate's own pytest recorder already counted such a session as stopped part-way: its record holds no `end` line, or the `end` line names a stop pytest made, or shows an exit other than 0, 1 and 5. The gate showed that count only on a suite that had already failed. Now the suite fails wherever the record at `HEAD` counts a session that stopped part-way, whatever the row's exit. The run exits 1, prints `BROAD GATE FAILED`, and writes no `trail/gate.md`. Under the suite's own lines, the failure form says that the row exited 0 and that an exit of 0 says only that nothing the session ran failed. The count of stopped sessions follows, with where each session's record is kept. The base is run only where a test failed before the stop, as for any failing suite. A run whose every session ran to its end passes as before. One stop is still out of the record's reach: a `pytest.exit()` raised by a `pytest_sessionfinish` hook that runs after the recorder's. A repository whose suite stops itself on purpose at exit 0 now has every broad run fail until that stop is removed. `templates/setup/config.md` *The criterion for choosing a value*, rule 3, and `skills/code-review/orchestration.md` state the new behaviour. The rule is in force from this merge through the work item's rule changes. The settle after the release writes it into `docs/the-broad-gate.md` *One act, one owner, and the owner is the orchestrator*.
