**The constraints a sentence of the new page meets.** It stays within 88 display columns as prose. It names no version at or above 0.31.0. It shares no 15-word run with a rule document (English edition only). It names no concrete release branch, no `install.sh`, no `preset-setup`, no `tasks/` and no old root.

**The failure scenario of the chosen approach, six months on.** The page keeps the hook table and the command rows, and both still grow one row per new hook or command. A command row's sentence can go stale where no case reads it, because a row links its home and does not restate it. What catches a stale row is a reviewer reading the diff that changed the command, and contract rule 19's `git grep`. A hook row cannot drift out of existence unnoticed, because `GROUPS` derives the rows. The Korean edition can drift in a sentence while keeping its outline, as K4 did for 35 releases. The outline case and the hygiene warning do not see that drift. The proofer reads the two editions side by side at every pull request that changes one, as `CONTRIBUTING.md` requires.
