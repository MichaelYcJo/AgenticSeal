### Removed

- **`seal unverified --baseline` is gone, and the proofer is now the one reader of a row or a closing memo deleted instead of closed (#1240).** `seal unverified --baseline <ref>` compared the closing memos at the merge base with the working tree, and named each row that left without the word `closed`. Only a person ran it, because no workflow step has run `seal unverified` since `5daa931f`. Each new shape of path reopened the comparison (#1225, #1238, #1264). `seal unverified` now takes no option but `-h`. Argparse refuses `--baseline` with exit 2, so a script that still passes it fails. Exit 1 means only that a section could not be read. The proofer reads a deleted row or memo in the closing memo's diff. `skills/implement/SKILL.md` *4. The closing memo* and `skills/verify/SKILL.md` *And something has to read the row afterwards* now say so, and they name no command. The `seal unverified` row of `README.md` and `README.ko.md` drops `[--baseline <ref>]`. Two exit-0 messages lose the clause about the base. On a settled root, the message no longer adds "and nothing left the record without being closed". Where no root stands, it no longer says there is "nothing to compare against the base".
- **A closing memo has one reading, whichever command reads it (#1240).** `skills/verify/scripts/unverified_check.py` kept a looser reading for a memo read at a git ref, so it could read memos written before the format was settled. That reading took an older heading, a `Who` column, a U+2705 mark read as closed, and a `none` line read as no rows. After `--baseline` left, no shipped command read a memo at a ref, so the looser reading is gone as well. `seal settle` reads each memo from disk with the reader `seal unverified` uses, as it did before. What either command prints does not change. A memo that reader cannot read is listed as one entry saying it cannot be read, never as zero rows.
