### Changed

- **A pull request into a release branch no longer waits on the macOS runner (#1516).** The `tests` workflow runs ubuntu at Python 3.12 and the four Windows shards on every run. A new `pytest-wide` job runs ubuntu at Python 3.14 and macOS at 3.12 on every run except a pull request into `release/*`. A pull request into `main`, a push to `main` and a manual dispatch run all seven legs. The release pull request is now where those two legs first run a release's code, and a defect only they meet is fixed by a pull request into the release branch. On the feature pull requests before this change, macOS met no defect and every long wait was a macOS job queued for a runner. Ubuntu at 3.14 never failed where ubuntu at 3.12 passed.
- **Every check keeps its name.** `pytest-wide` runs `pytest`'s steps through a YAML alias, and its legs report under the names they had, such as `pytest (macos-latest, 3.12, 10)`. The release table still reads each leg's minutes, because `release-report` waits on both jobs. Neither job is a required check.
- **The cases that hold a property of every leg read every job that runs the suite.** These are the timeouts, the report flags, the install pins, the Python floor on each system, and the rule that a matrix is `include:` alone with a split or a store only on Windows. A new case pins which legs each job runs, the condition and name of `pytest-wide`, and its steps against `pytest`'s.
- **`CONTRIBUTING.md` and the pull request template say which legs a contribution runs.** A contribution's pull request runs Linux and Windows, and macOS and Python 3.14 run on the release pull request.
- The version moves to 0.38.0.
