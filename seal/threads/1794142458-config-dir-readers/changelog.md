### Fixed

- **`seal cost --latest` and `seal payload` read the files Claude Code keeps in the config directory in use, and no longer in `~/.claude` alone (#1367).** Claude Code keeps its session transcripts, the user's `CLAUDE.md` and user skills in the directory `CLAUDE_CONFIG_DIR` names, and in `~/.claude` where the variable is unset. Both scripts read `~/.claude` whatever the variable said. On a machine that sets it, `seal cost --latest` found no transcript or an old one, and `seal payload` counted a `CLAUDE.md` and skill shadows the session never loaded. `skills/verify/scripts/session_cost.py` now looks for transcripts under `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects` and reads the variable at each call. `skills/verify/scripts/payload_meter.py` reads the user's `CLAUDE.md` and each skill shadow in the same directory. A row read under a set variable is labelled `$CLAUDE_CONFIG_DIR/CLAUDE.md` or `$CLAUDE_CONFIG_DIR/skills/<name>/SKILL.md`, so no account name reaches the table. An empty variable reads as unset, as the shell's `:-` does. A `@~/` import in either `CLAUDE.md` still resolves against the home directory, because Claude Code resolves `~` that way whatever the variable says. Where the variable is unset, every row, label and JSON key reads as before. Where it is set, a `--baseline` taken before this release does not pair the user's `CLAUDE.md` row, because its label changed. `skills/verify/orchestration.md`, `README.md` and `README.ko.md` spell the directory `${CLAUDE_CONFIG_DIR:-$HOME/.claude}` where they named `~/.claude`. The suite removes `CLAUDE_CONFIG_DIR` from its environment at import, so a developer's own directory never reaches a case.
- **The plugin's version moves from 0.35.0 to 0.35.1** in `.claude-plugin/plugin.json`.
