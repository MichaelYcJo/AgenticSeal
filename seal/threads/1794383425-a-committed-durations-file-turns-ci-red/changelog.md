### Changed

- **No `tests` run turns red because a durations file aged, and no pull request refreshes one (#1486).** The Windows leg's four shards were divided by a committed `.test_durations`. On a pull request into `main`, the `durations` job failed whenever that file priced too little of the suite it had just measured. The issue counts six red runs on the file's age, the 0.37.0 release pull request among them, and each was followed by a pull request that only refreshed the file. The file has left the tree, and `.gitignore` names `/.test_durations`. The union the Windows shards measure now lives in `actions/cache`. On every run that is no pull request's, a push to `main` among them, the `durations` job saves the union under a key starting `test-durations-`. Each Windows shard restores the newest such key before it divides. Where no key matches, the shards split by count, which unbalances them and drops no case. `.github/scripts/durations_union.py` keeps the union, its refusals and its per-shard report. It loses the age verdict, `--committed` and `--stale-fails`. `CONTRIBUTING.md` *Running the checks* states the cache, and no recipe for a hand refresh remains. Step 5 of `skills/settle/SKILL.md` used to name a durations refresh among the commits that carry `Seal-Routing: no work item` with no route chosen. That clause is gone, so a settle's commit is now the one such commit it names.
- **The release table reads both durations unions from run artifacts (#1486).** `.github/scripts/release_report.py` takes `--durations` for this run's union and `--durations-at` for the union of the tag's push run. A side with no union reads `no union found` in the suite row and the test-file table, and the script still exits 0. A file that is present and does not parse still exits 2. The `release-report` job downloads both artifacts.
- **The suite reads a workflow file through a YAML parser, not through hand-written readers (#1486).** PyYAML 6.0.3 is pinned for the suite beside markdown-it-py and cmarkgfm. `bin/test` installs it, and so do the CI lines and the fallback commands in `CONTRIBUTING.md`. `tests/workflows.py#load` returns what `yaml.BaseLoader` gives, so the trigger key stays `on` and every value is a string. Three readers go: the walker in `tests/text/test_ci_gives_the_checks_what_they_need.py`, the indentation compare in `tests/behaviour/test_a_release_publishes_its_note.py`, and the step readers in `tests/conftest.py`. Every other test helper that took a job, a step or a key out of a workflow by indentation or by a regular expression goes as well. `.github/scripts/run_tests.py` installs its three pins from one table, `PINS`, through `has_pin` and `add_pin`. A plugin user installs nothing new, because nothing the plugin ships imports PyYAML.
- **`test.yml` names no run, and macOS runs as one job (#1486).** The comments beside the timeouts carried a run id on 14 lines, and a sizing argument built on a suite of 7,530 s. They now state the rule alone: 1.5 times a leg's slowest measured job, rounded up to 5 minutes. On the runs measured before this change, that gives 5 minutes for each ubuntu leg and 10 for macOS and for each Windows shard, where 15, 15, 15 and 20 stood. macOS ran in three shards. As one job it ran the whole suite in 199 s on this work item's run, inside that run's slowest Windows shard of 244 s. So the shards shortened no run, and each paid a job's fixed cost again.
