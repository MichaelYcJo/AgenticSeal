### Changed

- **A frame names where its work meets the release's other work items and which of them merges first, and the orchestrator merges in that order (#1443).** `templates/records/sdd-plan.md` gains the section `## Overlap with the release`, immediately before `## Operational impact`. It holds one row for each other open work item of the release that the work meets: where both change, which item merges first, and why that order costs less. Where none meets, or the spawn names none, it holds one sentence saying so. Two items meet where both change the same file, or where one changes a rule, a check or a fact that the other's change reads or adds content to. The framer reads the release's other open work items its spawn names, each one's issue and its frame where the frame is committed, and writes the section (`agents/framer.md` step 4). Its hand-back names the rows and the order they state (step 8). The orchestrator's prompt that spawns each framer names those items: the issue, the branch, and the frame's path where it is committed. The orchestrator merges the items in the order the plans state. Where two plans state opposite orders for one pair, or the item ordered first cannot be sealed before the other, the orchestrator chooses the order and writes it as a row of *Judgments of the run* in the plan of the item it merges out of the stated order. The version move goes to the item first in that order, and items no plan orders against each other merge as each is sealed. The orchestrator's own rule for the first item, the one likeliest to be sealed first and often the smallest diff, is now part of what the framer weighs. Where a plan orders a branch after another item, the orchestrator merges the base into that branch once the other item has landed, before the branch's next round, or before its broad run where its rounds have ended. A round already owed then reads the resolution, and the broad run and the sealer read the merged tree once (`skills/code-review/orchestration.md` *Orchestrator: the pull request opens once the sealer seals*).
- **The plugin's version moves from 0.35.1 to 0.36.0** in `.claude-plugin/plugin.json`.

Updating: nothing to do. A plan framed before this release has no *Overlap with the release*, so no plan orders its item against another, and the orchestrator merges it as it is sealed.
