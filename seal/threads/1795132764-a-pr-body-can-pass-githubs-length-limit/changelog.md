### Fixed

- **`seal pr-body` folds the longest sections of the records' copy where the body would pass GitHub's limit of 65,536 characters (#1559).** Before, the command wrote a body of any length. GitHub then refused it at `gh pr create`, after the seal, and a body shortened by hand was refused by the pull request's check. Now the sections after `## What changed` fold one at a time, the longest first, until the body fits. A folded section keeps its heading. In place of its text stands one line per record it copies from, ending, for `## Not verified`, `` `gaps.md` holds what this section copies. ``, and a directory of records is named once. `## What changed`, `pr.md` and `pr.<lang>.md` never fold. The body is counted in UTF-16 code units, where a character outside the Basic Multilingual Plane, such as most emoji, counts as two, so a body within that count also fits where GitHub counts code points. The fold leaves room for the seal mark's line whether or not the mark is written. A body with no mark therefore folds once it comes within that line's length of the limit, and the run after the seal folds the same sections the sealer's check folded.
- **`seal pr-body` names the sections it folded (#1559).** Both forms print one line opening `seal pr-body:` that names the folded headings, after the mark key's sentence where one stands. The pull request's check prints the same sentence as a notice and refuses nothing for it.
- **`seal pr-body` refuses a body that still passes the limit with every section folded (#1559).** It exits 1 with nothing written, on one `refused:` line on the work item's directory. The line gives the body's length, counted with the seal mark's line whether or not it is written, and the length of each first-part file and of `changelog.md`, and asks for one of them to be shortened. Before, that body reached `gh pr create` and was refused there.

Updating: where `seal pr-checks install` wrote `.github/workflows/hygiene.yml` pinned to 0.38.2 or earlier, the pull request's check composes no fold, and it refuses a folded body at its first folded section. A body folds where, counted in UTF-16 code units with room for the seal mark's line, it would pass 65,536 characters. So an open pull request's body can fold under this release where it came within that room of the limit, or where characters outside the Basic Multilingual Plane, counted twice, take it past the limit; the next `seal pr-body` run before a `gh api -X PATCH` writes it folded. To open or update a pull request whose body folds, run `seal pr-checks remove` and then `seal pr-checks install` once the plugin is 0.38.3, and commit the result.
