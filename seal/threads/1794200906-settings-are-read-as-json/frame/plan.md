# Implementation Plan: settings are read as JSON (#1454)

## Technical context

The tree as read at `20bd4132`.

The reader is `lib/config.py`. `config_text` opens `<home>/config.md` once, `config_table` walks its `| Item | Value |` table through `gfm_table`, and `config_value`, `declared_value`, `declared_mode`, `policy_root`, `reference_roots`, `pact_declaration` and `declared_pacts` answer one row each (`lib/config.py:311-875`). `read_table`, `pact_signers` and `baseline_commit` read `pact.md` and `parity.md` (`lib/config.py:1259-1404`). The walker and the units it reaches are measured in design G11. The writer is `skills/implement/scripts/seal.py#write_row` with `#with_row` (`seal.py:1466-1690`). Script readers of a setting: `skills/verify/scripts/broad_gate.py:664-1100`, `skills/settle/scripts/fold_check.py:295-352`, `skills/code-review/scripts/pr_body.py:435-577`, `.github/scripts/release_seal.py:422-429`, `skills/code-review/scripts/chain_check.py:1595-1625` (parity), `skills/verify/scripts/pact_check.py:385-430` (map) and `:668` (signers). `tests/conftest.py:979-1180` holds the config helpers most cases build fixtures with, and `tests/config_shapes.py` the table shapes of #871.

The constraint is the installed plugin (design G13). The orchestrator's `seal` and every agent come from 0.36.0, which reads `seal/config.md`; this repository's CI runs the tree's scripts, which after phase 1 read `seal/config.json`.

**What breaks in six months.** A person edits `config.json` by hand and leaves a trailing comma: `seal gate`, `seal pr-body`, `seal fold`, `seal pact` and `seal mode` exit 2 naming the parser's line and column until it is fixed, and `seal rules`, `seal settle` and `seal unverified` read the default policy root and reference roots. That is loud, and it is the price of a parser that reads exactly. A person on Windows writes `C:\tools\new\pytest.exe` into `Broad gate` with single backslashes: `\t` and `\n` are JSON escapes, so the value reads with a tab and a newline, and `seal gate` runs a command that fails with a path nobody wrote. `templates/setup/config.md` *Broad gate* states the limit, that a backslash is written `\\` in JSON. A third: a later key wants a list, and a value grammar inside a string grows again, as `Pact` and `Reference specs` already have (A6).

## Operational impact

**A compatibility break.** A repository that holds `seal/config.md` runs `seal mode` once after updating to 0.37.0. Until it does, `seal gate`, `seal pr-body`, `seal fold`, `seal pact` and `seal mode --check` exit 2 and name `seal mode`, and nothing runs; `seal rules`, `seal settle` and `seal unverified` read the default policy root and reference roots. `seal/parity.md`, a `pact.md` signer table and `~/.claude/agentic/pact-paths.md` are rewritten by hand into `seal/parity.json`, a `Pact signers` key and `~/.claude/agentic/pact-paths.json`; the changelog fragment's *Updating* line says so (design *Scope* item 9), and `frame/questions.md` Q1 holds whether a converter should do it.

**This repository during the run.** From phase 1's commit this branch holds `seal/config.json` and no `seal/config.md`, and the installed 0.36.0 `seal` reads no setting on it: `seal gate` finds no `Broad gate`, and `seal pr-body` refuses for want of the language rows. On this branch the orchestrator runs the tree's command, the worktree's own `bin/seal`, for `gate`, `pr-body` and `mode`, and names it in the sealer's spawn prompt. After this item merges into `release/v0.37.0` the same holds there until 0.37.0 is installed, which is why it merges last (*Overlap with the release*). Agents spawned from 0.36.0 read `Record language` in `config.md`, find none and write English, which is this repository's record language, so nothing changes for them.

No new dependency: `json` is in the standard library. No environment variable. This pull request does not move the version; #1445 does.
