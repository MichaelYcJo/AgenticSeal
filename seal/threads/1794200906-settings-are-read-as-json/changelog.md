### Changed

- **A repository's settings are a JSON file, `seal/config.json`, read by Python's own JSON parser (#1454).** The settings were a markdown table, `seal/config.md`, read by a table walker of the plugin's own. That walker had to decide what a fence, an HTML comment, a blank line or an escaped pipe meant inside a table, and #867, #871, #925, #1119, #415, #429 and #430 were each a table shape it read differently from the person who wrote it. `seal/config.json` is one JSON object with one key per setting, named as the rows were: `Commit and pull request language`, `Record language`, `Mode`, `Broad gate`, `Reference specs`, `Pact`, `Pact signers`, `Policy root`, `Document token ceiling`, `Pull request seal mark` and `Release note seal mark`. Each value is a JSON string in the grammar `templates/setup/config.md` gives it, so a pipe in the `Broad gate` command is written as it stands, and a `"` or a `\` is written `\"` or `\\`. `lib/config.py` is the one reader. A file that will not decode, will not parse or is not one object is refused for every key, naming the path and the parser's message. A key written twice, or one whose value is not a string, is refused for that key alone, and every other key reads.
- **`seal mode` writes `seal/config.json`, and converts an old `seal/config.md` once.** Where the root holds `config.md` and no `config.json`, bare `seal mode` writes `config.json` from the table's rows in their order and removes `config.md`. A table it cannot read whole, or a row written twice, writes nothing and prints why. Until the conversion, `seal gate`, `seal pr-body`, `seal fold`, `seal pact` and `seal mode --check` exit 2 and name `seal mode`, and `seal rules`, `seal settle` and `seal unverified` read the `Policy root` and `Reference specs` defaults, as they do for any config they cannot read. Where both files stand, `config.json` is read and `seal mode` names `config.md` as left in place. With no file at all, `seal mode` writes `{"Mode": "<the folder's mode>"}`.
- **The migration config is `seal/parity.json`, and its machine-local paths are `~/.claude/agentic/parity-paths.json`.** Its presence still declares a migration. `chain_check.py`'s parity arm reads its `Baseline commit` key, and refuses a `seal/parity.md` that git carries without a `seal/parity.json`, naming the keys to write. `templates/setup/parity.json` replaces `templates/setup/parity.md`, and the template's prose moved to `skills/legacy-parity/SKILL.md` *The migration config*.
- **A pact's signers stand in a `Pact signers` key of the pact repository's `seal/config.json`, and the checkout map is `~/.claude/agentic/pact-paths.json`.** `seal pact` exits 2 naming the key where it is absent. The map is one JSON object from a remote URL to a checkout path, and two keys that name one remote are refused, with neither read.
- **The table walker lives in `lib/tables.py` and reads records only.** It reads a frame's anchor table, *Judgments of the run* and `seal mode`'s conversion of an old `config.md`. `lib/config.py` holds the settings alone.
- **Every shipped text calls a setting a key and names `config.json`.** `templates/setup/config.md` was rewritten whole around a JSON example, and its heading *What no row governs* is now *What no key governs*. `skills/config/SKILL.md` shows a `Key` column and adds a missing key alone, as `"<key>": "<value>"`. First setup (`skills/implement/bootstrap.md`) adds the two language keys and the `Broad gate` key the same way. `README.md` and `README.ko.md` say how to update. Where a sentence meant the `Broad gate` value being run, it now says "the command": the gate's printed reasons say "the command ran once at the base" and "no pytest the command ran here left a record". The refusal for an absent `Broad gate` key says `/agentic:config` "shows every key and adds this one". The `hygiene.yml` step that runs `seal mode --check` is named "the mode the key declares is the mode the folder is in".

Updating: run `seal mode` once in each repository that holds `seal/config.md`. It writes `seal/config.json` from the table and removes the old file, and until then `seal gate`, `seal pr-body`, `seal fold`, `seal pact` and `seal mode --check` exit 2, and `seal rules`, `seal settle` and `seal unverified` read the default policy root and reference roots. Rewrite three files by hand from the old ones, since no command converts them. `seal/parity.md` becomes `seal/parity.json`, with the keys `Original repo`, `Module`, `Baseline commit`, `Policy root`, `Coordinate-trust exceptions` and `Scope notes`. The `| Signer |` table of a pact's `seal/pact.md` becomes a `Pact signers` key in that repository's `seal/config.json`, the remote URLs separated by `;`. `~/.claude/agentic/pact-paths.md` becomes `~/.claude/agentic/pact-paths.json`, one object from remote URL to checkout path.

### Removed

- **The explanations of a settings table the walker did not read.** `broad_gate.py` no longer explains a `Broad gate` row that was fenced, commented out, below a refused line or holding a bare pipe, since a JSON key has none of those causes; its refusal for an absent key stays. `templates/setup/config.md` lost its list of refused table shapes, its escaped-pipe rules and its paragraphs on a fenced row and a row inside an HTML comment. `skills/config/SKILL.md` lost its copy of that list.
- **The table writer and the 0.18.x pact header.** `seal mode` no longer edits a table line in place, and `seal pact` no longer reads a `| Signatory |` header; a pact with no `Pact signers` key is refused as a pact nobody signs.
- **`templates/setup/parity.md` and the `| Signer |` table of `templates/setup/pact.md`.**
- **"To create it, copy `templates/setup/config.md`".** `skills/commit-pr-convention/SKILL.md` now says `seal mode` creates the file; the template is the documentation of the keys, not a file to copy.
