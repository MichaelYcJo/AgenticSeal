### Fixed

- **The hook dispatcher passed on a gate's `allow` as the group's decision, and printed a `PreToolUse` gate's JSON with its `updatedInput` and a top-level `decision: "approve"`, so a hook of this plugin could approve a tool call or change its input; the plugin directory held the plugin for it. The dispatcher now passes on `deny` and `ask` alone (#1381).** `hooks/dispatch.py#merge` treats any other decision, `allow`, `Allow` and `defer` among them, as no decision, and keeps its reason as the gate's text. Where several gates decide, `deny` wins over `ask`, and every reason is kept. The word it passes on is printed lower case, so a gate's `Deny` reaches Claude Code as `deny`. On `PreToolUse`, a gate's JSON without a decision is printed without its `updatedInput` and without a top-level `decision` other than `block`. A `block`, `continue: false` and `stopReason` still pass, and every other event's JSON is printed whole as before. No gate prints anything the change stops passing on, so no installed repository sees its gates decide differently. The change passes on less and never allows more: a dropped `allow`, `approve` or `updatedInput` leaves the call, with the input Claude sent, to Claude Code's own permission flow, which asks the person or applies their permission rules. The one dropped value that does not reduce to asking more is `defer`, which ends the turn in a `-p` run. No gate prints it. The change adds no prompt to a session. It reads and writes JSON in one Python process, so nothing in it differs across macOS, Linux and Windows. CI runs the suite on all three under Python 3.12, and no CI leg runs Python 3.9, the oldest `python3` the dispatcher is written for. Whether the change clears the plugin directory's validation is read when the owner resubmits the `dist` branch of this release. The rule is in force from this merge through the work item's rule changes. The settle after the release writes it into `docs/checks/the-session-hooks.md` *Registration*.
