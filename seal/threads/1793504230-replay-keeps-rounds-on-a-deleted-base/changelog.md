### Fixed

- **The replay generator keeps a round whose base branch was deleted after its release (#1224).** A round record names the branch its target was reviewed against, often a `release/vX.Y.Z` branch, and every such branch but the newest is deleted once its release ships. `evals/scripts/replay_targets.py` read the base as the merge-base of the target and that branch, so it left every such round out as `the target line names no base that resolves`: 18 rounds over v0.27.0 and v0.26.0 on 2026-11-01. The commit that last wrote the round's record now stands for the deleted branch. A pull request into a release branch is squashed, so that commit holds none of the target's commits, and its merge-base with the target is the fork the branch named. Every target the generator kept before comes out the same, and the eight committed proofer cases regenerate byte for byte as they did before.

- **A base that would give an empty diff gives no base (#1224).** Where the tip a round's base is read from already holds the target, as the last writer of a branch still in progress or a branch merged with a merge commit does, the merge-base is the target itself and the case would review nothing. `--count` picks the smallest targets first, so such a case would have been picked before any other. The round is now left out with the reason a base that does not resolve gives.
