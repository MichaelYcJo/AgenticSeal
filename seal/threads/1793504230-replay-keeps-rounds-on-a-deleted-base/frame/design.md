## Scope

In:

1. **`replay_targets.py#targets` passes each record's landed commit to `round_target`.** The landed commit is `written_at` of the record's path: the commit that last wrote it in the working tree's history, or in the history of the first tag that holds it. This applies to both layouts and to all three record shapes. A round whose `target:` value, or whose asked paragraph, names a base ref that no longer resolves then takes its base as the merge-base of its target and that commit. A record no commit wrote passes no landed commit, as today.
2. **`replay_targets.py#ref_base` gives no base where the tip it reads already holds the target.** The tip is the ref where it resolves, or LANDED where it does not. Where `git merge-base --is-ancestor <target> <tip>` succeeds, the tip carries the target's own commits, so the merge-base is the target itself and the case would review an empty diff. The round is then left out with the reason it gets today, `the target line names no base that resolves` or `the asked paragraph names no base that resolves`, which is true of it. A working-tree record of a branch still in progress is such a record where its ref does not resolve: its last writer, which scope item 1 passes as LANDED, descends from its target. `--count` picks the smallest targets first, so a target with an empty diff would be picked before any other.
3. **The docstrings say what LANDED is for each caller.** `round_target`'s sentence "LANDED is the commit the work landed on, where the caller knows it" names both callers: `targets` passes the commit that last wrote the record, and `seed_defects.py#target_at` passes the shipped commit's first parent. `ref_base`'s docstring states the check of scope item 2. The docstring of `targets` says it passes LANDED. The comment in `tests/evals/test_replay_targets.py#Test_module::test_a_labelled_target_names_its_base` that says "where the caller knows that commit" is rewritten to say who passes it.

Out, each with its reason:

- **How an unanswered `--case` name is reported (#1228).** That is `replay_targets.py#say_unanswered` and `seed_defects.py#say_unanswered`, and a separate work item that runs after this one. The two items touch the same module. This one edits `targets`, `ref_base` and the docstrings of `round_target` and `targets`, and leaves `say_unanswered`, `main` and the module docstring's `--case` sentences to #1228.
- **Any change to `seed_defects.py`.** It already passes the shipped commit's first parent as LANDED (`seed_defects.py#target_at`), and the probe gives all 8 of its commits a base that is not the target. Scope item 2 is in `ref_base`, which both generators call, and it changes no seeded output: a seeded target whose base came through LANDED and equalled its target would have no added line to seed, so no such case exists.
- **Regenerating the committed proofer cases.** #1229 does that in 0.27.2. Scenario 4 says what this work changes in such a regeneration.
- **A remote not named `origin`.** `target_base` reads `against <name>` as `origin/<name>`. In a clone whose remote has another name, no ref resolves, and scope item 1 then gives every merged record its base from the landed commit, while scope item 2 leaves out a record of a branch in progress. Nothing in the tree runs the generators outside this repository's own clones.
- **A table record whose asked paragraph names no base ref.** 75 records from before 0.22.0 are left out as `the asked paragraph names no base that resolves`, because the paragraph names a document, not a branch (`## Grounding`, the every-tag row). No ref was deleted there, so they are not this defect, and nothing in the record says which commit the review was against.
- **The issue comment's count of 15.** The measured count is 18 on 2026-11-01 (`## Grounding`). Both counts belong to the day their run was made, and Scenario 1 asks for no record left out for this reason, whatever the count.

## Data & interfaces

- `evals/scripts/replay_targets.py#targets` gains one argument in its call to `round_target`: `landed=`, set to `written_at(layout.record(item, n), tags)`. `round_target` already calls `wrote(rel)` for a record in blocks or in labelled lines. The crafter may reuse that result instead of calling `written_at` twice, as long as `written_at` stays the one source. One `written_at` call took about 18 ms in the clone (executed: five `git log -1` calls in 0.09 s), and `--list` over two tags reads 63 records.
- `evals/scripts/replay_targets.py#ref_base(target, ref, landed=None)` keeps its signature and return value. It returns `""` where the tip holds TARGET. The crafter picks the test: `git merge-base --is-ancestor <target> <tip>` exiting 0, or the merge-base equal to TARGET's full SHA, which says the same thing without another git call.
- `round_target`, `target_base` and `base_of` keep their signatures. `seed_defects.py` is not edited.
- No output line changes its text. `--list` prints more kept lines, and a round left out by scope item 2 keeps the reason the unchanged generator gives.

## Rule changes

- nothing
  why: No policy sentence says how a replay case finds its base. `docs/the-review-record.md` *What the check reads at the pull request* names which check reads a record, and this work keeps that. `evals/README.md` describes a replay case as "a round record's target", and this work does not change what a case is.
