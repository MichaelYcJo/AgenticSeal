## Technical context

The tree as read at `e503c6961`.

Two texts disagree, and a script holds one of them. `skills/implement/orchestration.md:539-556` has the orchestrator move every unresolved row out after the last round, and its table sends a row to `seal/follow-up.md` or, for a work item whose subject is the policy root, into a policy document. `skills/code-review/scripts/chain_check.py#follows` (`:1007`) refuses the first commit after the last record's `target:` that touches a path outside the work item's directory, and `#records` (`:1472`) prints it as a verifying round owed. The policy root states the script's rule (`frame/design.md` G1) and the core holds it as an invariant (G2), so the procedure is the text that is wrong. Since release 0.39.2 `seal gate --preflight` meets the refusal before a pull request exists.

A row bound for `seal/follow-up.md` is known before a round is spawned in every case but one (G7): the orchestrator defers a finding of a round after which no fix pass runs. In a repository with a tracker that finding's home is an issue or a comment, which is no commit (G8).

The orchestrator's rows of `frame/plan.md` *Judgments of the run* are prose in a four-column table that `skills/settle/scripts/settle.py` reads by its header (G17). The false rows that release 0.39.2's records and its branches show are of these kinds. Most restated what a fold commit changed: a number of lines, a list of what was folded or left, a word for the kind of fold, or which commit made a change (G11, G12, G15). One judged what a sentence meant (G13), one grounds cell misdescribed two rewrites (G11), and one said the frame named a constant it did not (G15). One decision had no row (G14). The fix of G12's rows made one of them longer, by listing more of what the fold changed (G15), which is the content *Scope* item 4 takes out. `skills/implement/orchestration.md:126-144` has the row written before the decision is sent, so a row that describes the fold describes a commit that does not yet exist, or is rewritten afterwards from memory of a hand-back.

The failure scenario of the chosen approach, in six months. For #1630: a repository with no tracker stops a run with every open finding deferred, one of them to `seal/follow-up.md`, and pays a verifying round for one table row or takes rung 4 and loses the row; if such repositories turn out to be common, row 2 or row 4 of the table below is weighed again against that count. For #1639: a sentence that tells the orchestrator what a row leaves out is still text, and an orchestrator that writes an inventory of a fold into a row is found only by a round or by the sealer, as today; the settle's dry run then shows the same kind of row costing rounds again, and rows 8 and 10 are the mechanisms to weigh first.
