### Changed

- **Each record of a work item holds its own facts once, and the pull request body opens with the part a teammate reads (#1148).** In 0.24.0, 12 of 17 findings that review rounds raised again stood only in a work item's own records, where one record restated another. Each fact now has one record, and the other records cite it. The record templates lose every section that could hold only a copy. `frame/design.md` has no `## Open questions`, since `frame/questions.md` holds the questions. `frame/plan.md` has no `## Summary` and no `Approved` line: reading the plan and spawning the build is the approval, and the phase's Status cell records the commit. A phase record, `trail/phases/phase-N.md`, is its title and `## What this phase found`, and every departure from the frame is written there, a removal the frame did not name among them. `gaps.md` holds `## Not verified` and `## Not done`, with `## Scope confirmation` for work that has no plan. The first phase writes `gaps.md` when it closes, and every later phase and fix pass adds to it. The pull request body that `seal pr-body` writes now opens with the orchestrator's part. Under it comes the line `## From the records`, and then the copy of the records inside one `<details>` fold with nothing inside it folded again. `seal pr-body --check` compares only the part below that line, so a body written by 0.25.0 is refused until `seal pr-body` runs again. The ready pull request check no longer asks for a verifying review round after a `fixed` finding of the last round whose commit touched only the work item's own records; a `rejected` finding and a fix that touched any other file still need the round. A repository still running 0.25.0's check refuses such a pull request until its plugin updates. `skills/implement/orchestration.md` drops from 5,971 words to 3,422. Its table of orchestrator acts moves to `skills/implement/acts.md`, and its procedure for a work item that commits in more than one repository moves to `skills/implement/multi-repository.md`. The rule that three failed fixes of one bug stop the work moves from the crafter's definition to `skills/implement/SKILL.md`, where a session that builds without a crafter also reads it. The framer gains a rule that a design adding a mechanism names what it removes, and that a step that was blocked or failed is answered by removing or citing its cause, never by a new mark. Before the first build, the orchestrator reads the frame against the issue and sends its reading to the framer as proposals, which the framer answers in one exchange. The interpreter-too-old message no longer sends a user to a `CONTRIBUTING.md` their repository does not hold. A work item already in flight keeps its records as they were written, since nothing parses the sections that left.
