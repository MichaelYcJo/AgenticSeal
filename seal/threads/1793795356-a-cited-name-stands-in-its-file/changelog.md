### Added

- **A cited `path#name` must name a name its file binds (#1256).** A comment or document that cites a function, a class or a constant as `hooks/x.py#helper` now fails the suite once `helper` leaves `hooks/x.py`. Before this release nothing read such a citation, and one comment cited a function that was removed before the comment was written, through 25 release tags. `tests/behaviour/test_a_cited_section_stands_in_its_file.py` reads the new shape in the same files it reads section citations from: every tracked file outside `seal/threads/` and `evals/behaviour/`. It parses the cited file with Python's `ast`. A name resolves where the file defines it with `def` or `class` at any depth, or binds it at module scope by an assignment or an import. A local variable does not resolve. A cited path that names no tracked file fails, as a cited `.md` file does. A cited file that cannot be read or parsed is named in a warning and decides nothing. A token preceded by `:` or `/` is not read, so a `<commit>:<path>#<name>` and a path inside a URL are left alone, and a path whose first segment is no tracked top-level entry is not read. A citation in `docs/` that a pending rule change corrects passes with a warning until the settle, as a section citation does. The change has to hold the cited token whole in its `from` and not hold it in its `to`, so a rename from `#load` to `#load_all` corrects the citation. Five places in the tree cited a name their cited file does not bind: three files had lost the name, one cited file had been deleted, and one planted key named a file that never existed. Four sentences about a name the past held are rewritten without it, and one keeps the issue number its value's grounds hang on. One test builds its planted key when it runs.
