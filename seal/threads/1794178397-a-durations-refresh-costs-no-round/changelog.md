### Changed

- **A stale `.test_durations` now fails only the release pull request, so no work item spends a review round or a broad run on refreshing it (#1444).** `pytest-split` divides the Windows and macOS test shards by the per-case seconds in the committed `.test_durations`. A suite case, `test_the_durations_file_prices_the_suite`, failed every run of the suite once more than one case in twenty had no price in the file, or more than one second in twenty of the file's belonged to cases nobody ran. The logged crossings each came from one work item that renamed or removed many cases, and that work item then committed a refresh after its build, which owed a verifying round, and a broad run taken before the refresh failed. The suite case leaves. `.github/scripts/durations_union.py`, which the `durations` job already ran to union the Windows shards' measurements, now reads the two shares once for its summary and for a verdict. With `--stale-fails` it exits 1 past `STALE_SHARE` (0.05), after it has written the union and its report. Its sentence names the counts, the shares, the first ids on each side and the refresh. The script's exit codes are now 0, 1 and 2. `.github/workflows/test.yml` passes the switch only on a pull request into `main`. The `test-durations` upload runs wherever the union was written, so a red run still carries the file a refresh commits. Every other run reports both shares and passes. `CONTRIBUTING.md` *Running the checks* states that a work item never commits `.test_durations`. When the release pull request's `durations` job is red, whoever prepares the release downloads that run's `test-durations` artifact and moves it over the committed file. They commit it alone with the trailer `Seal-Routing: no work item`, on a branch cut from `release/vX.Y.Z`, and merge that branch into `release/vX.Y.Z` by a pull request. The per-branch refresh steps (`gh run rerun`, `gh workflow run`) are gone from that paragraph.
