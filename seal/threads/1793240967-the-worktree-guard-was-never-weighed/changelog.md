### Removed

- **The worktree guard (#1049).** No hook of this plugin asks about or refuses a `git checkout` or `git switch`, a `git worktree add`, or an Agent call with `isolation: "worktree"` any more. A run you routed `automation` no longer stops on either, and a switch is no longer refused for five minutes after another session has ended. The guard's record held no catch: the issue tracker, the 51 `flow-measurement` logs and the work item records at the 61 release tags `v0.0.1` to `v0.24.0` show it stopping no switch or creation that would have disturbed another session, and four `from-use` issues show it stopping or misleading a run. What a person loses is the one thing it was for: nothing stops a session from switching the branch of a working tree another live session is using. `git switch` still aborts where the switch would lose local changes, and the routing edit gate still refuses an edit on a branch no `routing.md` names. Both READMEs now state the limit under the gate table: give each concurrent session its own worktree. The tokens `[worktree-ok]` and `[shared-tree-ok]` and the variable `WORKTREE_GUARD_IDLE_MIN` are read by nothing, and `docs/worktree-guard-spec.md` is deleted.
- **The creation record and the session lease (#1049).** The hooks `worktree_consent` and `session-lease` are gone, and so is the `post-agent` hook group, which ran only the first. Clones that ran an earlier release keep three directories nothing reads now, and you may delete them: `<git-common-dir>/agentic-worktree-consent/`, `<git-dir>/agentic-worktree-choice/` and `<git-dir>/agentic-leases/`.
- **The plugin option `worktree_guard_language` (#1049).** It was declared in 0.24.0 and set the language of the guard's prompts, the only gate with Korean prompts. A value you set in `/config` is read by nothing. `SPECSEAL_LANG` is read by nothing either, earlier than the 0.24.0 notes said: they said it would be read through the 0.24.x releases.
- **The command readers only the guard used (#1049).** `hooks/lib/cmdline_base.py` (2,288 lines), `hooks/lib/tokens.py` (118) and `hooks/lib/one_heredoc.py` (107) are deleted, with `hooks/worktree-guard.py` (3,667), `hooks/session-lease.py` (128) and all of `hooks/worktree_consent.py` (630) but its press reader. `hooks/lib/cmdline.py` keeps what the commit notice reads and goes from 1,382 lines to 925. `hooks/lib/hooksession.py` loses its walk of the process tree. The suite loses about 116 s of recorded serial test time.

### Changed

- **The reader of the `automation` press moved to `hooks/lib/press.py` (#1049).** The routing edit gate and the question gate read your click on the routing question there, as before. Nothing in what it reads changed.
- **A gate that fails in `pre-bash`, `pre-agent` or `post-bash` is reported with a shorter line (#1049).** No other gate shares those groups now, so the end-of-turn line ends "calls went ahead without it." where it used to add that the other gates in the group still decided.
- **`skills/implement/SKILL.md` no longer tells the story of the guard's question over uncommitted changes (#1049).** That paragraph's one example was the guard. The issue template for a misfired gate names the routing edit gate and the question gate as its examples.
