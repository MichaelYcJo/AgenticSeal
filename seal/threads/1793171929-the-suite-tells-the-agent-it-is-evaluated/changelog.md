### Changed

- **The behaviour suite no longer tells the agent under test that the run is an evaluation (#1042).** Every commit a rule case's scaffold makes is now authored as `textutil <textutil@example.com>`, after the project the case builds; it was `eval`. The five sealer cases keep the issue body and the pull request body under `.git/<work-item-id>/`, where the directory was `.git/agentic-eval/`. The seeded cases' amend no longer sets an identity: it keeps the target commit's author and takes its committer from the environment, and it runs where git has no identity configured. `noninferiority.py run` loads the plugin from a temporary directory named `agentic-` followed by random characters, where it was `agentic-eval-`; that path is the base directory of every skill the agent reads. A new case, `tests/text/test_no_case_tells_the_agent_it_is_evaluated.py`, reads every `prompt.md` and `scaffold.sh` under `evals/behaviour/` and refuses six words that name the run as a measurement, such as `eval` and `grader`, in any inflection. Two kinds of text are exempt: the record shapes the plugin's templates write, and the values a replay or seeded case copies from this repository. Written again by their generators, the seeded cases also fetch from this repository's current URL. A side recorded before this change cannot be regraded onto the new suite, so the next comparison of the crafter, framer, proofer or sealer takes both sides at the new suite. The truth graders still sit in the tree the eval loads, because `claude plugin eval` reads cases only from inside the plugin it loads.
