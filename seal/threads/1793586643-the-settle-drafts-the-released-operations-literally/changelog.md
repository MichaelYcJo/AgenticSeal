### Added

- **A settle can start from a literal draft: `seal settle --draft` writes every operation of the released designs into the policy root in merge order, and names each one it could not place (#1217).** Each settle wrote a scratch script to apply the released designs' `## Rule changes` in merge order before judging them, and the 0.27.1 settle placed 90 of 91 operations that way (#1214). The command now does that pass. It applies each operation of each design the dry run groups, in merge order and in the order its design lists them, to the policy root in the working tree, each over the text the earlier ones left. A `change` turns its `from` into its `to` inside its section, an `add` lands at the end of the section's own text, and a `remove` cuts its `from`, or the whole section when it has none. An `add` whose `to` is one table row lands as the last row of the last table in the section's own text, before its first sub-heading. An `add` with no section creates its document, a `remove` that empties one deletes it, and each document keeps its line ends, CRLF or LF. A superseded operation is written like any other, because the draft decides nothing. Where an operation's document or heading is not there, its heading is there twice, its `from` is not in its section exactly once, or an `add` with no section names a document that exists, the draft writes nothing for it and prints one line with its kind, its work item, its design's line and the reason. The operations after it are still written. The last lines count what was placed, and send the settling session to the procedure's step 4, where every section the draft wrote is read against the code and each operation not placed is written by hand. The draft exits 0 whatever it placed. Beside `--apply` or `--from` it exits 2 with one sentence and writes nothing. It is run once, before the first edit of the policy root, and committed on its own, so the settle's pull request shows the literal pass and the session's judgment as two diffs. A second run writes every operation again over the first. Replayed over the eleven designs of the 0.27.1 settle, it places 93 of 94 operations, and `docs/README.md` comes out equal to the file that settle merged. Running the draft is optional, and a settle that does not run it works as before. `skills/settle/SKILL.md` *What `--draft` writes* holds the rules. The settle after the release writes the change into `docs/the-record-layout.md` *The fold, and what tells it from a deletion*.
