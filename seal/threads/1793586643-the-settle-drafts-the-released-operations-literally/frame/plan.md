# Implementation Plan: the settle drafts the released operations literally (#1217)

## Technical context

- **The reader and its order.** `skills/settle/scripts/rule_changes.py#parse` reads each design's operations, and `#order` (shared root) or `#merge_order` (local mode) gives the merge order. `skills/settle/scripts/settle.py#timeline` (lines 697-762) calls both, keeps the ordered list `ordered` in a local, and returns only the groups. The draft needs that list returned beside them.
- **Where text is found.** `rule_changes.py#pattern` (line 270) is the whitespace-collapsing, word-bounded pattern the dry run's `settle.py#facts` (line 680) finds a `from` and a `to` with, and `#section_lines` (line 282) gives a section's span. `apply_op` uses both, so the draft and the dry run find a `from` the same way.
- **The applier to restore.** `91d570289^:skills/settle/scripts/rule_changes.py`, lines 198-279: `_cut` and `apply_op`. At that commit it read headings through the same `headings` and `reader().gfm_lines(text, keepends=True)` the module holds today (`hooks/lib/blocks.py#gfm_lines` still takes `keepends`). P1 ran it unchanged but for the table-row branch.
- **The table reader.** `hooks/lib/config.py#table_cells` (line 949) and `#opens_table` (line 1052). `rule_changes.py` loads its siblings by path (`reader`, `passages`), and `config.py` joins them the same way. Both modules are linted at `py39` (`ruff.toml`), and `tests/hooks/test_launch.py` holds that list.
- **The second application.** `rule_changes.py#copies` (lines 361-401) and `skills/code-review/scripts/chain_check.py#pins_and_copies_in` (lines 1239-1297), from #1216. It stays as merged: this work does not touch it (A3, A17, A18).
- **The argument refusals.** `settle.py#main` refuses `--from` beside `--apply` with `FROM_WITH_APPLY` before anything is read. `--draft` joins that refusal.
- **#1139.** In review on its own branch, it changes `--apply` and adds `settle.py#adding_commit`. This work touches `main`, `timeline` and a new `draft`, not `apply`. A textual conflict is the orchestrator's to merge.

**The failure scenario, six months out.** A settling session runs `--draft`, sees most operations placed, and commits the result with little reading. A superseded sentence, a doubled check line, or a `to` that ends while its old paragraph goes on below it reaches `docs/`, because each of those is a correct literal application. What stands against it: the procedure's step 4 says every section the draft wrote is read against the code, the draft is committed alone so the owner's review sees the session's judgment as its own diff, and the settle's broad run still reads every check. A grammar change that adds an operation kind has three places to change in one module: `parse`, `apply_op` and `copies`' loop over `gone`. `apply_op`'s docstring names `copies` as the other application, so whoever changes one finds the other.
