### Where the script stops and the session's judgment starts

`skills/core/SKILL.md` *Judgment is spent where meaning is the question, and a script answers the rest* splits the work this way.

- **The draft answers exactly.** It places each operation where G2's table says, finding a `from` by the `pattern` the dry run already uses (`rule_changes.py#pattern`), and reading a table row through G9's reader. Where a place is not there once, or a `from` is not there once, it writes nothing for that operation and names it with the reason. It applies every operation of every grouped design, a superseded one among them, because a literal pass has no notion of which decision is latest.
- **The session judges meaning, as before.** Which operation is the latest decision, and what an earlier one it restates leaves standing. Whether a section the draft wrote reads as one rule: a `to` that ends in a check line while the old paragraph goes on below it, two sentences that now say one thing. Whether a sentence still names something another design removed. How each operation the draft named is written by hand. Whether the code has moved past the decision. Every section the draft wrote is read against the code like a section the session wrote, and the session's procedure says so.

## Scope

In:

1. **`rule_changes.py#apply_op(text, op)` places one operation in one document's text.** It is G8's function restored, with `_cut`, beside `pattern` and `section_lines`. It returns the new text, or the reason it did not place the operation, or that a `remove` emptied the document. It places each kind as G2's table states, and refuses, each with a reason that names the file and the section: a document not in the tree, an `add` with no `section` whose document exists, a heading not there, a heading there more than once (outside the nested whole-section case G8 keeps), a `from` not in its section, and a `from` there more than once. It keeps the document's line ends.
2. **An `add` whose `to` is one table row lands as the last row of the section's last table.** The `to` is one line that `config.py#table_cells` reads as a row. The table is the last one `config.py#opens_table` finds in the section's own text, before its first sub-heading, and the row goes after that table's last row. Where the section's own text holds no table, the `add` lands as any `add` does. A row whose width differs from the table's is placed all the same, and the session reads it. The `add` row of *Rule changes*' table says this in one sentence.
3. **`seal settle --draft` writes the draft.** It reads what the dry run reads: the released designs as `--released-at` holds them, or in local mode from their directories, and the policy root in the working tree. It applies each operation of each design the dry run groups, in merge order and in the order its design writes them, to the text the earlier operations left. A design the dry run lists to read whole, or that holds the no-change block, gives no operation. It writes each document it changed once, at the end, creates a document an `add` with no `section` names, and deletes one a `remove` emptied. It writes only the `file` of an operation, which `parse` holds to a top-level `.md` of the policy root. It prints one line per operation it did not place, with the operation's kind, its work item, its design's coordinate and the reason, in the shape of the dry run's operation lines (`settle.py#op_line`). Then it prints how many of how many it placed, and one sentence naming step 4 of the procedure as where each written section is read. It exits 0 whatever it placed, since an operation not placed is no verdict. `--draft` beside `--apply` or beside `--from` exits 2 with one sentence and writes nothing. A root holding no work item prints its settled line and writes nothing.
4. **The draft is run once, before the first edit of the policy root.** It applies to the working tree as it stands, so a second run applies each operation again. This is a limit stated in one sentence of the skill, with the command that returns the policy root to `HEAD`, and not a guard.
5. **`skills/settle/SKILL.md` states the draft.** The usage block gains `seal settle --draft`. The opening sentence G4 quotes says what the script writes, and that it judges nothing. A section after *What the dry run shows* states what `--draft` writes, what it prints, what it refuses, and the limit of item 4, and splits the work as *Where the script stops and the session's judgment starts* above does, in the skill's own words. Step 4 opens with the optional first act: run `seal settle --draft`, commit what it wrote as one commit, then write each group's section from there. Whatever the draft wrote is read against the code like any section the session writes, and an operation it named as not placed is written by hand. Step 11's body names the operations the draft did not place, each with how it was written.
6. **`copies` applies a design's operations through `apply_op`.** Its `gone` argument becomes `{path: [Op]}`, the design's operations by document. Each is applied with `apply_op`. Where one does not place and has a `to`, the `to` is put at the document's end, as `copies` does today for a `from` that stands only in another pending design's `to`. `chain_check.py#pins_and_copies_in` hands it the operations instead of `(taken, put)` pairs, and keeps `_section_text` for the pins of a `remove` with no `from`. Its docstring and `copies`' say what each operation does through the one applier.
7. **Every other text that says the script writes no policy document says what it writes** (contract rule 19). The method is `git grep -n -e 'neither writes' -e 'writes no policy' -e 'reads and removes' -e 'writes nothing' -- skills/settle README.md README.ko.md templates agents tests`, run at the phase's head and read line by line. Each hit about `seal settle` as a whole is corrected, and each about `--apply` or the dry run alone is named in the phase record as still true. `settle.py`'s docstring and `--draft` help join the usage. The `README.md` and `README.ko.md` rows gain one sentence each for `--draft` (G14).

## Data & interfaces

**`skills/settle/scripts/rule_changes.py#apply_op(text, op)`** returns `(new_text, None)` where it placed OP, `(None, None)` where a `remove` with no `from` left the document empty, and `(None, why)` where it did not place OP. TEXT is None for a document not in the tree. It loads `hooks/lib/config.py` by path once, as the module loads `unverified_check.py` and `passages.py`, and stays within `py39` (G13).

**`skills/settle/scripts/settle.py`.** `--draft`, a `store_true` flag. `timeline` also returns the grouped designs in merge order, `[(id, [Op])]`, so the draft and the groups read one order. A `draft(found, root, out)` beside `apply`, reading and writing each document with its line ends kept. The refusal sentences beside `FROM_WITH_APPLY`. Output, one line per operation not placed:

```
not placed  <kind>  <work item id>  seal/threads/<id>/frame/design.md:<line>  <why>
```

then `placed <n> of <m> operations in <policy root>/`, and the sentence naming step 4.

**`rule_changes.py#copies(op, texts, gone)`**: `gone` is `{path: [Op]}`. Its return value is unchanged.
