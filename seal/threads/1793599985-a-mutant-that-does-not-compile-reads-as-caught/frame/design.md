## Scope

In:

1. **A `.py` mutant that does not compile is refused before anything is written or run.** For a target whose path ends in `.py`, each mutant is compiled with the builtin `compile(<bytes>, <path>, "exec", dont_inherit=True)`. The bytes are the mutant's text encoded as UTF-8, which are the bytes the write would put on disk. Warnings raised while compiling are silenced, so the first line printed is still the verdict. A `SyntaxError` is a refusal: the existing `refused` verdict, exit 2, with a sentence naming the error's line and message and saying that nothing was written and the cases did not run. In a batch, the refusal names the pair by its place, as a pair that does not land exactly once already does, and no pair runs. The compile happens after every pair has been checked to land exactly once, and before the baseline.
2. **A `.py` file that does not compile as it is gets no compile step, and the run says so.** The file as it is is compiled the same way first, before any mutant. Where it does not compile under the running interpreter, no mutant is compiled and the run goes on as it does today, its verdict read from the cases' exit code. The first line printed carries one clause saying the mutants were not compiled, with the running interpreter's version and the original's error line. That line is the verdict line for one pair and the baseline line for a batch. A `refused` or a run that measured nothing keeps its own first line, and the clause is not added to it.
3. **A target whose path does not end in `.py` is not compiled.** It runs exactly as today. `.md`, `.yml`, a Python script with no `.py` suffix, a suffix spelt in other case such as `.PY`, and every other file kind fall here.
4. **Every `red` line carries the cases' exit code.** One pair's line already reads `red: the cases failed against the mutation (exit N)`. A batch's line changes from `mutant <n>: red (<s>s)` to `mutant <n>: red (exit <N>, <s>s)`. The command decides nothing from the code. Under pytest an exit of 2 is a collection error, so a reader of a batch can see one. An exit of 1 covers both an assertion and an import error raised inside a test (G8a), so telling those apart stays with the reader, who can run that one pair alone to see its output.
5. **The text a reader acts on says what the command now does, in the same commit as the code.** The script's docstring has the verdict table and the batch paragraph. `skills/verify/SKILL.md` *`seal mutate` asks condition 2 of one unit, one break at a time* has the verdict list and the batch line. Each gains the compile step, its refusal, the `.py`-only scope, the not-compiled clause and the exit code on a batch red. That section also carries the limits: the compile uses the running interpreter's grammar (G9), and a mutant that compiles and fails at import is not refused (G14). The `--replace` help names the compile for a `.py` target. `agents/crafter.md` already cites the skill for the verdicts and is not edited.
6. **The release's first pull request carries the version.** `.claude-plugin/plugin.json` moves from `0.28.0` to the release's version, `0.29.0`, in the release's first pull request (G12). Phase 2 moved it to `0.28.1` with this work item's `changelog.md`; the release was renamed to `0.29.0` to carry the feat #1299, and the orchestrator moved it on in a commit of its own.

Out:

- **Telling an import or collection failure from an assertion failure.** The exit code cannot tell them apart (G8a), and reading the cases' output would gate on words (G5). Item 4 reports the code instead, and the judgment stays with the agent reading the run.
- **Parsing other file kinds** (JSON, TOML, YAML, shell). No recorded run's red came from one, and each kind would need a parser of its own. The class "a mutant the cases' loader cannot parse" ranges over every file kind a case can load, so no method makes that list whole (contract rule 12). This work covers the one kind the issue and the records name, and the skill's limit sentence names the rest.
- **The cases' interpreter.** The compile cannot use the interpreter the cases run under, because the tests command is any command and names none that `seal` can read. The limit is stated (item 5).
- **`seal arms`.** Its mutants already pass `ast.parse`, and its operators cannot make the compile-only errors (G3).
- **Changing the installed plugin, or how agents resolve `seal`.** G11 says what a later item types instead. The orchestrator carries it in its spawn prompts.

## Data & interfaces

- `skills/verify/scripts/mutation_check.py`. One helper compiles bytes and returns `None`, or the `SyntaxError`'s line and message. `mutation_run` and `batch_run` call it on the original from `_held` first, then on each mutant, after every pair has been checked to land and before `_baseline`. A refusal is raised as the existing `Refused`, so `main` prints it as `refused:` and exits 2. In a batch, it carries the existing `pair <n>:` prefix. The not-compiled clause reaches `main` with the verdict, or with the baseline item for a batch, and joins the first line. `_report_batch` prints a red line with its exit code. That code is the one `run_cases` already writes into the red detail as `(exit N)`.
- The printed lines. A refusal reads `refused: <sentence naming the file, the line and the message; nothing was written and the cases did not run>`. In a batch it reads `refused: pair <n>: ...`. A batch red line reads `mutant <n>: red (exit <N>, <s>s)`. Every other line is unchanged. The crafter words the sentences, and S1 to S7 pin what a reader acts on: the verdict word, the exit, the pair's place, the line number, and the clause's presence.
- No exit code changes meaning. `red` stays 0, `SURVIVED` 1, and everything that measured nothing, `refused` among it, stays 2.
