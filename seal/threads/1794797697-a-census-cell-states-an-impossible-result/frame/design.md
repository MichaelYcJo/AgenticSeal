## Data & interfaces

The paragraph of *Scope* item 1 states five claims. The wording is the build's, under `skills/writing-style/SKILL.md` *English prose rules* and the three rules of *에이전트와 검사가 읽는 글은 한 가지로만 읽히게 쓴다*.

- **C1, what it covers.** A search the framer writes into a *Verified by* cell of `frame/plan.md`, or into a *Verifiable how* cell of `frame/design.md`, together with the result it is to give: that it prints nothing, or only named files or lines. The paragraph names this object by what it is (G9).
- **C2, the run and the account.** Before writing the cell, the framer runs the search at the commit `## Grounding` names. Each line it prints is one of three kinds. It is a line the build removes, under a *Scope* item or a `## Removes` row. Or it is a line the design keeps, and the search is narrowed until it no longer matches that line, or the cell names that line's file. Or it is a line in a file the cell excludes by name or by pathspec.
- **C3, the work item's own records.** The frame quotes the patterns it searches for once it is committed, and the run at the frame's commit cannot see that. So the search excludes the work item's directory, or the cell names it among what the search still finds.
- **C4, what the cell states.** The cell states the result the account leaves. Where any line stays, the cell names where it stays, and does not say that the search finds nothing.
- **C5, the record and the other half.** `## Grounding` holds the run, labelled `executed`, with its command and commit, as the paragraph opening *A question a command answers is answered by running it* asks of a probe. A search that prints no line the build removes at that commit cannot fail either, which `skills/verify/SKILL.md` *An absence claim is only as good as the search behind it* states. The paragraph cites that section and does not restate it.
