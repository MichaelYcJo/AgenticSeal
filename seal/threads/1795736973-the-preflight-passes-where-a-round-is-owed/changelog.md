### Fixed

- **`seal gate --preflight` and the broad run now refuse a branch whose last round record owes a verifying round, before a pull request exists (#1620).** The gate runs `skills/code-review/scripts/chain_check.py` under `--sealing` and fails its chain arm on the exit code alone. With no pull request to read, the check judged none: it printed each refusal as a notice and exited 0, so the preflight printed `PREFLIGHT PASSED` over "a verifying round is owed", and the pull request's check was the first reader to refuse it. Two of the five gate runs that releases 0.39.0 and 0.39.1 recorded passed that way. Under `--sealing` the check now reads no pull request's state, asks neither the event payload nor `gh`, and judges as at a ready pull request, whatever the state. The arms that read what is written after the gate, `trail/gate.md`, `guarantee.md` with its `original:` line, and the pull request's body, still print and do not fail. The first line the check prints under the flag says how the run is judged. A run without the flag, CI's and the `--worktree` reads the orchestrator and the proofer take, keeps its judgment. `docs/checks/the-pull-request-check.md` *What the check reads at the pull request* states the rule from the settle after this release, which writes it from the work item's `## Rule changes`.
- The version moves to 0.39.2.
