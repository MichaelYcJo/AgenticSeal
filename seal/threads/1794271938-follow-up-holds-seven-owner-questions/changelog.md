### Changed

- **A phase moved to an issue has a value for its Status cell, `deferred #N` (#1493).** `skills/implement/SKILL.md` *3. The SDD file set* said a Phases row's Status cell is empty or holds the commit that closed the phase, so a session meeting a phase handed to another issue either invented a spelling or left the cell empty, which reads as a phase still open. The cell now holds one of three values: empty, the commit that closed the phase, or `deferred #N` for a phase the work item handed to issue #N. A tick and the word `done` are still refused, because neither names something a reader can open. Nothing checks that issue #N exists; the proofer and the sealer read the plan against the tracker.
- **Three cases that say what a release script may invoke read its `gh` argvs through one parser (#1493).** `tests/github/test_release_completeness_check.py` and `tests/github/test_label_merged_on_release_branch.py` searched the script's source with its whitespace folded, so a forbidden argv with a comment between two of its words passed. They now read the script through `argv_words` in `tests/github/test_close_issues_on_release.py`, which parses it with `ast`, as that module's own case already did. It reads an argv written as a list, as a tuple or as call arguments. An argv that takes one of its first three words from anything but a plain string literal, such as a module-level name, an f-string or a bytes literal, still passes all three, and `argv_words`' docstring says so.
- **The third routing axis's template case compares the template's placeholder with the parser's answers (#1493).** `tests/behaviour/test_waiver_decided_at_start.py` substituted the parser's constants back into the template row, so a renamed constant renamed the substitution with it and the template could drift from the parser with the case green. The case, renamed `test_the_template_PARSES_into_the_THIRD_axis_it_ships`, now reads the two answers the `Implementation` placeholder offers and compares them with `lib/routing.py`'s `IMPLEMENTATION_ANSWERS`, as the `Planning` and `Automation` cases do.
