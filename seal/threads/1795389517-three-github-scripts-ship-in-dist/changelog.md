### Fixed

- **No file the plugin ships loads a script from `.github/`, and `dist` holds nothing under `.github/` (#1571).** Three shipped commands ran a file kept under `.github/scripts/`: `seal pr-body` loaded `close_issues_on_release.py` for its reader of closing keywords, `seal rules` ran `rules.py`, and `bin/test` ran `run_tests.py`. The release's version check watched nothing under `.github/`, so a release that changed one of the three alone reached nobody. The closing-keyword readers, and the one pattern that reads a squash subject's `(#N)`, now stand in `lib/closing.py`. `seal pr-body`, `chain-check`, the release closer, the claims check, the merged-label script and the release note all load that module, where each kept its own copy or reached into the closer. The check-line reader is `skills/settle/scripts/rules.py`, beside the two settle modules it reads. The suite runner is `tests/run_tests.py`, beside the suite it runs. `seal rules`, `seal pr-body` and `chain-check` keep their arguments, output and exit codes, and `bin/test` keeps its arguments and exit codes. In a copy with no `tests/` beside it, such as `dist`'s, `bin/test` now prints its own sentence, that this copy of `bin/` has no runner beside it. Before, the runner `dist` held answered there that no `tests` directory stood at the root. Both exit 2.
- **`.gitattributes` takes `.github/` out of `dist` by one line (#1571).** Fourteen lines took out `.github/workflows/` and each release script one by one, and a release script added under `.github/scripts/` needed a line of its own. GitHub's issue and pull request templates now leave `dist` with the rest of `.github/`. No shipped file reads them.
- **A release that changes only `docs/` must move the version (#1571).** Every installed agent opens `docs/` at the plugin's root, so a change there alone that kept the version reached no user. The pattern of the `hygiene` step *a change to what ships must move the version* now watches `docs/` beside `skills/`, `agents/`, `hooks/`, `lib/`, `templates/`, `bin/` and `.claude-plugin/`. `assets/` and the top-level files, such as `README.md`, stay unwatched: `dist` holds them and nothing installed reads them.

### Changed

- **The case that holds the version check's pattern reads what ships from `git archive` (#1571).** `tests/behaviour/test_the_release_check_watches_what_ships.py` kept two hand lists, one of the roots that ship and one of the entries that stay home, and both agreed with the pattern while neither matched `dist`. It now fails where a top-level directory the archive holds is neither watched nor named among the entries nothing installed reads, where a top-level file the archive holds is not named there, where the pattern watches an entry the archive leaves out, and where the pattern names a root the archive does not hold. The case that held the release document's copy of the root list is gone.
- **One census case replaces the two that read `.github/` in the archive (#1571).** `tests/behaviour/test_a_cited_section_stands_in_its_file.py` held a case that the archive carries no workflow and a case with a map of each `.github/scripts/` file a shipped command ran. One case now fails where the archive holds any path under `.github/`, or where a code string of a `.py` file the archive holds names a path under `.github/scripts/`.
