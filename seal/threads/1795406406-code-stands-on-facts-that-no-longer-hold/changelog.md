### Fixed

- **`seal mode` no longer names a clone's git directory as another worktree (#1576).** When `seal mode` moves the records between the shared and the local root, it prints a note for each other worktree of the clone, because that worktree reads its own branch's root until the commit reaches it. In a repository made with `git init --separate-git-dir`, and in a worktree of a bare clone, git lists the git directory itself first, and the note named it as a worktree. The note now leaves out the path git answers as the common git directory. Seen from a linked worktree of a `--separate-git-dir` repository, git lists no main worktree, so the note names none either.
- **`seal mode local` and the workflow template no longer say a workflow left in local mode examines nothing (#1576).** Where the switch leaves `.github/workflows/hygiene.yml` pinned to the installed release, `seal mode local` now says its checks read nothing as declared and pass. The header of `templates/setup/hygiene.yml`, which every installed copy carries, says the review-chain step judges the commit trailers alone and the mode step finds no root to disagree with. Both had said every step examines nothing, while the review-chain step still judged the trailers.

### Removed

- **The release workflow no longer creates the labels the documents declare (#1576).** `.github/scripts/tracker_labels.py` and its step in the close-issues workflow are gone. The one label it declared, `size: now`, stands on the tracker, and the workflow still takes it off each issue it closes. A person who deletes the label recreates it with `gh label create`. The roll of the flow-measurement issue still runs after a failed close.
- **`seal unverified` exits 0 for one state of a root only: the settled root (#1576).** It also exited 0 where the tree held no `seal/` root and where `threads/` held work items none of which carried a `gaps.md`, because a CI step ran it on every pull request, and that step left the shipped workflow in an earlier release. Both states now exit 2, as any path holding no `gaps.md` does: the first says `no such path`, and the second says `nothing was checked`. `seal unverified seal/threads/` on a root a settle emptied still exits 0 and says so. A workflow pinned to an earlier release keeps that release's command.
- **A `## Not verified` row opening with U+2705 is no longer refused (#1576).** An earlier release closed a row with that emoji, and the reader refused it with the edit to make. Such a row now reads as an open row whose item opens with the emoji, so `seal unverified` reports it rather than failing on it. A closed row opens with the word `closed`, as before.
- **`none` is not read as `nothing` in a record (#1576).** A round record's confirmation block reading `confirms: none` is refused at its line, where it was read as a confirmation of nothing; a round that confirms no earlier finding writes no `confirms:` line. A section opening with `- none` is no longer named as a near miss of the `- nothing` block, though the section is still refused for what it lacks. `skills/settle/rule-changes.md` gives `- Nothing` as its example of such a line.
- **`seal settle` no longer orders a design by its 0.22.x path (#1576).** The dry run places each design by the commit that added it under `seal/threads/`. A design first committed at `seal/specs/<id>/spec.md` was placed by that earlier commit, and is now placed by the commit that moved it.
- **A repository with no `seal/` root leaves its `specs/` directories out of `seal unverified`'s walk (#1576).** Releases up to 0.3.x kept closing memos under `specs/<id>/`, so in a repository with no root the walk read them. It now reads every `specs` directory as a reference root there, as it does where a root stands and no `Reference specs` key is declared.
- **A `trail/rounds` that is a file reads as no round record (#1576).** An earlier release's migration command left that file. `seal settle`'s dry run, the release's finding counts and the release seal named it as a directory they could not list; they now count no round there. A link at `trail/rounds`, and a directory nothing can list, are still named.
