## Scope

In:

1. **`agents/crafter.md` *A fix pass appends close blocks and writes no phase record*, the paste-ready sentences at `:167-173`, rewritten in place.** A paste-ready fix stays the proofer's claim and not the fix. A spawn prompt or a judgment row that tells the fix pass to apply it names the fix and does not waive the reading (G5, the second instance). The reading is against the frame and the code: what the phase's `frame/plan.md` row and `frame/design.md` say the unit does, and every input the code hands the unit (G5, the first instance). A procedure step is also read the three ways the sentence names now (either `seal/` root, every condition, the release that ships it), and the release sentence stays. Where the reading fails, the fix pass writes the fix in its own words and says so in `answer:`, as now. A draft:

   > A paste-ready fix is the proofer's claim and not the fix, and a spawn prompt or a judgment row that tells you to apply it names the fix without waiving this reading. Apply it only after reading it against the frame and the code: what the phase's `frame/plan.md` row and `frame/design.md` say the unit does, and every input the code hands the unit. A procedure step is also read as its own reader would: in either `seal/` root (contract rule 11), under every condition its file names, and in the release that ships it.

   The two sentences after it ("In that release, …" and "Where that reading fails, …") stay as they are. The sentences from "Once the fixes are committed" to the end of the paragraph are #1318's and stay as they are (G4, G13).
2. **Contract rule 15, `skills/agent-contract/SKILL.md:181-184`, rewritten in place.** A case that asserts something is not named, counted, read or let through passes against old code that does none of it. So it is shown red with only the guard it names removed, and the failing line is read for that guard. If the case stays green because a second guard also holds it, it pins nothing of the guard it names. The same is true if it fails on a line that names something else (G7). The last sentence keeps "A case that passes against the defect it was written for pins nothing", and its catch covers both forms: reverting the fix, or removing the one guard. "Say in the hand-back how it was shown" stays.
3. **`agents/sealer.md:145`, *A `seen red` is re-run against the code before the change*.** "A case that passes there was never red" gains its exception. A case that asserts something is not named, counted, read or let through, and whose record says it was shown red with its named guard alone removed (contract rule 15), is run again in the sealer's clone with HEAD's code restored and that guard alone removed, and its failing line is read for that guard. The clone is removed once its runs are done. The heading stays, because `evals/behaviour/sealer/rule-sealer-false-red/` is its check.
4. **`skills/verify/SKILL.md:42-43`, *2. Able to fail*.** "For a new test: it was observed failing against the pre-change code" gains one clause. A new test that asserts something is not named, counted, read or let through, where it passes there, is shown red as contract rule 15 says. The clause cites rule 15 and does not restate it.
5. **`skills/implement/SKILL.md:162-164`, *2. Implement test-first, and let each rule name its test*.** One sentence after the cadence's first sentence. A case that asserts something is not named, counted, read or let through and is already green against the tree as it stands takes its red from contract rule 15.
6. **`skills/code-review/SKILL.md:172`.** "A fix pass takes the snippet as the repair" becomes a statement of what a fix pass does now. A fix pass that finds the snippet holds applies it as the repair. The rest of the paragraph stands (G10).
7. **`tests/text/test_a_moved_rule_leaves_its_definition.py#test_the_crafters_fix_pass_appends_a_close_block_and_sweeps_what_its_range_reworded`.** It is the existing check of item 1's paragraph. Its clause tuple at `:472-482` takes item 1's rewritten sentences in place of the ones they replace. Each changed clause is seen red with its sentence deleted (contract rule 15). No case is added.
8. The work item's `changelog.md`, with one `### Process changes` row for item 1 and one for items 2 to 5.

Decided, and nothing is built for it:

9. No check, eval, hook or mark for either rule (G2, G9; `frame/plan.md` *Alternatives considered*). Whether a paste-ready text holds against the frame is a question of meaning. So is whether a failing line is the named guard's. `seal mutate` already reads the one exact fact, red or survived.
10. The issue's "with every sentence it leaves standing read too" stands in `agents/crafter.md:179-181` (G4), so this work does not restate it.
