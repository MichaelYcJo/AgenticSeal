### Changed

- **A fix pass reads a paste-ready fix against the frame and the code, even where its spawn prompt or a judgment row tells it to apply the text (#1286).** In #1216's run, one fix pass kept a proposal's collection against the frame's own rule that a `change` keeps its `to`. Another applied a paste-ready comment as its judgment row said, and the comment's first line went on stating the old fact. `agents/crafter.md` *A fix pass appends close blocks and writes no phase record* now says that an instruction to apply a paste-ready fix names the fix and does not waive the reading. The fix pass reads the text against what `frame/design.md` and the `frame/plan.md` row of the phase that built the unit say the unit does, and against every input the code hands that unit. A procedure step is still read in either `seal/` root, under every condition its file names, and in the release that ships it. Where the reading fails, the fix pass writes the fix in its own words and says so in `answer:`, as before. `skills/code-review/SKILL.md` *A paste-ready fix reaches every statement of the fact it repairs, or names where it stops* now says that a fix pass that finds the snippet holds applies it as the repair. It no longer says that a fix pass takes the snippet as the repair.
- **A new case that asserts something is not named, counted, read or let through is shown red with only the guard it names removed (#1286).** Such a case passes against old code that does none of those things, so contract rule 15's red against the old code could not show it failing. In #1216's run, one such case went red on a line that named another file, and another stayed green when one of the two guards holding it was removed. Contract rule 15 now asks for a red with the named guard alone removed, and for the failing line to be read for that guard. A case that stays green because a second guard holds it, or that fails on a line naming something else, pins nothing of its guard. `agents/sealer.md` *A `seen red` is re-run against the code before the change* re-runs such a case in its clone with HEAD's code restored and that guard alone removed, and no longer calls its pass at the base "never red". `skills/verify/SKILL.md` *2. Able to fail* and `skills/implement/SKILL.md` *2. Implement test-first, and let each rule name its test* cite rule 15 for such a case.
