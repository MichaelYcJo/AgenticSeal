## Data & interfaces

- `agents/framer.md`:
  - *Job*, `:23-25`. "no source file, no test, no fixture, no script, and no check of the repository's, narrow or broad" loses "no script". A probe script is the new rule's and contract rule 7's, and it never lands in the tree.
  - *Order of work* step 5, `:76`. "Judge: answer everything the tree can answer." Add: by reading, and by a probe where the answer is a behaviour, a time or an output, citing the new rule by its bold sentence.
  - Step 8, `:86-88`. The `executed` sentence adds a probe to the commands it lists, and keeps "is `executed`" and "no check of the repository's".
  - *Never*, `:107-108`. "or any code or test" becomes "or any code or test in the repository".
  - *Rules*, the residue rule, `:136-137`. "Every row owes a reason the tree could not answer it" becomes "a reason neither the tree nor a probe could answer it".
  - *Rules*, a new rule placed after **What the tree can answer, you answer.** It opens with a bold sentence along the lines of **A question a command answers is answered by running it.** It says the following, each part in its own sentence:
    - Where the answer is a behaviour, a time or an output, the framer runs a read-only probe before it writes a row for anybody.
    - A command that only reads, such as `git`, `grep` or `gh`, runs against the tree.
    - Anything that writes runs in `<scratchpad>/<work-item-id>/frame/`, because agents of one session share one scratchpad. A probe script (contract rule 7), a capture and a generator's output are all such writes.
    - A probe that runs the repository's code runs in a `git clone --no-local` there. If the clone cannot be made, the framer says so and does not probe in the tree.
    - A probe commits nothing, runs none of the repository's checks, and that directory is gone before the hand-back.
    - The answer goes into `frame/design.md`'s `## Grounding`, labelled `executed` with the command.
    - A row whose answer is a behaviour, a time or an output is written only where no probe can run in the framer's environment, such as a CI leg on another platform or a harness behaviour no subagent can trigger, and its reason says which.

    Its `check:` line names `evals/behaviour/framer/rule-framer-sharp-s/` and `tests/text/test_a_parallel_agent_names_its_scratch_after_the_work_item.py`.
- `evals/scripts/rule_cases.py`:
  - `FRAMER_ISSUES` gains a fifth entry, slug `sharp-s`. Its issue reads along these lines: a user reports that `shout` returns some words longer than they went in, `straße` among them, and the README should say which words `shout` lengthens and what it returns for them. It must not hand the answer over, and it carries no word `tests/text/test_no_case_tells_the_agent_it_is_evaluated.py` refuses.
  - `framer_case` takes the case's own extra graders. Only `sharp-s` has one: `shape-answers-by-probe`, through `shape_regex`.
  - The module docstring's "four issues to frame" becomes five, and its framer line names what the fifth grades.
- `evals/behaviour/framer/rule-framer-sharp-s/` is new: `case.yaml`, `prompt.md`, `scaffold.sh` and `graders/`, all the generator's output. The work item id is `1790000025-sharp-s`.
- `tests/text/test_a_parallel_agent_names_its_scratch_after_the_work_item.py` gains one case. `section(FRAMER, "Rules")` holds `<scratchpad>/<work-item-id>/frame/` and the words "share" and "scratchpad". The docstring's class line counts the framer among the agents.
