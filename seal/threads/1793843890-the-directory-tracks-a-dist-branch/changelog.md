### Changed

- **The plugin directory's submission form did not answer in time for this repository's whole tree, and answered for the tree without its suites and records; the directory now reads `dist`, a branch the publish workflow adds one commit to at each release, whose tree is `git archive` of the release's tag (#1374).** `.gitattributes` marks `/tests/`, `/evals/`, `/seal/`, `/.test_durations`, `/CLAUDE.md` and `/.github/workflows/` `export-ignore`, and that list of what leaves is the only one. The workflows leave too because GitHub refuses a push made with a workflow's own token that creates or changes a workflow file, and no installed copy runs them. The publish workflow gains a job, `dist`, which runs wherever the `publish` job passed on a tag, a re-run included. Its condition no longer skips it on the `publish` job's failure alone, so it also runs where the note step failed after the tag was made, provided GitHub hands a failed job's outputs to the jobs that need it, which its documentation does not say. Its script, `.github/scripts/dist_branch.py`, builds the commit on `dist`'s tip on `origin`, or as the first commit where `dist` does not exist yet, under the GitHub Actions bot's name. It makes no commit where the tip already holds the tag's archive, and it pushes without force, so a `dist` that moved after its tip was read turns the run red rather than being rewritten. The job has no `continue-on-error`: a release that did not reach `dist` is a red run, and a re-run of the workflow adds the commit. The census that reads cited sections and cited names also reads the files the archive holds, against the archive, so a cited file marked `export-ignore` fails CI. The two readers that built a tag's tree with `git archive`, the `release-report` job's last-tag tree and `evals/scripts/noninferiority.py#extract`, now check the tag's whole tree out, because an archive leaves the marked paths out and exits 0. `.github/scripts/plugin_directory_check.py` reads a marketplace pin against `main` and `origin/dist` and names the ref that holds it. GitHub's source-code archives of each release from this one on leave the marked paths out too. `/plugin marketplace add` still installs from the repository's default branch, `main`, whole.
