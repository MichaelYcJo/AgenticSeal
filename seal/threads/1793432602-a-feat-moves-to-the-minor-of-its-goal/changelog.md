### Changed

- **A planned minor is a category with one goal, and a `feat:` that lands in a milestone numbered as a patch moves to the planned minor whose goal it shares, so one minor is no longer made for each `feat:` (#1205).** A minor milestone's description states the one goal its `feat:`s share, and a patch's description says it builds no `feat:`. Whoever files a `feat:` issue into a patch-numbered milestone, or moves one there, moves it to the planned minor whose goal it shares. The milestones are renamed one step forward only in three cases: no planned minor shares the goal; the work that follows needs the `feat:` before that minor ships, and the renamed milestone's description names that work and says why the minor is too late; or the `feat:` is already squashed onto the patch's branch, where the release pull request's reading counts it even after a revert. The release pull request's refusal now names both repairs, each at the moment it can be made: the move before the squash, and the rename after it. Until a release branch is cut, a planned milestone's name follows its goal, and a regrouping renames milestones back as well as forward. Once a branch is cut, its name is never pulled back, so a minor with no `feat:` still ships under its name, and the release check's line for that case now says this is because the branch was cut under that name.
