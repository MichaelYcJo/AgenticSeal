# Implementation Plan: each form a script does not decide on goes to plain words (#1319)

## Technical context

The work has two parts.

- **The reasons.** The framer has already decided the reason census (design *The reason census*), so phase 1 builds it. The edits fall in `skills/core/SKILL.md`, `skills/agent-contract/SKILL.md` and `docs/running/the-agent-set.md` *One contract every agent receives, and one definition each*, and in any case that pins a sentence that moves or is cut; phase 1 found none, and corrected one docstring that stated a moved reason (`trail/phases/phase-1.md`).
- **The forms.** The form census cannot be decided before it is taken. Its readers alone run to about 11,000 lines: `skills/code-review/scripts/chain_check.py` 2050, `skills/verify/scripts/unverified_check.py` 1938, `skills/settle/scripts/settle.py` 1992, `skills/code-review/scripts/pr_body.py` 785, `skills/settle/scripts/rule_changes.py` 767, `hooks/lib/routing.py` 640, `.github/scripts/rules.py` 550, `hooks/lib/blocks.py` 453 and `hooks/lib/fields.py` 389 (executed: `wc -l`). The broad gate's and the stamp's readers and `evals/scripts/` come on top. So the form census runs in three phases, one per family of readers (design *Scope* items 3 to 5). Each phase takes its family's census and builds what it decides, so one crafter reads a family's readers once.

What the phases build on, by coordinate:

- **The block grammar.** `hooks/lib/fields.py`'s kinds (`ROUND_BLOCK`, `FINDING_BLOCK`, `CLOSE_BLOCK`, `CONFIRMATION_BLOCK`, `VERDICT_BLOCK`, `RUN_BLOCK`) and `#read`, over `hooks/lib/blocks.py#walk`.
- **The pull request check's arms.** `chain_check.py`'s module docstring lists all eight, including `#frame` and `#frame_foot` for the mark, the references check around `:855-900`, and `MARK_RE` and `REFRAME_RE` at `:211-212` at `d4a43c611`.
- **The no-change block's reader.** `unverified_check.py#nothing_block`.
- **The routing reader.** `hooks/lib/routing.py`, which `hooks/routing-edit-gate.py` and `hooks/question-gate.py` read through.
- **The English-only list.** `templates/setup/config.md` *What no row governs*, which a phase corrects where a form leaves a script's reading.
- **The account of what a script gates.** `docs/running/what-a-script-gates.md` *The checks*, whose cells a removed branch takes with it.
- **The precedent.** 5a365e8d9 (#1277): a declaration that still carries a removed row reads as before, and a case holds it (design G10, C1).

How the review chain reads this:

- The proofer reads each phase record's census rows against the design's *The census row* and *The decision rules*.
- It re-runs each phase's enumeration commands (S1) and each D3 or D4 row's `git grep` (S3).
- It reads each D1 row's reader for no change (S4), and re-runs the measurement (S6).
- A disagreement about a decision is a finding on the row. Its fix rewrites the row and the build together.

The failure scenario six months on. The census rows stand in phase records, which leave with this directory at the settle after 0.31.1 and are read at `v0.31.1` after that. A later change adds a form, and nobody re-takes the census, so the new form's reader is never asked for. The core's rule still applies to that form at review, as it did before this work. What the census leaves behind is fewer forms and one place per fact, not a mechanism that keeps the list whole. A check that kept the list whole would be a mechanism with no catch on the day it was added (`skills/core/SKILL.md` *The rule a mechanism is kept against*).

## Operational impact

- **For a deployer:** none. Each form that leaves the templates stays readable in records written before this release (design C1), so a repository's committed records keep passing its pull request check.
- **For the orchestrator:**
  - The suite is `unverified` until its one broad run (contract rule 2).
  - Each phase whose rows reach an eval scaffold or grader names the cases it touched (design C4). The next behaviour comparison of that agent then needs a fresh baseline side, because `regrade` refuses a scaffold change.
  - A phase that edits `seal/follow-up.md`, an eval scaffold or a test docstring that #1346 also reaches names the file in its phase record (design G15).
