### Added

- **The fields a script reads in a round record, `guarantee.md` and `trail/gate.md` stand in `seal` blocks, and one module reads them (#1198).** A `seal` block is a fenced block opened by a line of three backticks and `seal`, with nothing else on the line. Each line inside it is `<key>: <value>`, and the first key names the block's kind. A round record holds a round block with its `target:` line, one finding block under each `### <n>. <symptom>` heading with its `severity:`, `location:` and `evidence:` lines, a close block once the finding is answered, and one confirmation block per `confirms:` line. `guarantee.md` holds one verdict block per run of the sealer, and `trail/gate.md` one run block per green broad run, the newest last in each file. `hooks/lib/fields.py` is the one reader of the blocks and the one spelling of their grammar. Inside a block, a line that is not a field of its kind, a key over its count and a blank line are refused at their line. Outside a block no line is a field, so no reader decides whether a line of prose meant a label. A fence whose info string is `seal` in another spelling, such as `Seal`, is named as not read and changes no exit code. `templates/records/sdd-round.md` and `templates/records/sdd-guarantee.md` hold the blocks. With labelled lines a reader had to sort every line of a record into a label, a near miss or prose, and review rounds chased the edges of that sorting across #1123 and #1132, and in half of #1167's findings.

### Changed

- **`chain_check.py` reads the round records, the guarantee and the gate record through `hooks/lib/fields.py`.** A finding with no close block is open. A finding whose section holds no finding block is refused for lacking it, which includes a finding block written inside the fix's fence. A line shaped like a field outside every block, such as `verdict: fixed abc1234` written as prose, is no field and the check names nothing about it. The check no longer loads the round record's grammar table from `docs/the-review-record.md`, no longer names a line that opens like a label, and keeps no list of retired verdict words: a `Verdict:` value outside its three shapes is refused at its line. The guarantee's `Target SHA` row with its `; earlier run:` chain and the gate record's `Broad gate` cell are no longer read. `record_findings`, `round_of` and `issue_of`, which the release seal and the eval replay call, keep their names and return shapes.
- **`seal gate --record` appends one run block per green run**, below the blocks already in `trail/gate.md`, and appends nothing where the last block names the same run. It writes nothing, and says why, where the file as it would stand holds a line the reader refuses or ends in a run other than this one.
- **`seal pr-body` copies each round's blocks and each finding's heading and blocks verbatim**, and the gate record's run blocks, and `--check` compares the same text.
- **The templates and the instructions say where a field goes.** `agents/proofer.md` has the proofer write the round block and a finding block per finding, with no `verdict:` line, and read the record back through `chain_check.py --worktree`. `agents/crafter.md` has the fix pass append a close block. `agents/sealer.md` has the sealer append a verdict block per run. `skills/code-review/SKILL.md`, `skills/code-review/orchestration.md`, `skills/implement/SKILL.md`, `skills/legacy-parity/SKILL.md`, `skills/verify/orchestration.md` and `skills/writing-style/SKILL.md` say the same. `templates/setup/config.md` *What no row governs* names `hooks/lib/fields.py` as the one spelling of every key and fixed value word, which no `Record language` translates.
- **The proofer's and the sealer's eval graders read the blocks.** The nine proofer `shape-findings.md` graders ask for a finding block under each finding heading, and the five sealer `shape-verdict.md` graders ask for the `Verdict:` line inside a verdict block.
- **Compatibility (#1198).** A work item whose pull request is open across the upgrade to 0.27.0 has its round records refused, with one message naming `templates/records/sdd-round.md`, until they are rewritten into blocks with their verdicts and answers unchanged. Its `guarantee.md` and `trail/gate.md` are refused until the sealer and `seal gate --record` run again, each appending its block below the old text. A released work item's records are not read again, so it is not affected. `docs/the-review-record.md` still describes labelled lines until the settle after this release writes the rule changes this work item's design states; until then `hooks/lib/fields.py` and the two templates are the form. A recorded run of the proofer or the sealer eval suite no longer compares with a run after this release, since their scaffolds and `shape-` graders changed, so the next comparison of either suite runs both sides fresh.

### Fixed

- **The stamp is no longer queued for a guarantee the pull request's check refuses (#1122).** The sealer's write of `guarantee.md` queued the stamp where a `Verdict: sealed` line stood, even where a fence nobody closed below it hid a second `Verdict:` line and the check refused the file. The stamp now reads the guarantee through the reader the check reads it through. It queues nothing where that reader refuses any line of the file, a fence nobody closed and a line beginning `<!--` among them, or where the newest verdict block does not read `Verdict: sealed`. "Drawn once" reads the earlier verdict blocks where it read the `; earlier run:` chain, and a guarantee in the history that holds no verdict block counts nothing.
- **`seal gate` and `seal payload` end a YAML line only where YAML does.** The reader of the hygiene workflow's step names and the reader of an agent definition's `name:` and `skills:` split lines with `str.splitlines`, which also ends a line at U+2028 and seven other characters YAML 1.2 does not, so a step name or a `skills:` entry holding one was cut short. Both now split at LF after universal newlines, as `seal deferrals` does since #1167.
