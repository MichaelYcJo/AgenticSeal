# Phase 1: 1795759277-scripts-read-git-past-submodule-settings-and-a-floor

## What this phase found

**The frame holds for this phase, except at one sentence of `frame/design.md` *Data & interfaces*.** The `lib/gitcmd.py#FLAGS` bullet says the subcommand is the first argument of `argv`, or the first after a leading `-C <directory>` pair, "which is the one global option a caller passes". The tree contradicts it at the commit the framer read. `skills/settle/scripts/settle.py#git_run` (`:480`) and `#git_fields` (`:1534`) pass `--literal-pathspecs` before the subcommand, and the reads `frame/design.md` G4 lists at `settle.py:343`, `:1238`, `:1571` and `:1595` go through those two functions (read). An `argv` built to the sentence would put no flag on any of them. The build reads the subcommand as the first argument that opens with no `-`. `-C` and `-c` before it each take the next argument as their value, as git(1)'s synopsis spells them, and every other option counts as one argument. The case `Test_argv::test_accepts_the_flags_after_the_subcommand_past_the_options_before_it` holds it with the shape `settle.py` passes. The decision is judged against `docs/running/what-a-script-gates.md` *Which gate a script holds*, as `frame/design.md` G1 reads it: the flag goes on each command the setting reshapes.

**How the callers were listed, and what that list is.** `test_tmp_git_calls.py`, a probe in the phase's scratch directory, parses each `.py` file under `lib`, `skills`, `hooks`, `.github/scripts`, `evals/scripts` and `bin` with `ast` and prints each call to a function whose name ends in `git`, with its first three arguments as source text (executed). It prints a subcommand held in a variable, such as `*DIFF` in `range_read.py`, the `*args` of each wrapper and `*verify` in `.github/scripts/plugin_directory_check.py`. `git grep -nE '"--(literal-pathspecs|no-pager|git-dir|work-tree|namespace|bare|no-replace-objects|glob-pathspecs|noglob-pathspecs|icase-pathspecs|no-optional-locks|config-env|exec-path)' -- lib skills hooks .github evals bin` prints `settle.py:480` and `:1534` and nothing else (executed). Both are samples: the probe reads calls by a function's name, and the search reads options by their spelling. The probe also found three `log` reads that `frame/design.md` G4 does not list. They are `.github/scripts/close_issues_on_release.py:362` and `:364`, and `.github/scripts/release_completeness_check.py:135` through `close_issues_on_release.py#run`. Each reaches `lib/gitcmd.py#git` through `#_asked`, so it carries the flag, and the frame's out-of-scope line on `.github/scripts/` covers them. No case was added for them.

**A long option written with its value as a separate argument is read as no value.** A caller that passed `--git-dir <path>` before the subcommand would have `<path>` read as the subcommand and get no flag. The docstring of `lib/gitcmd.py` tells a caller to write such an option in one argument. Neither search above found a caller that passes one.
