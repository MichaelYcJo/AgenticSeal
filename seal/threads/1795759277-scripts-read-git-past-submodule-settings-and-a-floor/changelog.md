### Fixed

- **A submodule's path now stays in every `diff`, `diff-tree`, `log` and `status` read a script makes, whatever the repository's settings say (#1640).** `diff.ignoreSubmodules` in a configuration takes the submodule's path out of what `diff`, `log` and `status` print, `ignore = all` in a submodule's `.gitmodules` entry takes it out of `diff-tree` as well, and no `-c` key reaches the `.gitmodules` entry. `seal range` alone passed `--ignore-submodules=none`. Under the `.gitmodules` entry, `chain_check.py` read a commit that moved only the submodule's pointer as touching no path, so such a commit could stand after the last round, the broad gate or the seal. Under either setting, its listing of a pull request's changed paths read such a pointer as no change to code, and the `git log` listing the sealer types in `agents/sealer.md` step 1 listed such a commit after the broad gate's run with no path, so step 1 did not withhold on it. `lib/gitcmd.py#FLAGS` now holds `--ignore-submodules=none` for `diff`, `diff-tree`, `log` and `status`, and `argv` puts it directly after the subcommand on every command a script starts, past any option a caller writes before it, such as the `--literal-pathspecs` of `seal settle`'s reads. `seal range` passes the flag nowhere itself. The sealer's step 1 types the flag directly after `log`, and withholds on such a commit. `tests/lib/test_gitcmd.py` holds each subcommand under each setting that reshapes it, and a case fails where a subcommand is added to `FLAGS` with no case of its own.
- **The oldest git the plugin's scripts are written for is stated, 2.30, and `seal range` names it where an older git answers (#1642).** `seal range` passes `--end-of-options` to `git rev-parse`, which git learned in 2.30, so an older git refused the command with an error about the commit and nothing named git as the cause. `lib/gitcmd.py#OLDEST` holds the version, and the module's docstring gives the option it comes from and the rule for a later command that needs a newer git. `README.md` and `README.ko.md` state it beside the Python floor, and `tests/behaviour/test_release_hygiene.py` holds both editions to `OLDEST`. `seal range` asks `lib/gitcmd.py#older` before its first git command, and on a git older than 2.30 it prints `seal range: git <version> answers here, and the plugin's scripts need git 2.30 or newer` at exit 2 and writes nothing.
