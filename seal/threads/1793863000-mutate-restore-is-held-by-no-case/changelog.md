### Fixed

- **`seal mutate`'s restore after a baseline that measured nothing is now held by a case on each of its exits, and the `not restored` message no longer calls a file the cases wrote a mutated module (#706).** The command runs the cases against the file as it is before it writes a break. When that run fails, reaches the bound or is interrupted, the command puts back whatever the cases wrote. Only the interrupt of a single pair had a case whose cases wrote the file, so skipping the restore on any of the other five exits left every case green. `tests/skills/test_mutation_check.py` now has `test_what_the_cases_wrote_in_a_baseline_with_no_verdict_is_put_back`, with one parameter for each of those five: `no baseline` and `timed out` for one pair and for a batch, and an interrupt in a batch's baseline. Each parameter's cases write the file during the baseline, and each parameter fails when the restore on its own exit is skipped. The timed-out and interrupt parameters run on POSIX alone. The message `restore` raises, which `seal mutate` prints after `not restored:`, now says that every later verdict would be measured against a file that does not hold the bytes it held before the command started, in place of "a mutated module". The verdict table in `skills/verify/scripts/mutation_check.py`'s docstring, `NotRestored`'s docstring and the exit-2 list in `skills/verify/seal-mutate.md` now say that a file not restored may hold the break or what the cases wrote. The comment on `main`'s interrupt arm no longer says that an interrupt during the baseline wrote nothing. No verdict word and no exit code changes.
