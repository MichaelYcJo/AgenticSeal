**D1. The baseline's restore is held on every exit where the cases ran and ended without a pass, in both shapes.** One pair and a batch each have a no-verdict baseline that ends at `no baseline`, at `timed out`, or at an interrupt. Five of those six paths are held by no case today. Each gets a case whose stand-in writes the target before it ends, and which asserts four things: the stand-in's write happened, the exit is 2, the first line opens with the verdict of that exit, and the target holds the bytes it held before the command. The first assertion reads something the stand-in leaves after its write, such as a line in a log beside the target, so a run that ended before the write cannot pass the case without exercising the restore. Each case is shown red under the mutant that skips the restore on its own path alone, and green under the other four. The one-pair interrupt stays held by the existing `[baseline]` parameter.

**D2. `main`'s interrupt comment states what holds wherever the interrupt lands.** It is reached after `run_cases` ended what it started and after the `finally` of `mutation_run` or `batch_run` put back any bytes that differ. Those bytes are the break, or what the cases wrote, in the baseline as well as in a mutant's run. A restore that fails raises `NotRestored` instead, which is reported above. So the printed sentence, that the file holds the bytes it held before the command started, is true wherever the interrupt lands. "An interrupt during the baseline wrote nothing" goes. The comment cites no round of a work item whose records left the tree and names no commit.

**D3. `not restored` is described as a file that may not hold its first bytes, holding the break or what the cases wrote.** Each of the four statements in the `not restored` class row says that the restore did not land, so the file may hold the break or what the cases wrote, and that it is restored from the commit made before the run. `seal-mutate.md` keeps its action, "restore it from the commit made before the run". The test docstring at `:1110-1113` keeps its own scenario, a mutant left on disk, and drops the claim that this is the one outcome `not restored` says.

**D4. The message `restore` raises says what a later verdict would be measured against, without calling it a mutated module.** At `fe793f03` it is `arm_check.py:836-840`: "`{path} was not restored: {back} != {original_sha}. Every verdict after this point would be measured against a mutated module, so the run stops here.`" `main` prints it inside the `not restored` line. On a baseline exit no module was mutated, and the file holds what the cases wrote, so the clause "a mutated module" is false there. The message keeps "was not restored" and the two hashes, and says a later verdict would be measured against a file that does not hold the bytes it held before the command. `restore`'s docstring states the same reason ("Every verdict taken after a failed restore is measured against a mutated module", at `arm_check.py:828-829`), and it takes the same correction wherever #1393's rewrite leaves it saying so. The printed line changes, so a case pins the new clause, as contract rule 14 asks. The case is shown red with the old sentence put back, as rule 15 asks. The class is listed after the merge by `git grep -n 'mutated module\|not restored\|NotRestored'` over the tree outside `seal/threads/`, each hit read in place, which also reaches a moved test docstring that says the next run would meet a mutated module.

Out of scope:

The mutant-side restore is held as a whole: `test_the_file_is_restored_from_the_bytes_held_before_the_write` has cases that rewrite or remove the mutant, and the batch cases assert the target ends at its first text and that each mutant's run saw that mutant alone (read: `:94-109`).
- **The module docstring's and `seal-mutate.md`'s account of the loop**, "puts the file back from the bytes it read first". It does not say that the baseline's exits restore too, and it says nothing false, so it stays.
- **A text case pinning D3's descriptions.** They are not printed lines (contract rule 14 does not reach a description), and `plan.md` *Alternatives considered* weighs it. D4's message is printed, and *Scope* item 5 pins it.
