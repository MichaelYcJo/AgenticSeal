### Changed

- **The party that fixes reads its own diff and the work item's records whole against HEAD before it hands back (#1318).** Over the 45 work items new at the tags `v0.27.0` to `v0.30.1`, review rounds opened 37 findings as regressions, and 35 of them stood in the fixing party's own diff or in its work item's records. Each was found by a later round, not by the party that fixed. Contract rule 12 now says that the reach of a party's own fix is a closed set: its own diff, and each file of the work item's directory that states the present, each read whole. A list of that set is never a sample. A sample stays one only where the class is open, and what the party did not finish is named as not done. Rule 12 no longer lets a party hand on the rest of a closed list by saying where the open part of a sample stands. For an open class, the hand-back still says where the part its sample did not reach stands, and neither that part nor what the party did not finish is the proofer's share. `agents/crafter.md` *Before you hand back, your range and the work item's records are read whole against HEAD* binds the crafter in a phase and in a fix pass. After its last commit, the crafter reads every hunk of its range's diff with the paragraph or unit around it. It reads `routing.md`, the three frame files, `gaps.md` and `changelog.md` whole. It fixes each statement HEAD contradicts in a file it writes, and names each one in a file it does not write for the orchestrator to fold. Only its search across the tree is a sample, and it calls that list one and says where the part it did not reach stands. The fix-pass paragraph and step 10 cite the rule, and the fix pass's own copy of the search is gone. The crafter's *Job* now gives a fix pass the write to `changelog.md` that `docs/layout/the-record-layout.md` *A commit after the build brings its changelog fragment along* already asked of it. `skills/implement/orchestration.md` *Orchestrator: the order inside a ticket* now has a fold read each frame file or `routing.md` a hand-back names whole against HEAD, not only the line it names. After the fold commit, the orchestrator reads the work item's records whole too, and hands a statement it finds in `gaps.md` or `changelog.md` to a fix pass of the crafter that wrote the last build or fix commit. `skills/code-review/orchestration.md` *Orchestrator: a phase is a fresh crafter, and a fix pass resumes the implementer* says what the fix pass's hand-back carries and cites both homes, and it keeps no copy of the crafter's search.
