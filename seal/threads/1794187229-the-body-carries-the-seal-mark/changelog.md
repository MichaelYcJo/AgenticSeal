### Fixed

- **The pull request's check reads the pull request's body against what `seal pr-body` composes at HEAD, so a body sent before the seal, or one that drifted from the records, fails a ready pull request (#1452).** The six work item pull requests of 0.36.0 opened with the body written before the sealer's verdict, so none carried the seal mark, and no check read the body. `skills/code-review/scripts/chain_check.py` gains a ninth arm, `body`. It reads `pull_request.body` from the event payload it already reads the draft state from, and compares it with the body `seal pr-body` composes for the pull request's one judged work item: `pr.md`, the heading, the seal mark where the `Pull request seal mark` row reads `yes` and the work item is sealed at HEAD, and the records' copy. The comparison is `skills/code-review/scripts/pr_body.py#compared`, the function `seal pr-body --check` now calls too, so the sealer and the pull request read the body by one code path. Each differing line is refused on the work item's directory, naming the body's line and the line the composition gives there, a record's line or a fixed one. A draft prints the refusal and passes. A payload with no body, a run under `--worktree`, and a pull request carrying more than one judged work item holding `pr.md` name the body as not read and decide nothing on it. Under `--sealing`, the broad gate's own run, a difference prints as a notice, because the guarantee the mark stands on is not written yet. In local mode nothing is declared, so the arm reads nothing, and the sealer's `seal pr-body --check` stays the body's reader.
- **A refusal for a run of lines added to or taken out of the body names every line of the run.** `seal pr-body --check` named only the first line of such a run. A body lacking the mark and the blank line under it was refused naming the blank line alone. It now names both, the mark among them, on one `refused:` line.
- **The shipped workflow, `templates/setup/hygiene.yml`, runs on `edited`.** A body edit makes no commit, and the `edited` payload carries the new body, so without the event a body sent after the pull request opened is read only on the next push. `tests/text/test_ci_gives_the_checks_what_they_need.py` requires the event wherever a workflow runs `chain_check.py`.

Updating: a repository that installed `hygiene.yml` from an earlier release runs the arm only once its workflow clones this release or a later one, and reads a body edit only once `types:` lists `edited`. Run `seal pr-checks remove` and then `seal pr-checks install`, or edit the `types:` line and the pinned tag by hand. The arm compares the mark line too, and the mark's address names the plugin version that composed it. So a body written by an installed plugin whose version differs from the release the workflow clones is refused on that line.
