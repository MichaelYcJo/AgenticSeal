### Fixed

- **The plugin's core arrives in every session and every agent, not only in this repository (#1177).** The core is the plugin's first value, efficient development through the workflow, and the rule a mechanism is kept against. It stood in this repository's `CLAUDE.md`, which no session or agent in a plugin user's repository reads. It is now one shipped file, `skills/core/SKILL.md`. Every agent definition lists it in `skills:` before `agent-contract`, so an agent holds it before its first tool call. Every session receives it from the plugin's own `SessionStart` hook, when the session starts, after `/clear` and after a compaction, once each time and never twice. The hook prints the file under a first line naming the file it printed, the plugin's version and the file's SHA-256, about 1,980 tokens at the meter's assumed 3.2 bytes per token. To see which core a session holds, type `! seal core`: it reads that first line back from the session's transcript, and exits 1 unless the core is in context once and whole. `/memory` no longer lists the core, because the hook's output is not a memory file. To turn the core off, disable the plugin's hooks, which turns off its other hooks too. The preset block, `install.sh`, `uninstall.sh` and `/agentic:preset-setup` are gone, and each rule the old block stated stands in the skill or agent definition that applies it. `/agentic:update` from 0.24.x leaves an empty marker pair in `~/.claude/CLAUDE.md`, with `CLAUDE.md.bak` beside it, and the next update takes the pair out. A project's `CLAUDE.md` that still holds a block from `install.sh --project` is named by the update and not edited, so delete the lines between its markers yourself. `seal payload` prints a session's table before the agents' tables, with the hook's output as a row of its own, and no agent's table carries it.
