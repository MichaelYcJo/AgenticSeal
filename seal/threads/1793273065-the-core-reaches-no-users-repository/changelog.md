### Fixed

- **The plugin's core arrives in every agent and every session, not only in this repository (#1177).** The core is the plugin's first value, efficient development through the workflow, and the rule a mechanism is kept against. It stood in this repository's `CLAUDE.md`, which no session or agent in a plugin user's repository reads. It is now one shipped file, `skills/core/SKILL.md`. Every agent definition lists it in `skills:` before `agent-contract`, so an agent holds it before its first tool call. The preset block in `~/.claude/CLAUDE.md` is now one `@` line that imports the core from the marketplace clone, and `/agentic:update` replaces an older block and says that the core arrived. The rules the old block stated (the tool preferences, the three-fix rule, the verification gate and scope, linting before a commit, when to use a worktree, and the routing question) each stand in the skill or agent definition that applies them, and the block states none. `bash install.sh` writes the block to `${CLAUDE_CONFIG_DIR:-~/.claude}/CLAUDE.md`, and warns where the file the line imports is not there. `bash install.sh --project` is gone: from a project's `CLAUDE.md` the import points outside the project, so it waits on an approval dialog and a headless session never loads it. `seal payload` follows the `@` lines of the two `CLAUDE.md` files and counts each imported file, so the core's cost is measured: the share a session in a plugin user's repository reads from `~/.claude/CLAUDE.md` goes from 1,786 B to 6,810 B, about 1,570 tokens more. Where the new block is installed, an agent should read the core twice, about 2,100 tokens per spawn: once through `skills:`, and once through the import, which by #292's measurement reaches every spawn. Both paths stay, because `skills:` is the only one that reaches a user who never ran the installer, and #1183 weighs another carrier.
