### Changed

- **A command of the plugin copied out and run on its own says one sentence about what it lacks (#1482).** Each script under `skills/`, `.github/scripts/` and `evals/scripts/` now reaches the other modules of the plugin through `lib/sibling.py`. Where a file it loads is absent, it prints `cannot read <path>, which this command loads. It ships in the plugin beside this script; a copy of one script taken on its own is not a plugin. Nothing was read.` and exits 2. `<path>` is the absent file's absolute path. A copy of `seal.py`, `settle.py`, `fold_check.py`, `pact_check.py`, `payload_meter.py`, `chain_check.py`, `pr_body.py` or `broad_gate.py` taken alone prints that sentence about `lib/sibling.py` itself, and so do `rules.py` and `release_report.py` when their arguments reach a load. Every other script copied alone ends as it did before, most of them in a traceback. Before, the scripts that reported an absent file each did so in a sentence of their own, naming what the file was for. `chain_check.py`, `pr_body.py` and `broad_gate.py` print the new sentence where they printed a line of their own. Where `seal gate` or the release seal goes on without a module, as each does for the round records' counts, it names the absent file in a line of its own and prints no sentence saying nothing was read. In a whole plugin, no command's output or exit code changes.
- **A lone copy of `settle.py`, `fold_check.py`, `pact_check.py` or `payload_meter.py` run with `--help` exits 2 in that sentence (#1482).** It printed its help at exit 0. A copy without `lib/` can run nothing its help lists, and a bare run of the same copy already exited 2.
