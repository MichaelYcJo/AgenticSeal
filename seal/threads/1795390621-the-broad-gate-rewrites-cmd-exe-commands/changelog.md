### Changed

- **Where the shell is `cmd.exe`, `seal gate` refuses a `Broad gate` command name that starts in a directory with `/`, and no longer rewrites it (#1577).** `cmd.exe` reads a `/` inside a command name as the start of a switch. Handed `bin/test -q`, it runs a command called `bin` and fails before any check has run, and the report reads as the suite failing. The gate used to turn each such `/` into `\` before it handed the command to `cmd.exe`, and said so on stderr and in the kept output. That left the key still wrong in the file, and a model of `cmd.exe`'s reading good enough to repair every value is a second shell inside the gate. Now the gate exits 2 with nothing run, and its message names each refused name with its `\` spelling and gives the key as meant. On `cmd.exe` the key as meant of a key wrapped in backticks or `$(…)`, or ending in a single `&`, turns those names too, so the value any refusal offers is one the gate runs. Every shell is handed the key as written. The gate reads the value up to its first `"`, `^` or `%`, splits that part at blanks and tabs, and takes a word for a command name where it is the first word or follows a word that is exactly `&&`, `||`, `&` or `|`. A name is refused where the part before its first `/` is a directory under the repository root, or on Windows a drive such as `C:`. Where the reading stops early, one line names each word past the stop that it would have refused, and that line decides nothing. A command name `cmd.exe` reads where the reading takes none, such as one behind a leading `@`, is neither refused nor named. Under `/bin/sh`, or a `COMSPEC` naming another shell, nothing changes. `templates/setup/config.md` *Broad gate* states the reading and where it and `cmd.exe` differ, and its refused table and `skills/config/SKILL.md` name the new form.
- **This repository's own `Broad gate` key runs its suite as `uv run --no-project tests/run_tests.py -q` (#1577).** The key named `bin/test -q`, which the gate now refuses on `cmd.exe` because the repository holds `bin/`. The new spelling runs the same suite through the same runner, and names no directory in front of a command. `bin/test` stays the command a contributor types.

Updating: a Windows user whose `Broad gate` key starts a command with a directory and `/`, such as `bin/test -q`, and whose shell is `cmd.exe`, now gets exit 2 from `seal gate` with nothing run. The refusal names the `\` spelling and the key as meant. A key that runs only under `cmd.exe` takes that spelling, such as `bin\test -q`. A key that also runs under `/bin/sh` names its commands with no directory in front, and hands a script's path to an interpreter as an argument, since `/bin/sh` reads `bin\test` as another name. `/agentic:config` is the door to the key. A key whose commands start with no directory, and every key under `/bin/sh`, needs nothing.
