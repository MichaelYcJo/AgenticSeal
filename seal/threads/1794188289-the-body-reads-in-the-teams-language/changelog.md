### Fixed

- **Both language rows of `seal/config.md`, `Commit and pull request language` and `Record language`, are required, and `seal pr-body` refuses to compose a pull request body without either (#1453).** A downstream repository whose team writes its pull requests in Korean had neither row. An absent row read as English and nothing said so, so its records and its pull request bodies came out in English, and every party passed them. `seal pr-body` and `seal pr-body --check` now exit 1 where either row is absent or empty, with one `refused:` line per row that names `seal/config.md`, the row, and the section of `templates/setup/config.md` that says what the row governs. A `config.md` that will not read, and a row written twice, are refused at `seal/config.md` in `lib/config.py`'s sentence. The pull request check's body arm reads the body through the same function, `skills/code-review/scripts/pr_body.py#compared`, so it refuses at `seal/config.md` too. No commit is refused for the rows: a commit in a repository without them is still written in English.
- **First setup and the start of a work item ask for the two rows.** The one question of first setup in `skills/implement/bootstrap.md` step 1 now carries four questions: the mode, the `Broad gate` row and the two language rows. Beside the language questions the orchestrator shows the titles `gh pr list --state all --limit 10` returns and names the language it reads them in, and that language is the first option. Where a repository's `config.md` lacks either row when a work item starts, the questions asked before the first edit carry both rows, and the routing commit writes them. Where nobody is there to answer, the orchestrator writes both rows as the language of the titles, `English` where there are none, and `routing.md` *Why this way* says so in one sentence. `/agentic:config` adds a missing language row as a row alone.
- **Where the two rows name different languages, the pull request body opens in the team's language.** The orchestrator writes `pr.<lang>.md` beside `pr.md` before the first round. It holds each quote of `pr.md` rendered in `Commit and pull request language`, in `pr.md`'s order, each followed by the same coordinate, and nothing else. `seal pr-body` writes it above `pr.md`, so the body opens with that file, then `pr.md`, then the heading and the records' copy. Where the rows differ and the work item holds no file matching `pr.*.md` beside `pr.md`, or more than one, both forms refuse on the work item's directory. `--check` compares the whole first part line by line and names the file each differing line comes from. The rows are compared with case folded, and nothing reads the language code in the file's name. Every round reads `pr.<lang>.md` against the quotes it renders, and the sealer reads it as part of the body's first part. Where the rows name one language, the body opens with `pr.md` as before.
- **The convention no longer links a translated body from the end of the pull request.** `skills/commit-pr-convention/SKILL.md` *Pull request bodies* told the writer to link the translated file from the body, and to keep it out of the git directory so that a reader could open it. `seal pr-body` now copies the file into the body as it copies `pr.md`, so both sentences are gone.

Updating: a repository whose `seal/config.md` lacks either language row is asked for both at its next work item's start. Until both rows are written, `seal pr-body` refuses, and the pull request check's body arm, where the workflow runs this release, fails a ready pull request at `seal/config.md`. `/agentic:config` writes the rows at any time. A repository whose two rows name different languages writes `pr.<lang>.md` for each work item from then on, and a work item already past its first round needs the file written and committed before its body is composed again.
