### Fixed

- **Contract rule 21 asks every agent to write each command so Claude Code's parser can read it (#1445).** A command line the parser cannot read is held for a person to approve, so an automation run stops until someone answers. From 2026-11-03 to 2026-11-09, people answered 21 prompts on Bash calls in the transcripts read, and 19 of them were in two shapes. Ten were an `rm` whose path held a variable, seven of them agents removing what they had made under the scratchpad, mostly file by file in a loop. Nine were a zsh expansion flag such as `${(f)"$(cat list)"}`, which agents used to pass a list of test files to one command. `skills/agent-contract/SKILL.md` rule 21 now asks for plain POSIX syntax that bash and zsh read the same way. Its examples are a list passed as `xargs <runner> < list` or `<runner> $(cat list)`, an `rm` whose path is literal or writes each variable as `"${VAR:?}"`, and a directory removed in one `rm -rf` rather than file by file. The rule says these are examples and not a list, and no check, hook or script reads an agent's command. `tests/text/test_the_agent_contract_holds_the_universal_rules.py` pins two of the forms the parser reads and the zsh form it cannot, inside rule 21's body.
- **The orchestrator follows rule 21 for its own commands.** `skills/implement/orchestration.md` *Orchestrator: the order inside a ticket* step 1 has the orchestrator open contract rule 21 once beside the core, so its commits, the broad run and the removal of its scratch files take the rule's forms. The orchestrator of the 0.36.0 run was asked about an `rm` on a variable path.
- **`skills/update/SKILL.md` step 3 removes its temporary file with `rm -f "${f:?}"`,** in place of `rm -f "$f"`, in the block a session copies to read the release notes.
- **The crafter has a scratch directory of its own, and rule 21's removal never names the scratchpad.** Every agent of a session shares one scratchpad. `agents/framer.md`, `agents/proofer.md` and `agents/sealer.md` each named a directory under `<scratchpad>/<work-item-id>/`, and `agents/crafter.md` named none. In the run that built this change, a crafter wrote its scratch files straight into the scratchpad, read rule 21's "a directory you made is removed in one `rm -rf`" as covering it, and removed the whole scratchpad twice, taking files other agents of the session were still using. `agents/crafter.md` now puts a phase's scratch under `<scratchpad>/<work-item-id>/phase-<n>/` and a fix pass's under `<scratchpad>/<work-item-id>/fix-<n>/`, and has the crafter remove that directory and never the scratchpad. Rule 21's example names the directory under `<scratchpad>/<work-item-id>/` and says the removal never names the scratchpad itself. `tests/text/test_a_parallel_agent_names_its_scratch_after_the_work_item.py` pins both sentences.

Updating: nothing to do. Agents receive rule 21 at their first spawn under 0.37.0.
