### Removed

- **A straight upgrade from a release before 0.23.0 is no longer supported (#1154).** The readings the plugin kept so that a repository, a clone or an install last run under such a release reached the current layout with no step of its own are gone: the session start's move of a `seal/` root an earlier release wrote, with the state files it renamed (`hooks/root-migrate.py`); the bootstrap's paragraphs on a 0.3.x layout and on an earlier release's root; the session start's removal of the git hook stubs releases up to 0.22.3 wrote (`hooks/stub-remove.py`); `/agentic:update`'s removal of the `CLAUDE.md` block under the markers a release before the rename wrote; `seal pr-checks install`'s rewrite of a workflow that clones the repository under its old name; and the README sections *Coming up from 0.3.x* and *Coming from `specseal@specseal`*.

- **Compatibility (#1154).** A person on a release before 0.23.0 takes one of two ways. The first goes through 0.26.0, the last release that carries every reading above: remove the old marketplace with `claude plugin marketplace remove <its name>`, which also uninstalls its plugins; add `MichaelYcJo/AgenticSeal#v0.26.0`, since a GitHub marketplace is pinned to a tag by appending `#<ref>`; install `agentic@agenticseal`; start a session in each clone and commit the move it makes; run `/agentic:update`; then remove the pinned marketplace and add `MichaelYcJo/AgenticSeal` again without the ref. These steps stand on the platform's two documented sentences for `#<ref>` and `marketplace remove`, and nobody has run them end to end. The second way is to move the files by hand to the layout `docs/one-root-by-lifetime.md` describes. Either way, a git hook stub an earlier release left in a clone stays until it is deleted by hand: it is a file under `.git/hooks/` whose second line starts with `# specseal-git-hook`.
