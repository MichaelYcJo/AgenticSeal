# Implementation Plan: 1795742082-a-records-only-fix-is-keyed-on-its-finding

## Technical context

The tree as read at `dee0338af`.

The records arm decides whether the last record's `fixed` findings were read. `skills/code-review/scripts/chain_check.py#records` (`:1468`) hands `#channel` (`:893`) a predicate of two halves: `#located_in_records` (`:988`), every path the finding's and its close's `location:` name lies in the work item's directory, and `#records_only` (`:995`), the `fixed` commit touched that directory alone. Apart from the predicate, `#follows` (`:1003`) refuses every commit after the last record's `target:` that touched a path outside the directory. So the first half is the only thing that tells a records-only pass the sealer reads from one a round reads, and it tells them apart by what the proofer wrote on `location:`.

The form asks the proofer to name "each place the defect shows" (`docs/forms/the-round-record.md:25`). A record sentence that misstates the code shows in the record and in the code, so 240 of this repository's 804 line-form findings name a record and a path outside the records together (`frame/design.md` G9). Most of those are fixed outside the records and owe a round for that. The ones fixed in the records alone, 19 findings in 6 passes that held no other kind of fix (G7, G9), owed a round for the citation.

What those rounds read is measured. The 6 rounds held 4 findings, each a record sentence a records-only fix wrote, the kind the core's row already gives to the sealer where the citation is absent (G8). No round after any of the 19 fixes found a change that the cited path was owed and did not get (G9, G10). The condition's own origin is a constructed case (G5). The sealer withholds over record sentences often, four times over a sentence that a records-only commit wrote and no round had read (G11), and since 0.39.0 it reads such a pass over its diff (`agents/sealer.md:105` to `:122`).

One guard is worth what it costs to keep. A `fixed` commit must touch a named path (`chain_check.py#verdict_problems`, `:1432`), so a records-only commit closes a finding only where the finding block names a record or the fix pass adds one on the close block's `location:`. The second case is the fixer choosing its own reader for a finding the round placed wholly outside the records. No pass in history did it (G9), so keeping the round for it costs no round measured, and `Finding.located` (`:199`) already holds the finding block's paths apart from the close's.

The issue's third proposal meets a gap and not a rule. `agents/proofer.md:141` to `:152` bounds a verifying round by "the diff of the last fixes", and `git diff` across a merge of the base lists the files other work items brought in (G17). `skills/code-review/orchestration.md:293` to `:310` says a round already owed "reads the resolution". What the round does with the rest is unwritten, and the answer follows from rules that stand: other work items' text passed its own seal, the round's records read is against its target as it stands, and the settle writes only the sections its designs name (G18).

The failure scenario of the chosen approach, six months on: a last round's finding names a frame sentence and the code line it misstates, and its paste-ready fix changes both. The fix pass rewrites the sentence and leaves the code line, closes the finding `fixed`, and the check passes it to the sealer. The sealer reads the new sentence against HEAD, finds it true of the code as it stands, and does not weigh that the finding asked for the code to change. The pull request opens with the code line as the round found it. Before this work a verifying round would have answered the close. *Scope* item 3 puts that read in the sealer's step, and *Scope* item 8's row is where the owner reads whether a seal passed one.

## Operational impact

No version move: `.claude-plugin/plugin.json` reads `0.39.2` (`frame/design.md` G21). No migration, environment variable or dependency.

The check refuses less. A repository on an older plugin still owes the round for a records-only fix of a finding that cites code, and stops owing it at its update; no record written under either version is refused by the other for this change. A repository that keeps its own copy of the check, as the owner's comment says owlery does, keeps the old condition until it copies this one.
