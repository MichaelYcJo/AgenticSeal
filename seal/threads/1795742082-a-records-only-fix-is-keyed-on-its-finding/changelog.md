### Fixed

- **A fix pass that touched the work item's records alone no longer owes a verifying round only because its finding also names a path outside the records (#1632).** `skills/code-review/scripts/chain_check.py`'s records arm gave a last `fixed` finding to the sealer only where every path its finding's and its close's `location:` lines named lay in the work item's records. A finding that a record sentence misstates the code names the sentence and the code line, as the round record's form asks, so a fix that rewrote the sentence alone still owed a round. In this repository's round records up to 2026-11-27, 19 such findings were fixed by a commit that touched the records alone, and no round after one found a change the outside path was owed and did not get. The check now reads the finding block's own `location:` and gives the fix to the sealer where one of its paths lies in the records and the commit touched the records alone. A path that only the close block names is not read, so a finding the round placed wholly outside the records still owes the round, whatever the fix pass wrote on its close. The row *No fix that no round reads* of `skills/core/SKILL.md` *Judgment is not licence to skip a party* states the new condition. `agents/sealer.md` step 4 names that row in place of restating it, opens a path outside the records that such a finding names, and withholds where the finding asked for a change there that the fix did not make. `agents/proofer.md` *Rules* gains a rule for a round whose range holds a merge of the base: it reviews the branch's own commits and the merge's resolution, reviews none of what the merge brought in, and holds the work item's diff and records against the merged tree. `docs/checks/the-pull-request-check.md` *What the check reads at the pull request* and `docs/forms/the-round-record.md` *The round record* state the rule from the settle after this release, which writes them from the work item's `## Rule changes`.
