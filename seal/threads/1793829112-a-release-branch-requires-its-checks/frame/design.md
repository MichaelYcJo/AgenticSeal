## Scope

In:

1. **The `release` ruleset requires `lint` and `release`.** The ruleset gains one `required_status_checks` rule: contexts `lint` and `release` from integration 15368, `strict_required_status_checks_policy` `false`, and `do_not_enforce_on_create` `true` (G4, G7, G8). `bypass_actors` stays empty, and the `non_fast_forward` and `pull_request` rules stay as they are. The `main` ruleset does not change. The orchestrator applies this with `gh api` once the review rounds settle and before the broad run, and records the ruleset's JSON before and after in the work item's records (`plan.md` *Operational impact*). It is not a change to the tree.
2. **`docs/releasing/branch-and-release.md` *Work accumulates on a release branch* states the rulesets as configured.**
   - a. The table under **Two rulesets enforce the merge methods.** names each ruleset as `gh api` names it, gives its target, keeps its `allowed_merge_methods`, and gains a column for the checks it requires: `lint` and `release` on both.
   - b. A new paragraph after the table, opening with a bold rule sentence, says the following. Both rulesets require the `lint` job of `.github/workflows/test.yml` and the `release` job of `.github/workflows/hygiene.yml` to pass at the commit that merges. A ruleset with no bypass actor still merges a pull request whose checks are red unless those checks are required. The `pytest` and `arms-grammar` legs are not required, and the reason is given: their check names carry the matrix values, and the chain check already refuses a ready pull request whose suite did not run at HEAD. The `release` ruleset does not hold the checks where a branch is created, because a release branch is cut at a commit of `main` that no pull request's `hygiene` run reported on. Neither ruleset requires a branch to be up to date, for G8's reason. There are no bypass actors and no override; the rule applies to the owner too. A required check that is red is answered by the commit that turns it green. Where the check refused correct work, it is answered by fixing the check, never by passing it. The paragraph also says the settings are outside the tree, that `gh api repos/<owner>/<repo>/rulesets/<id>` reads them, and that no case reads them.
   - c. The sentence "Both rulesets require a pull request, so neither branch takes a direct push, and there are no bypass actors: the rule applies to the owner too." is rewritten so the no-bypass half lives only in the new paragraph (b). The "No workflow can therefore commit the version to a release branch" sentence after it stays.
3. **`docs/releasing/release-checklist.md` *0. Before starting*, the first box, asks only about the jobs no ruleset requires.** The person checks that no check of each work item's pull request was red at the commit that merged, and the box names no job list (G12). The box says the rulesets hold `lint` and `release`, citing `docs/releasing/branch-and-release.md` *Work accumulates on a release branch*. The sentence on a merge pressed while a later push was on its way stays.

Out:

- **Requiring the `pytest` or `arms-grammar` legs, by name or through a new aggregate job.** The names change with the matrix (G4). An aggregate job is a new mechanism with no catch record in the 40 merged pull requests read (G5). `plan.md` *Alternatives considered* rows 3 and 4 hold the grounds.
- **Any change to the `main` ruleset.** It already requires both checks (G3).
- **A check, a test or a workflow step that reads the ruleset** (G10).
- **Any change to `chain_check.py` or to `hygiene.yml`** (G10).
- **`docs/releasing/branch-and-release.md:36` and `:197-198`.** Both stay true (G2).
- **`CLAUDE.md`**, which no longer states the rulesets (G2).
- **Moving `.claude-plugin/plugin.json` to 0.32.1, as a Scope item.** It is not a rule this frame decides. It goes in the commit that adds the changelog fragment of the release's first work item (`docs/releasing/branch-and-release.md` *Cutting a release*). The orchestrator made this item the release's first (`plan.md` *Judgments of the run*), so the move rides in this item's changelog commit and #1301 leaves the version alone.
