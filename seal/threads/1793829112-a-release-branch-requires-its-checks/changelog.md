### Changed

- **A pull request into a release branch could merge with its `release` check red, because the `release` ruleset required no check; it now requires `lint` and `release` at the merging commit, as the `main` ruleset already did (#457).** The ruleset's new rule names the `lint` job of `.github/workflows/test.yml` and the `release` job of `.github/workflows/hygiene.yml`. It does not require a branch to be up to date before it merges, and it does not apply where a release branch is created. The ruleset has no bypass actor, so the rule applies to the owner too. `docs/releasing/branch-and-release.md` *Work accumulates on a release branch* states both rulesets as configured: each ruleset's name and target as the setting holds them, the checks each requires, why the `pytest` and `arms-grammar` jobs are not required, and that `gh api` reads the settings and no case does. The first box of `docs/releasing/release-checklist.md` *0. Before starting* asks a person about the checks no ruleset requires.
