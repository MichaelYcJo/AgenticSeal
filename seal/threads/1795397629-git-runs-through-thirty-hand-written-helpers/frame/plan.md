# Implementation Plan: 1795397629-git-runs-through-thirty-hand-written-helpers

## Technical context

The tree as read at `d0b15b72f`.

**What the runner builds on.** `lib/gitcmd.py` holds `KEYS`, `argv`, `git_path` and `under_root`, and starts no process. Every script that reads it loads it through `lib/sibling.py#load`, at import (`seal.py:194`, `chain_check.py:284`, `unverified_check.py:61`, `close_issues_on_release.py:83`, `publish_release_note.py:122`, `pr_wait.py:137`) or at first use (`broad_gate.py#gitcmd_module`, `seal_stamp.py#_gitcmd`, `rule_changes.py#gitcmd`, `settle.py`'s `sibling.load(GITCMD)` at each call). `lib/console.py` imports `gitcmd` by its plain name (`console.py:80`), so `write_output` can stand there with no new import. The design's *Data & interfaces* gives the surface and what each script reads of an unanswered command; this section gives what the build has to hold while it moves the calls.

**Constraints the build meets.**

- `lib/gitcmd.py` and `lib/console.py` stay Python 3.9 syntax, since the `Stop` hook reaches both (design G6). `tests/censuses.py` *floor_syntax* holds the files the floor table names.
- Each function added to a `lib/` module has its `Test_<name>` class with a `test_accepts_` and a `test_refuses_` case (design G7): `Test_git`, `Test_gh` and `Test_is_ancestor` in `tests/lib/test_gitcmd.py`, `Test_toplevel` in `tests/lib/test_optin.py`, `Test_write_output` in `tests/lib/test_console.py`. `seal layout --check` reads them.
- `gitcmd.git` builds every argv with `argv`, so the `-c` pairs now open every git command a script starts, `git rm`, `git add`, `cat-file --batch` and `archive` among them. A case that asserts an argv equal to `["git", "-C", ...]` or `["git", "rev-parse", ...]`, such as `tests/github/test_release_seal.py:1153`, asserts the new argv or the arguments after `-C <root>`.
- Many cases intercept a call by patching `<module>.subprocess.run` (executed: `git grep -nE "monkeypatch\.setattr\([^)]*subprocess" -- tests`, which lists `test_close_issues_on_release.py`, `test_publish_release_note.py`, `test_release_seal.py`, `test_optin.py`, `test_broad_gate.py`, `test_chain_check.py`, `test_seal.py` and `test_settle.py`). The attribute is the `subprocess` module itself, so a patch still reaches the runner where the module keeps its import. Where a script drops `import subprocess`, its cases patch `gitcmd.subprocess.run` or raise at the runner, and `frame/questions.md` Q2 is how each is decided.
- `tests/skills/test_seal.py#unanswered` (`:277`) raises an outcome for one argv tail and runs every other call for real. It is the seam S1, S2, S4 and S5 are written over, and `TIMED_OUT` (`:105`) is the outcome.
- `tests/skills/test_settle.py#calls` (`:140`) counts the processes whose argv opens with `git`. The runner's argv still opens with `git`, so the count holds.

**The failure scenario of the chosen approach, six months on.** A new script starts git with `subprocess.run` and nothing refuses it, because the rule is read at review and no census holds it (*Alternatives considered*). The cost is one more copy, found by the reader of that diff or by the next audit. A second scenario: a repository far larger than this one makes one read pass `TIMEOUT`. The script then ends with one line naming the command and the bound, and the remedy is one constant in `lib/gitcmd.py`, where today it is one bound per call or none.

## Alternatives considered

| Approach | Failure scenario | Verdict |
|---|---|---|
| A1. ## Operational impact

- No new dependency, environment variable or configuration key.
- What a person sees changes in three places. `seal mode` exits 1 where its stage step did not happen (design S1 to S3). A git or `gh` command past 60 s ends a script with one line, where it ended in a traceback or waited without end. `seal export` says that git did not answer where it said there was no repository (design S5).
- Bounds that move: `lib/optin.py` and `lib/routing.py` from 5 s to 60 s, `seal.py`'s from 15 s and 30 s, `chain_check.py`'s `gh` call from 30 s. `seal stamp --guarantee`'s git reads through `seal_stamp.py#_git`, unbounded at `d0b15b72f`, are bounded; the `Stop` hook runs `seal_stamp.py --stop`, which reads none of them.
- The version does not move in this pull request: the release's first pull request carries the patch version.
