**Decisions settled while writing the code.**

- **The runner's lines.** `Unrun` reads `` `<command>` did not finish within 60 seconds `` past the bound, `` `<command>` could not be run: `<program>` is not on PATH `` where the program is missing, and `` `<command>` could not be run: <error> `` for any other error of the start. `Exited` reads `` `<command>` exited <code>: <first line of stderr> ``, or without the colon where stderr is empty. `<command>` is the program and the arguments the caller passed, joined by spaces. The grounds are design *Data & interfaces* and S9, `frame/questions.md` Q1's spelling `did not finish within 60 s`, and `skills/code-review/scripts/pr_wait.py#gh`'s backticked command. Phase 2's cases for design S1, S2 and S5 pin these lines through `seal`.
- **`FileNotFoundError` names the program only where `shutil.which` cannot find it.** `gh` runs with `cwd=root`, and a `cwd` that is not there raises the same class, so the line says *not on PATH* only where that is true. Judged against design *Data & interfaces*, `Unrun`'s row.
- **`_start` takes the encoding as a parameter.** The first draft passed `encoding` inside `**kwargs`. The `encoding` census of `tests/censuses.py` refuses a `subprocess.run` with a splat and no `encoding=` named. So `subprocess.run` names `encoding=` and `errors=`, which are None where `binary` is true. This follows `CONTRIBUTING.md` *House rules*, **Every file read or written names its encoding** (design G5).
- **`_shown` and `_start` are private**, so they need no `Test_` class (design G7).
- **The `None` stdout stays read in `lib/optin.py`.** The comment that explained the named encoding now stands in `lib/gitcmd.py#_start`'s docstring, and `lib/optin.py#toplevel` keeps `or ""` with a comment of its own. `Test_repo_root::test_refuses_a_reader_that_decoded_nothing_and_answers_empty` and its twin in `Test_git_common_dir` still pin that `None`. I did not move the `None` handling into the runner, because no frame line asks for it (design *Data & interfaces*, `git`'s row).
- **`TIMEOUT` carries the measurement beside it**, design G13's numbers and #1573, so the next reader of the constant sees why it is 60. The comment cites the issue and not the work item's directory, which leaves the tree at the settle.
- **`lib/gitcmd.py`'s docstring states the rule, and not that every script already follows it.** At HEAD the calls phases 2 to 6 move still start git outside the runner. *Scope* item 1 asks for the docstring in this phase, so the docstring cites `docs/running/what-a-script-gates.md` *Which gate a script holds* as the rule, which design `## Rule changes` widens. Design S10's search lists the calls still standing until phase 6.
- **`frame/questions.md` Q2, answered by the work for phase 1.** `lib/optin.py` and `lib/routing.py` no longer import `subprocess`, so the nine patches in `tests/lib/test_optin.py` that set `optin.subprocess.run` now set `optin.gitcmd.subprocess.run`. The new routing case patches `routing.gitcmd.subprocess.run`. Read: each of these attributes is the one `subprocess` module object, so a case that patches `<script>.subprocess.run` in a later phase still reaches the runner, wherever that script's imports end up.
