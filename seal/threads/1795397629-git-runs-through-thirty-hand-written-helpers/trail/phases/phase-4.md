**Decisions settled while writing the code.**

- **What each reader gives for `Failed`.** `chain_check.py#git` keeps `None` for a non-zero exit and lets `Unrun` reach `main`. `commit_of`, `merge_base` and `tree_at` ask through `git`, so they now carry `argv`'s `-c` pairs and the bound, and keep their readings of a non-zero exit. `pull_request_from_gh` reads `Unrun` as `unknown`, with `` no pull-request event payload, and `` and the runner's line, and keeps its own line for a non-zero exit. `pr_wait.py#gh` and `#head` read `Unrun` as `Unanswered`, with `could not ask: ` and the runner's line, and keep their own lines for a non-zero exit, stderr indented below. `Exited` never reaches either script, since neither passes `check=True`.
- **`main` is split as phase 3 split `settle.py#main`.** `main` parses the arguments and sets `WORKTREE`. The rest of the check is `_checked(args)`, called inside `except GITCMD.Failed`, which writes `chain-check: ` and the runner's line on stderr and returns 2. One `try` around the body would re-indent about 200 lines and change nothing they do. `_checked` is private, so it needs no `Test_` class (`CONTRIBUTING.md` *The test layout*).
- **`pr_wait.py` keeps `could not ask: ` before the runner's line.** Exit 2's lines open with `could not ask: ` or `could not read the answer: `, as the module docstring's exit codes say, and the lead names which. It is not a second statement of the failure, which the runner's line states once. Phase 2's `the remote was left out — ` and the runner's line are the same shape. The pin of `could not ask: no `gh` on PATH` moved to the runner's line in the same commit, as rule 14 of the agent contract asks.
- **`head` asks `gitcmd.git(os.curdir, …)`.** The runner needs a root for `-C`, and `-C .` is the directory the old `git rev-parse HEAD` ran in. The runner's line names `git rev-parse HEAD`, since `-C <root>` is not part of the command it shows.
- **`follows` asks `touched`, which passes `--root`.** Every commit `follows` reads there comes after `full` on the branch, so it has a parent, and `--root` changes the listing only of a commit that has none (read: `git help diff-tree`). The local name `touched` that shadowed the function went with the call.
- **The comments that stood on the old reading were rewritten in place.** `carried_by`'s docstring and the comment above `gone` in `main` said `git failing` and `Where git cannot answer`, which now reads as a git that did not answer, and that ends the run. Both now say a git that exits non-zero. The comment above `GITCMD`'s load says it starts every git and `gh` command the check runs. The module docstring's exit codes name a git command that did not answer among the causes of exit 2, and a `gh` that did not answer as an unknown state. `pr_wait.py`'s docstring names `lib/gitcmd.py#TIMEOUT` for each `gh` and `git` call, at `:54` to `:56`.
- **`Test_pull_request_from_gh` is new.** `pull_request_from_gh` had no `Test_` class before this phase, and `seal layout --check` reports, and does not refuse, the functions of `chain_check.py` that have none. It gained an accepting case over the suite's `gh` stubs for a draft and a ready pull request, and a refusing case.
- **`seal layout --pairs` names the new `Test_gh` case beside the two cases of its class**, because all three call `gh` with equal arguments. They differ in the `gh` each case puts on PATH or in the process call it makes time out, which is what each case is about, so the pair is the layout's notice and not a duplicate.
- **`frame/questions.md` Q2, answered by the work for phase 4.** `chain_check.py` and `pr_wait.py` no longer import `subprocess` or `shutil`. `tests/skills/test_chain_check.py#answering` patched `chain.subprocess.run` and now patches the `subprocess` module itself, the one object `lib/gitcmd.py#_start` calls, so it holds wherever the script's imports end up. `test_pr_wait.py` patched neither module.
