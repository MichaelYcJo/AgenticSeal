### Fixed

- **A git or `gh` command that does not answer is no longer read as an answer (#1573).** About thirty hand-written helpers started git and `gh` with their own bounds, from none to 5, 15, 30 and 60 seconds, and several read a command that timed out or could not start as an empty answer: no repository, no origin remote, no branch, or nothing to stage. Every git and `gh` command a script under `lib/`, `skills/`, `.github/scripts/` or `evals/scripts/` starts now runs through `lib/gitcmd.py#git` or `#gh`, under one bound, `lib/gitcmd.py#TIMEOUT`, of 60 seconds. A command past the bound, or a program not on `PATH`, raises `lib/gitcmd.py#Unrun`, whose one line names the command and the bound. A script that does not catch it ends with that line at exit 1, never in a traceback. A non-zero exit is still returned to the caller, because for commands such as `merge-base --is-ancestor`, `diff --quiet` and `config --get` exit 1 is an answer.
- **`seal mode` exits 1 where its stage step did not happen.** Where `git rm -r --cached` or `git add` was refused or gave no answer, `seal mode` printed the step's line and exited 0 with `Now commit.`. It now prints the line with git's or the runner's reason and the command to run by hand, prints no `Now commit.`, and exits 1. `seal pr-checks install` and `remove` exit 1 in the same case.
- **`seal export` says git did not answer where it said there was no repository.** A `git rev-parse --show-toplevel` past the bound printed `not inside a git repository`. It now prints the runner's line and exits 1. A manifest field git gave no answer for is left out with the runner's line, and the zip is still written.
- **`seal settle`, `chain-check`, `seal gate`, `seal pact` and `seal layout` refuse at exit 2 in one line where git gave no answer.** Each wrote a traceback, waited without a bound, or, as `seal pact` did, read the silence as no repository or no origin remote. Each now writes its name and the runner's line and exits 2. `seal gate` and `seal layout --moved` also name the scratch worktree they could not remove, on stderr, and keep the result of the run.
- **`seal stamp --guarantee` refuses at exit 2 where git gave no answer, and queues and records nothing.** Its git reads had no bound. Read as an empty answer, a history git did not print would have queued a stamp for a work item stamped before, and a reach read git did not answer would have recorded a refusal of a commit the branch may hold.
- **`session_cost.py` names a `gh` that gave no answer by the runner's line.** It said `` `gh` is not on PATH `` for a `gh` past the bound. Where it reads the log, posts a comment and reads the comments, it now gives the runner's line.

### Changed

- **The bounds of the git reads in `lib/optin.py` and `lib/routing.py` move from 5 seconds to 60, `seal`'s from 15 and 30 seconds to 60, and `chain-check`'s `gh` call from 30 seconds to 60.** Each is `lib/gitcmd.py#TIMEOUT`.
- **`lib/optin.py#toplevel` gives the repository's top and raises `lib/gitcmd.py#Failed` where git did not answer.** `lib/optin.py#repo_root` keeps its reading of that case as outside any repository. `seal pr-checks`, `chain-check`, `seal gate`, `seal pact` and `seal layout` ask `toplevel`, so a git that did not answer is their refusal and not "not in a git repository".
- **`write_output` moves from `.github/scripts/publish_release_note.py` to `lib/console.py`.** `tag_release.py` loads it from there, and no longer loads another script.
- **The open-coded spellings of a relative path in git's form, `os.path.relpath(...).replace(os.sep, "/")`, ask `lib/gitcmd.py#git_path`.**

### Removed

- **The helpers the runner replaces:** the handlers of a timed-out process in each script, the three `GH_TIMEOUT` constants, `chain_check.py#is_ancestor` and `settle.py#reaches` for `lib/gitcmd.py#is_ancestor`, `broad_gate.py#repo_root`, `unverified_check.py#repo_root` and `test_layout.py#_toplevel` for `lib/optin.py`, `broad_gate.py#branch_name` for `lib/routing.py#current_branch`, and the two copies of `run` in `publish_release_note.py` and `roll_flow_measurement_issue.py`.
- **The two cases that pinned exit 0 for a stage step git refused**, which now pin exit 1.
