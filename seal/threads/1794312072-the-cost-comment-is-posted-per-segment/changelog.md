### Changed

- **The orchestrator posts one cost comment per work item, when its run ends, where it posted one after every crafter or proofer segment (#1479).** The section of `skills/verify/orchestration.md` that every orchestrating session reads is now *Measure the run, and feed the flow log*. When the work item's last segment has handed back, the orchestrator runs `seal cost --work-item <the work item's directory> --post --says <file>`. The file holds its sentence on what the readings say, the run's comparison table and the counts of the frame exchange. The release runs the same command for each work item it ships, and for a work item whose run posted it then posts nothing, unless a segment ran after that comment. 0.37.0's log held 39 segment comments, and each sentence above a fence restated a phase record, a round record or a guarantee.
- **The section says what each exit code of that command means and what the orchestrator does next (#1479).** Exit 0: one comment was posted, or nothing was due, which includes a repository where no issue has ever carried the label. Exit 1: nothing was posted, and the orchestrator names the printed line in the run's hand-over and opens no log, or writes the `--says` sentence again where it was empty. Exit 2: the command line was refused, and the orchestrator corrects it.
- **`seal cost --work-item` prints the Contract rule 6 line for a segment whose own transcript made an `Agent` call (#1479).** Only `seal cost --segments` printed it, and the per-segment run that met it is gone. The line has the shape `--segments` prints for an agent's own file, with no count against unnamed segments, because no parent transcript is in view. A lesson about an agent's conduct, this line or a broken spawn rule, takes the home `skills/implement/orchestration.md` *Orchestrator: where a decision or a lesson is written* gives it, and not a sentence in the cost comment.
- **The meter's messages place the post at a run's end (#1479).** `seal cost --post` prints "posted the run's reading to #N". Where the log has a history and nothing is open, its line ends "Name this in the run's hand-over" and says "two sessions posting at once would both read zero and both create". The Contract rule 6 line's sentence says a reading a person already takes when a run ends is what that leaves.
- **The roll's close comment sends its reader to `docs/running/measuring-a-run.md` *Where a reading goes* for the reasoning behind the two logs (#1479).** The skill's section no longer holds it.
- **The citations of the section name its new heading (#1479):** `README.md`, `README.ko.md`, `skills/code-review/orchestration.md`, `skills/commit-pr-convention/SKILL.md`, `skills/implement/orchestration.md` and `.github/scripts/roll_flow_measurement_issue.py`. The two READMEs say `seal cost` posts when a work item's run ends, where they said it posted each time the crafter or the proofer handed back.

### Removed

- **The section's description of how the meter computes its columns, about 1,800 words (#1479).** `session_cost.py`'s module docstring, its function docstrings and the pages it prints state each fact. The module docstring gained the two that stood in no code text: a `command` share above 100 per cent is calls running at once, and a `--spawns` row much longer than its parts is the orchestrator issuing nothing.
- **The sentences on readings taken before #300, #377 and #642 (#1479).** Git, the release notes and the module's own comments keep them.
- **The section's by-hand lookups, its `--state all` split and its by-hand post (#1479).** The command does each, and the exit codes state each outcome. The section holds 1,352 words, where it held 3,502.

`docs/running/measuring-a-run.md` *Where a reading goes*, `docs/releasing/release-checklist.md` *The release pull request* and `docs/releasing/issues-and-milestones.md` state the per-segment post until the settle after this release writes the rule changes of this work item's `frame/design.md`.
