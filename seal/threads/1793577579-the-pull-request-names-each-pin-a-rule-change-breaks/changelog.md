### Added

- **`chain-check` now names each test pin a design's rule change takes out, and each passage its `to` repeats from another rule document, as a notice at that line of the design (#1216).** A design's `## Rule changes` reaches the policy documents only at the settle after its release. So a test under `tests/` holding a sentence the change rewrites, and a `to` copying a passage another document already holds, met the suite first at that settle, after the pull request that could answer them had merged. The 0.27.1 settle met eleven failing cases and four copies this way (#1214). For each operation of a design the check parses, it now reads the string constants of four words or more in the tracked Python files under `tests/`, docstrings left out. It names each one that the operation's `from` holds and its `to` does not, and for a `remove` with no `from`, each one the section it takes out holds. It names each rule document that an `add` or `change` `to` shares a run of 15 words with, read as `tests/text/test_no_passage_is_pasted_into_a_second_file.py` reads one, in that document as all three kinds of the same design's operations leave it: each `change`'s `from` replaced by its `to`, each text a `remove` takes out removed, and each other `add`'s `to` added. So a passage the design moves from one document to another is no copy, one a `change` keeps in its `to` still is, and one passage two `add`s put into two documents is a copy in each. Each is printed at its line in the design, a notice annotation in CI, and changes no exit code. What the reading could not read is printed as not read: a test file or rule document that cannot be opened, decoded or parsed, a listing of tracked files git could not make, and the section a `remove` with no `from` takes out where the working tree lacks its document or heading. Replayed over the eleven designs of the 0.27.1 settle, the check names 26 pins, every pin the settle removed or repointed among them, and five pairs that hold the four copies it reworded. The proofer now weighs each such notice at review: a named pin of a rule's wording is a finding, and so is a copy another file keeps after the settle, while a pin of a fact a reader acts on is left for the settle to repoint. A finding taken from a notice quotes it, so the settle can count what the notices caught. A run that judges a design with operations reads the tests and the rule documents once. A repository's pull requests meet the new notices once its `hygiene.yml` pins a release that holds them. Internally, the paste check's reader moves to `skills/settle/scripts/passages.py`, which the paste test and `skills/settle/scripts/rule_changes.py` both load, and it tells a heading line through `skills/verify/scripts/unverified_check.py#heading_level`.
