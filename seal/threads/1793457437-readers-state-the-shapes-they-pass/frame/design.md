## Scope

In:

1. R19. One sentence in `templates/setup/seal-README.md`'s paragraph *The first line of this file is the marker*, before `Leave the line as it is.`, and the same sentence in `seal/README.md`, which must stay byte-identical to the template. The sentence says the line is compared whole with only its line end taken off, so a space after it, a byte order mark before it or a blank line above it makes it another line, and the gates then read the root under the git directory where its `README.md` opens with the marker, and read the repository as never opted in where none does (round 1's finding 1, fd549f8e). Two ids, a trailing space and a byte order mark, join the parametrized refusal case in `tests/hooks/test_optin.py`.
2. R30, written for every item. One sentence at the end of `templates/setup/config.md`'s paragraph **This file is optional, and an absent row is not an error, with two exceptions**: an item is named by its row's first cell spelt as this file spells it, case included, and a first cell spelt otherwise, such as `Policy Root`, names no item, so the item reads as absent. One case in `tests/hooks/test_config.py` holds that `config_value` gives `(None, None)` for `Policy root` on a `| Policy Root | … |` row.
3. R41. One sentence in `evals/README.md`, after `Nothing in the tree makes a later edit owe a run.`: `check` reads each of the record's four row counts only from a row with nothing before its first pipe or after its last, one space each side of the name and at least one each side of the value; a row spelt otherwise reads as 0, and so a record edited by hand can pass `check` on a count it never read. A parametrized case in `tests/evals/test_noninferiority.py` *Test_check_record* holds the four shapes read as 0, and a second the value padded with more spaces, which is read (round 1's finding 2, b5a4d754).
4. R27. The rule is the `add` in `## Rule changes`, and the settle writes it. This phase puts the marker `a-release-is-judged-under-its-two-names` on the two cases that already hold it in `tests/github/test_release_completeness_check.py`: the parametrized case asserting `nothing to judge`, and `test_a_milestone_that_does_not_exist_says_it_verified_nothing`.
5. R16. The `change` in `## Rule changes`. Nothing is built for it, because `tests/hooks/test_config.py` shape `C9a` already pins the refusal.

Out:

- R2 and R20. Each reader is gone (*Grounding*), and a limit sentence with no reader is not written.
- R18. The limit already stands in `templates/setup/config.md` *Repository config*, and a second copy in `skills/implement/bootstrap.md` would have no reader who meets the shape there.
- A guard on any reader. The ticket asks for limit sentences, and each shape is one no writer of the one-issue flow produces.
- Any edit under `docs/`. The settle writes the two items in `## Rule changes`.
- `skills/implement/SKILL.md` *Document layout — two roots, three lifetimes* and `templates/setup/config.md` *The fold's values*, the places the ticket named for R19 and R30. Item 1 and item 2 say where each sentence goes instead, and `plan.md` *Alternatives considered* gives the grounds.

- add
  file: docs/issues-and-milestones.md
  section: One thing reads a milestone, and it can stop a release
  to: **The release check judges a release only under the two names the release automation writes: a head branch named `release/vX.Y.Z` and a milestone titled `release: X.Y.Z`.** A head branch named otherwise is judged as nothing: the check prints that it is not a `release/vX.Y.Z` branch and exits 0 before it reads a subject. A milestone of that version under another title is no milestone of the release: the milestone reading prints a warning that it verified nothing and passes, and only the reading of the subjects for a `feat:` can still refuse. So a release branch cut under another name, or a milestone retitled by hand, reaches `main` with nothing compared, and the printed line is its one trace. Whoever cuts the branch or titles the milestone writes those two spellings (`docs/branch-and-release.md` *Work accumulates on a release branch*).
