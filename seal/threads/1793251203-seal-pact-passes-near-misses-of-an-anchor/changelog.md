### Fixed

- **`seal pact` reads a header that means the anchor header as the anchor table, and refuses an anchor row naming a remote the signer does not declare (#1132).** A signer that wrote its anchors under `| pact | clause | hash |` or `| **Pact** | Clause | Hash |`, which a person reads and GitHub renders as the same table, was reported as citing nothing, and so was one whose anchor row named a remote one letter off the pact's. Now a header cell is compared case folded, after one emphasis run wrapping the whole cell is removed, so those tables are graded as the exact one is; nothing else is in that normalisation, and a plural such as `Hashes`, a code span or another word is another table. An anchor row whose `Pact` cell names a remote the signer's `seal/config.md` does not declare is refused at its line. The retired inline token is refused in any case, so `PACT:` and `Pact:` are named as `pact:` was; a token with a space beside the colon, such as `pact: abc`, is not read, because prose writes that spelling too.

### Changed

- **The proofer judges a line meant as a pact anchor that `seal pact` does not read (#1132).** `skills/code-review/SKILL.md` stage 1 asks the proofer, reviewing a signer's work item, to raise a line written as an anchor under a header outside the normalisation, a row with no header, or a row outside the anchor table, as a finding. Whether such a line was meant as an anchor is a judgment of meaning, so no script refuses it.
