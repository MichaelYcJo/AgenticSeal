### Fixed

- **`seal pact` refuses a near miss of a pact anchor instead of reading it as no anchor (#1132).** A signer that wrote its anchors under a header that differed from `| Pact | Clause | Hash |`, such as one in lower case, one reading `Hashes` or one in bold, or that named a remote one letter off the pact's, was reported as citing nothing, and `seal pact` exited on the other signers' anchors alone. Now an anchor row whose `Pact` cell names a remote the signer's `seal/config.md` does not declare is refused at its line, and so is a row outside the anchor table that names a declared remote and a clause, whatever header it stands under. A line of an indented code block is not read as a row. The retired inline token is refused in any case, so `PACT:` and `Pact:` are named as `pact:` was. A token with a space beside the colon, such as `pact: abc`, is not read, because prose writes that spelling too, and a row that misses both the header and the remote is not seen; both are stated as limits.
