### Changed

- **The plugin registers no hook, because the Claude plugin directory refuses every command hook a plugin ships (#1376, #1381).** The directory refused 0.32.5 and 0.32.6 on `LOCAL_CODE_HOOK_COMMAND`, and every hook this plugin registered was a command hook. `hooks/hooks.json`, `hooks/dispatch.py` and every hook script are gone. The question gate, the routing edit gate, the mode gate, the review skill gate, the version check, the Python lint hook, the implementer mark and notice, the session's core hook and the two stamp hooks are removed. `seal no-work-item` and `seal core` are removed with them. Every check that answers exactly stays exact: the suite, the lint, the broad gate and the pull request's check of the four invariants run as before. What a hook held now stands elsewhere:
  - The core reaches a session through the entry skill, `skills/start/SKILL.md`. The model invokes it on a plain request to change code, such as "#1376 하자", and the person can type `/agentic:start`. It opens the core once, puts the routing question every time with the ladder's answer marked recommended, and writes and commits `routing.md` before the first edit.
  - A plain request to review a pull request reaches `agentic:code-review`. The built-in `/code-review` runs only where the person types it by name.
  - Under `Automation` `yes`, the run does not stop on a question the tree or the framer can answer. A blocking question stays for what only the owner can decide and would be costly or outward-facing to undo, and a remark the owner makes mid-run is taken up. This is guidance, not a gate.
  - The sealer withholds where `Implementation` is `crafter` and a phase closed with a Status commit but no phase record.
  - The lint and the version check run in CI and in the broad gate.
- **The terminal stamp is drawn by an opt-in `Stop` hook in the person's own settings.** `seal stamp --install <data-dir> --settings <file>` writes a launcher under the plugin's data directory and one `Stop` entry into the settings file the caller names. First setup and `/agentic:update` ask once where neither the launcher nor a recorded no stands. `seal stamp --remove` takes the entry and the launcher out, `--decline` records a no, and `--hook` says which of the three stands. The sealer queues its stamp once with `seal stamp --guarantee`, and the hook draws it with `seal stamp --stop`. The queue is keyed by the clone, not the session, so the stamp script reads no environment variable. Where two sessions work in one clone, the one whose turn ends first draws every stamp pending there.
- **Two limits are stated in place of mechanisms.** A session that never reaches the entry is outside the workflow and bound by nothing in the core, and nothing checks that a branch declared its routing. In local mode nothing checks the pull request's rows; the sealer's step 1 and the orchestrator's guidance hold them. `README.md` *Shared or local* states the second.
- **`dist` no longer carries the thirteen release-only scripts in `.github/scripts/`.** `.gitattributes` marks them `export-ignore`; the release workflows run them from the tree. `rules.py`, `run_tests.py` and `close_issues_on_release.py` stay, because a shipped command runs or imports each. A new case fails the pull request's CI where a script no shipped command runs reaches the archive.
- **`hooks/lib/` is now `lib/`, and `tests/hooks/` is now `tests/lib/`.** `seal.py#HOOKS` is `seal.py#LIB`. No command-line interface changes with the move.
- **The plugin description drops "without asking anyone", and its keywords drop `hooks`.**

Updating: nothing to do for the hooks, since none is registered. `/agentic:update` asks once whether to draw the terminal stamp. A person who answered no and changes their mind runs `seal stamp --install`.
