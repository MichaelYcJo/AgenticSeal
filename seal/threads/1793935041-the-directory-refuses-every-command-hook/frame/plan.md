**The failure scenario of the chosen approach.** In six months a session that never types `/agentic:start` edits and commits on an undeclared branch, and nothing says so until a person reads the pull request's notice; decision 3 accepts that. A person who updates by `claude plugin update` without `/agentic:update` leaves the launcher naming the old cache directory, which stays on disk, so the old `seal_stamp.py --stop` draws until `seal stamp --install` runs again; `seal stamp --hook` says which root the launcher names. A fourteenth release-only script added to `.github/scripts/` without its `.gitattributes` line reaches `dist` and shows as a finding at the next Validate, which is the direction `.gitattributes`'s own comment chose.

## Operational impact

- **The version.** `.claude-plugin/plugin.json` moves from 0.32.6 to 0.33.0 in the commit that adds this work item's changelog fragment, which is the orchestrator's after the build (`docs/releasing/branch-and-release.md` *The version moves at the start of a release*). This pull request's base is `release/v0.33.0`, so the repository's `hygiene` version step does not run against it; the release pull request into `main` is where it runs.
- **The installed plugin during this run.** The chain runs under 0.32.6's installed hooks and agent definitions. This work item's `routing.md` is committed, so the installed edit gate holds; the installed stamp hooks draw this item's stamp at its guarantee's write, and the installed sealer runs no `seal stamp --guarantee`. 0.33.0 is cut and installed before any work runs under the new shape.
- **What a person does after updating.** Nothing, for the hooks: none is registered. For the stamp: `/agentic:update` asks once, where neither the launcher nor the declined marker stands, whether to draw the stamp, and refreshes the launcher where one stands; a person who declined and changes their mind runs `seal stamp --install`; `seal stamp --remove` takes it out. The owner meets the question at the first `/agentic:update` after 0.33.0. A person who updates by `claude plugin update` alone keeps a launcher naming the old root until the next `/agentic:update`.
- **`dist`.** The thirteen release-only scripts leave `dist` at the next tag through `.gitattributes`; the release workflow keeps running them from the tree. The portal's Validate of the release's `dist` answers the issue's third *Done when* item and the image hold; the owner writes the result on #1376.
- **Milestones after this one.** 0.33.1's paid smoke run measures the installed plugin, so it runs under 0.33.0 with no hook and its comparison with the #51 baseline breaks once; that run's record says so. 0.33.2 (#1401) is unaffected; its milestone description still reads "Order: after 0.32.7", a milestone since renamed, and the owner edits the description.
- **#1381.** Closes with this item: no dispatcher passes on anything. Its second *Done when* item, reading the next `dist`'s validation for `HOOK_GRANTS_PERMISSION`, is answered by the same Validate as #1376's.
- **Compatibility.** A repository whose `.github/workflows/hygiene.yml` pins an earlier release clones that release's tree in CI and keeps working. `seal no-work-item` and `seal core` disappear from `seal --help`; a session typing either gets argparse's refusal.
