### Fixed

- **Every phase boundary and every fix pass runs the repository's tree-wide test files, and a phase no longer pays for test files that only write a changed path's name into a fixture (#1441).** A crafter closing a phase ran the test modules that read a changed path, "whether they name it, import it or glob the directory that holds it". Read as a text search, the glob clause matched every file that writes a records directory into a fixture repository of its own. Every phase writes its own records, so every phase paid for those files: #1421's phase set was 68 modules for a change to one script, its test file and the version. A fix pass ran "what the fix touches", which reached no file that reads the whole tree, so a guard over the records or the documents failed first at the broad gate. `skills/verify/SKILL.md` *Scope: cheap and often, broad and once* now gives the phase boundary four parts in one command: the cases the plan row names, the test files the phase changed, the test files that read a changed path, and the tree-wide test files the repository's contribution guide names. A test file reads a path when its cases open it, import it or load it, directly or through another test file, and a file that writes the path's name only into a fixture, a parameter or a docstring does not. Where a contribution guide names no tree-wide files, the files that glob a changed path's directory stand in for them. A review round's fix pass runs the same set over the paths the fix changed, and `agents/crafter.md` step 9 runs it once the fixes are committed, before the close blocks.
- **This repository's tree-wide test files are `tests/text/` and `tests/behaviour/`, the files that declare no `TARGET`, and every case that walks the repository's own tree or a whole directory of it, lists its tracked files or runs a check over its root stands in one of them.** Fourteen cases left the `TARGET` files of ten modules for five files under `tests/behaviour/`, bodies unchanged: `seal rules`, `seal layout`, `seal fold` and `seal unverified` run over the tree, the routing declarations' parse, the census sweep, the conftest's two walks of `tests/`, the floor's derivation over the tracked files and `bin/`, and the payload and release meters' readings of `agents/` and `docs/`. `CONTRIBUTING.md` *The test layout* says where such a case stands. *What a contribution is asked for* asks a contributor for `bin/test tests/text tests/behaviour -q` beside each module the change touched. *The test layout* also lets a helper two test files share stand in one of them, which the other imports by name, as 28 test files do.
