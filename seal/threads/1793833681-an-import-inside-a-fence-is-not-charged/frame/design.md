## Scope

In:

1. **`imports_of` reads only the live text of a file.** Live text is text outside a fenced code block, an HTML comment and a code span. Every hop is read this way, so an import in an imported file is read the same way as one in the pair. The fences are backtick and tilde fences under the shared rule, `fence_opener` and `fence_closes`. A fence nobody closed hides every line below it, as G3 and CommonMark 4.5 say and as `heading_starts` already reads it. A comment runs from `<!--` to the next `-->`, and one nobody closed hides the rest of the file. A code span runs from a backtick run to the next run of the same length. Where that partner stands on a later line, it must arrive before the paragraph ends, as `_partner_ahead` decides.
2. **One scan says where the live text is.** `unverified_check.py` gains a function that returns the live pieces of each line, as offsets into the line. `liveness` returns what it returns today, read from the same scan, so the scan exists once. The comment at `unverified_check.py:98-117` names `payload_meter.py#imports_of` among the fence rule's readers. `imports_of` runs its pattern over each live piece and over nothing else.
3. **A path continues through a backslash before a space.** The path pattern becomes Claude Code's, `(?:[^\s\\]|\\ )+` after the `@`, and each `\ ` becomes a space in the target. The chain keeps the path as written, as #1177 decided. The rule that a quote or a backtick cannot open a path stays.
4. **Every sentence that states the old reading is rewritten in place, with its pin** (contract rules 14 and 19). This list is a sample by wording; the build runs `git grep` on `@\` line`, `@ lines`, `only under`, `fence rule it splits by` and `imports_of` outside `seal/threads/` at its own HEAD and names what it found:
   - `imports_of`'s docstring and the comment above `IMPORT`. They say what is read, cite G2's two sentences, and name the limits of *Out* below.
   - The module docstring's exit-code paragraph. `unverified_check.py` is now needed by any run that reads a `CLAUDE.md`, not only by `--sections`.
   - `_fence_rule`'s docstring and its stderr sentence. Both name the two uses, splitting a skill at headings and reading the imports of a `CLAUDE.md`. The purpose string and the comment in `Test_module.test_a_script_copied_alone_exits_2_and_names_what_it_misses` move with them.
   - `tests/behaviour/test_release_hygiene.py`'s `VERSIONS_OF_ANOTHER_PRODUCT` gains a row for `skills/verify/scripts/payload_meter.py`, because the rewritten docstring names Claude Code 2.1.318.

Out:

- **The shapes where Claude Code's reader goes past its documentation** (G3). These are an indented code block, an HTML block other than a comment, a path cut at `#`, the rule on a path's first character, an imported file whose extension is not text, a YAML frontmatter block, and an `@` that follows a code span, a comment, emphasis or a link with no whitespace between, which `marked` starts a text token with. Three shapes come from the shared scan itself, which this work does not move (S7), because its fence rule reads each line with no list item or block quote around it. It opens no fence behind `>` or a list marker, so the meter reads an import inside such a fence. A `<!--` that CommonMark reads as text, inside a paragraph that does not hold its `-->` or after a comment closed on its line, hides the text up to the next `-->`, or to the end of the file where none follows. A fence's closing line behind a list marker, where it stands within three spaces of the margin, opens a fence for the meter, and from there the meter's fences stand out of step with the file's until a later fence line happens to bring them back, or the file ends. The meter keeps its reading there, and `imports_of`'s docstring names them as what it does not model. A version-specific reading of the binary is a source the next release can change without notice (`questions.md` Q1).
- **The bytes of an HTML comment in a `CLAUDE.md`.** The docs say block-level comments never reach the context, and `file_row` still counts their bytes. This machine's `~/.claude/CLAUDE.md` holds six lines with `<!--` (executed: `grep -c`). The fix would change what a harness row's bytes mean, which the baseline and the delta read. That is a different question from which files are imported, so this work leaves it, and the pull request body names it for the owner.
- **`tests/behaviour/test_the_old_block_leaves_through_update.py#IMPORT`.** This is a second spelling of the import pattern, in a test. It reads more as an import than the meter does, which is the safe direction for its claim that `CLAUDE.md` imports nothing. It reads a file of the `/agentic:update` area, where #1184 works in this release (`plan.md` *Alternatives considered*, the fourth row).
- The version. The version move to 0.32.2 is #1184's.

## Data & interfaces

- `skills/verify/scripts/unverified_check.py`: a public function, `live_pieces`, returning for each line the `(start, end)` offsets of its live pieces, and a private `_scan` that both it and `liveness` read. Two functions are needed because whether a line begins live cannot be read off its pieces: a fence's opening line and an empty line both begin live and hold no text. `live_pieces` states its contract in its docstring. `liveness(lines, spans_cross_lines, comments=True)` keeps its signature and output, read from the same scan.
- `skills/verify/scripts/payload_meter.py`: `IMPORT`'s path group becomes `((?:[^\s\\]|\\ )+)` behind the existing opener rule. `imports_of(path, home, depth=HOPS, seen=None)` keeps its signature and its `[(chain, real_path)]` return. It reads the file through `gfm_lines` and the new function, and it asks `_fence_rule()` only for a file that exists.
- No JSON field, row name or command line changes, and no exit code is added. Exit 2 is newly reached by a copy that holds `hooks/lib/core.py` and not `unverified_check.py`, given no flag, wherever a `CLAUDE.md` exists (S8).
