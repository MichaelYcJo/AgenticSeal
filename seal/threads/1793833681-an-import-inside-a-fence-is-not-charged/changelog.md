### Fixed

- **`seal payload` charged a `CLAUDE.md` for an import that a fenced code block, an HTML comment or a code span quoted, where the harness loads nothing; it now reads an import in the file's live text alone (#1185).** The memory docs say "Import parsing skips Markdown code spans and fenced code blocks", and the harness strips block-level HTML comments before a file reaches the context. The meter read every `@` in the whole text, so `@a.md` inside a backtick or tilde fence, below a fence nobody closed, inside `` `cat @a.md` `` or inside `<!-- @a.md -->` became a harness row with that file's bytes. Each hop is read the same way, so an imported file that quotes an `@` line inside a fence adds no row either. The meter also follows a path through a backslash before a space, as the docs say, so `@Design\ Docs/api.md` is the file `Design Docs/api.md` and no longer a missing row named `Design\`. The repository's own `CLAUDE.md` holds no such import, so its report does not change. `imports_of`'s docstring names the shapes where Claude Code's reader goes past its documentation, such as an indented code block or a path cut at `#`, as shapes the meter does not model. A copy of the script taken without `unverified_check.py` now stops with exit 2 wherever it reads a `CLAUDE.md` that exists, not only under `--sections`, and its sentence names both uses.
