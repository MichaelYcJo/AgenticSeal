**The constraint.** The installed plugin composes the body one way and the tree's copy another until 0.37.2 is installed (`frame/design.md` G11). *Operational impact* states what follows.

**The failure scenario of the chosen approach.** A team whose two language keys differ reads in its language the sentence that opens each list item of the changelog, and reads the rest of each item, an `Updating:` paragraph among it, in the records' language under the line `HEADING` holds. A fragment whose items open with a sentence that does not state the change gives that team little, and no script can tell, because whether a line renders a sentence is a judgment. The proofer reads each rendering against its coordinate and each list item for its rendering. The second scenario is the body's length: a fragment such as `v0.37.0:seal/threads/1794200906-settings-are-read-as-json/changelog.md` stands whole before the fold, every item, its `Updating:` paragraph and its `### Process changes` table, where that work item's `pr.md` put nine quotes. ## Operational impact

No version move: `.claude-plugin/plugin.json` reads `0.37.2` at `53cab03ea`, moved by #1476. No migration, no environment variable, no dependency.

**In this repository, until 0.37.2 is installed.** The installed plugin is 0.37.1 and composes the changelog inside the fold, while `.github/workflows/hygiene.yml` runs the tree's `chain_check.py` (`frame/design.md` G11). So for this work item, and for every work item whose branch holds this change, the orchestrator writes the body with the tree's `bin/seal pr-body`, run from the work item's checkout, and the sealer's spawn names the tree's `bin/seal pr-body <item> --body <file> --check` as the command of its step 2. The installed `seal pr-body --check` would refuse the tree's body at the changelog's lines, and the sealer would withhold on a correct body. #1452 took the same step for the same reason (`v0.36.0:seal/threads/1794187229-the-body-carries-the-seal-mark/frame/plan.md` *Operational impact*).

**This work item's own `pr.md`** is written under the rule this work states: it quotes no sentence of `changelog.md`. The proofer and the sealer of this run hold the installed definitions, which ask nothing of `pr.md` that such a file fails.

**In a user's repository.** The installed plugin writes the body, and the pull request check runs the tag `hygiene.yml` pins. After the plugin moves to 0.37.2, a workflow pinned to an earlier release composes the changelog inside the fold and refuses each body at those lines. `seal pr-checks remove` and then `seal pr-checks install` pins the workflow to the installed release. A pull request open across the update has its body written again by `seal pr-body` and sent with `gh api -X PATCH`, which is the repair the check's refusal already asks for. The changelog fragment's `Updating:` paragraph says both (*Scope* item 8).

**A repository whose two language keys differ.** From 0.37.2 its `pr.<lang>.md` renders the opening sentence of each list item of `changelog.md` directly, and its `pr.md` quotes none. A `pr.md` and a `pr.<lang>.md` written before the update still compose and still pass the check: nothing reads which record a quote names.
