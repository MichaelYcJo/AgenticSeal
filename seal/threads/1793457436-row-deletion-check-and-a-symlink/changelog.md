### Fixed

- **`seal unverified --baseline` no longer passes a row deleted from a closing memo that a tracked symbolic link points at (#19).** Where a link and its target were both found, the check kept the path that sorted first and compared the base through it. A link sorting before its target, or standing alone under the scanned path, had its own blob read at the base. That blob holds no `## Not verified` section, so the file was listed as not compared, and a deleted row passed with exit 0. The check now keeps each record's real path, the file the link resolves to, and reads both sides of the comparison there, wherever the link sorts and whether or not the target lies under the scanned path. A deletion found through a link is reported under the target's path, where the link's path stood. A closing memo that was a file at the merge base and is a link now held its own rows there, so the check also compares those rows with what the link reads now and reports a loss under the link's own path; where such a link sorted after its target, its rows used to leave with exit 0. A link to a file outside the repository, which no commit holds, is listed under `not compared` with the reason `the file lies outside the repository, so no commit of the repository holds it`, where it read `no ## Not verified section` before; its open rows are still reported.
