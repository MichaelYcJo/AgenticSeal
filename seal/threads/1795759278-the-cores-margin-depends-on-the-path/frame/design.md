## Scope

**In.**

1. **The closing line names its two files relative to the plugin's root, and under a printed core it names that root only where the first line does not.** `lib/core.py#START` holds the two paths as `skills/implement/orchestration.md` and `skills/code-review/SKILL.md`, joined with `/` on every platform, and no slot for a root. One sentence follows it, after one space. Where the core printed is the running plugin's own, the sentence is `Both paths are relative to the plugin's root.`, and the first line's path is the only place the root stands. Where the core printed is another file, a clone's, the sentence is ``Both paths are relative to the running plugin's root, `<root>`.``, with the root absolute. The core at `path` is the plugin's own where `path` and `<plugin_root>/skills/core/SKILL.md` are the same file by `os.path.samefile`, and it is not where that comparison raises `OSError`. Which root the two files stand under does not change.
2. **Where the whole output would reach `CAP`, the hook prints one line that names the core's file and says to open it, above the closing line.** `rendered` returns the whole output where its length is under `CAP`. Otherwise it returns ``AgenticSeal core: printing <path> here would pass the harness's cap of 10,000 characters on a hook's output, so no core was printed. Open that file whole before anything else.``, a newline, and the closing line with the sentence that names the running plugin's root, whichever core it is. The cap's number in the line is formatted from `CAP`. The line opens with `AgenticSeal core:`, as `MISSING` does, and not with `AgenticSeal core from`.
3. **`lib/core.py#ROOT_ROOM` is 100: the length of plugin root at which the tree's whole output is held under `CAP`.** Its comment says what it is, that the default plugin root is the home directory plus the cache path `.claude/plugins/cache/<marketplace>/<plugin>/<version>`, and that a longer root receives the line of item 2. The comment on `CAP` says that a case holds the tree's output under it at a root of `ROOT_ROOM` characters.
4. **`lib/core.py` gains two units that read no file, and `rendered` composes from them.** `closing(plugin_root=None)` returns `START` and its sentence: the plugin's own where `plugin_root` is `None`, and the one naming `plugin_root` otherwise. `whole(text, path, version, plugin_root=None)` returns the header for `path` and `version`, a newline, `text`, a newline, and `closing(plugin_root)`. `rendered(path, plugin_root)` keeps its signature and its `MISSING` line, reads the file and the manifest, and returns `whole(...)` or the output of item 2. The module docstring and the docstring of `rendered` say what the closing line names and what a root past the cap receives, in place of "spelled absolute".
5. **The tree's case measures at a root of `ROOT_ROOM` characters.** `tests/lib/test_core.py#test_the_trees_core_stays_under_the_harness_cap` reads the tree's `skills/core/SKILL.md` and the tree's manifest version, takes the text below the frontmatter, and asserts that `core.whole(text, <root>/skills/core/SKILL.md, version)` is shorter than `core.CAP`, where `<root>` is a string of `core.ROOT_ROOM` characters that names no directory. Its failure message holds the length, `CAP` and `ROOT_ROOM`. It keeps its clause that the text opens with `# The core`. It calls neither `core.origin` nor `core.rendered` on the checkout.
6. **Cases for items 1, 2 and 4**, in `tests/lib/test_core.py` under `Test_rendered` and the groups of the new units: a core at another path prints `closing(<root>)`, which holds the root once; a scratch core long enough that the whole output reaches `CAP` prints the line of item 2 and the closing line naming the root, does not open with `AgenticSeal core from`, and is shorter than `CAP`; a scratch core one character shorter than that prints whole. `tests/lib/test_core.py#test_accepts_the_header_the_body_and_the_closing_line` is rewritten to the relative paths, and holds that the plugin's own core prints the root once, in the first line, above `closing()`. `tests/lib/test_core.py#start_line` goes. `tests/hooks/test_core_start.py#test_accepts_a_session_in_a_clone_of_the_plugin_with_the_clones_core` holds the clone's closing line through `printed`. Each new case is seen red as contract rule 15 states.
7. **Two documents a person reads.** `README.md` *What runs on your machine*, the `SessionStart` bullet, and the same bullet of `README.ko.md`, gain one sentence: where the plugin's root is long enough that the output would pass the harness's limit on a hook's output, the hook prints one line naming the core's file for the session to open, above the same closing line. `CONTRIBUTING.md`, the paragraph that ends "added to the core, which every agent and every session in a repository with a `seal/` root loads", gains the weighing: `tests/lib/test_core.py#test_the_trees_core_stays_under_the_harness_cap` holds the hook's whole output under `lib/core.py#CAP` at a plugin root of `lib/core.py#ROOT_ROOM` characters, so a sentence added to the core fits in what that case leaves or removes as many characters as it adds.
8. **The version moves, and `changelog.md` is written.** The last phase's commit that adds `changelog.md` moves `.claude-plugin/plugin.json` to the version the issue's milestone names, read with `gh issue view 1641 --json milestone`. The fragment's `### Fixed` entry states the measured lengths as measurements of 2026-11-27 and corrects the issue's installed figures by the probe above. It carries no `### Process changes` table: `docs/layout/the-record-layout.md` *A change writes fragments, never a shared file* asks for one where the diff changes the files it lists, and items 1 to 7 change none of them.

9. **`seal payload` says where its hook row counts the line of item 2 and not the core** (round 1, finding 1). `skills/verify/scripts/payload_meter.py#session_composition` passes the measured tree as the plugin root, so in a tree whose root is long enough `core.rendered` returns the line of item 2, and the row's bytes are that line's and the closing line's. The row's count stays what `core.rendered` returned. Where that text opens with `core.TOO_LONG` formatted for the core's path and `core.CAP`, the row carries the key `named`, true. `#_session_lines` reads the key where it writes the hook row's note: a `named` row's note says that the hook prints one line naming the core's file and the closing line where the whole output would reach `lib/core.py#CAP`, that the session opens the core itself, and that the row does not count it. The module docstring's sentence on the core the hook prints and the docstring of `#session_composition` gain the same clause. What `core.rendered` returns for a file that is there is the whole output or the line of item 2, and the key marks the second. The places that read the hook row are `#session_composition`, which builds it, `#_session_lines`, which writes its line and note, and the JSON `seal payload` prints, which carries the row's keys as they are. A case in `tests/skills/test_payload_meter.py` builds a tree whose core makes the whole output reach `CAP`, and holds the key, the row's bytes as those of what `core.rendered` returns, and the note; the existing case of a core that prints whole holds that its row carries no `named` key and keeps its note. The fix pass of round 1 builds this item.

**Out.**

- **The core's own text.** The core below its frontmatter is 9,398 of the 10,000 characters. This work changes what stands around it and how it is measured, and removes no sentence of it. Which sentence leaves to make room is the judgment of the work item that adds one (`frame/plan.md` *Alternatives considered*, A8).
- **Which root a clone's session is sent to.** The closing line keeps naming the running plugin's files (`frame/plan.md` *Alternatives considered*, A4).
- **A second `SessionStart` command for the closing line.** Its premise is not measured (`frame/plan.md` *Alternatives considered*, A5).
- **What `seal payload` counts for the hook row.** It stays `core.rendered` for the measured tree at that tree's path, and no row counts the core a session opens after the line of item 2 (`frame/plan.md` *Alternatives considered*, A12).
- **The three rules that send a session without the core to open it** (*Grounding*, the fifth row). The line of item 2 meets their condition as written.

## Data & interfaces

- `lib/core.py#START`: the two paths are relative, and it holds no slot for a root.
- `lib/core.py#closing(plugin_root=None)` and `lib/core.py#whole(text, path, version, plugin_root=None)`: new, and neither reads a file.
- `lib/core.py#rendered(path, plugin_root)` and `#output(cwd, plugin_root)`: signatures unchanged. `rendered` gains one more return, the output of *Scope* item 2.
- `lib/core.py#ROOT_ROOM`: new, 100. Three new string constants hold the two sentences of *Scope* item 1 and the line of item 2.
- What a session's context holds: the closing line's two paths are relative, and one sentence follows it. A session whose plugin root is too long for the cap receives two lines in place of a cut output.
- `skills/verify/scripts/payload_meter.py`: the session's hook row, in `#session_composition`'s return and in the JSON `seal payload` prints, gains the key `named`, present and true where the row counts the line of *Scope* item 2 and absent otherwise. The session table's note for such a row is a new text.
- `hooks/core-start.py` and `hooks/hooks.json`: unchanged in code and interface; the hook's docstring says what `lib/core.py#rendered` returns past the cap.
