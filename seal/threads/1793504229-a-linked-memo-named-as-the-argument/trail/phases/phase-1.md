## Round 1's fix pass

**What the presence check decides.** It compares two lists: the memos the base holds under an argument, from `ls-tree`, and the memos the scan read. A memo counts as one memo on both lists only where both spell its path the same way. `ls-tree` lists a path through directories only, never through a link. So where a component inside the repository is a link, the base spells the path one of several ways: as named where that link was a directory at the base, and resolved where it was a link there too. Phase 1 gave the base the named spelling alone, and round 1's finding 1 is what that cost. The defect was never one site's: every place that holds a base listing against a tree path needs every spelling of the path.

**`spellings` lists them, and every comparison reads it.** It takes a path in `as_named`'s form and gives the path as named, then the path with the components through each one resolved by `real()`, ending at the real path. Without a link inside the repository it gives one spelling, the one phase 1 gave. The typo check and the presence arm's prefixes read each spelling of every argument. The presence arm's `here` holds each spelling of every scanned memo. The second arm compares each spelling of a scanned memo other than its real one, where the base held a file there, and compares it once however many scanned paths reach it; its line names the spelling compared. Judged against `docs/the-record-layout.md` *The fold, and what tells it from a deletion*: a memo the base held that is still read is no deletion, and one that is not read is.

**Round 1's paste-ready fix was not applied as written.** It reads the base under two spellings, the named path and the real path. That misses the spelling between them. The base lists `specs/OTHER/gaps.md`, which is neither the named `view/OTHER/gaps.md` nor the real `specs/WORK/gaps.md`. The round's prefixes are what `spellings` gives an argument with one link, so its own case passes under either fix.
