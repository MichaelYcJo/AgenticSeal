### Fixed

- **`seal unverified --baseline` no longer passes the rows a closing memo lost when the path a person names is a symbolic link, or passes through one (#1225).** The check resolved every link on a named path before it scanned. A memo replaced by a link to a smaller memo therefore reached the scan as its target's path, and nothing compared the base at the path the person named. Three runs that exited 0 now exit 1 with `<path>:1  2 rows at <base>, 1 here`, the line naming the path as typed: the memo named where it became a link, the memo's directory named where it became a link, and the memo named under a directory that became a link. The check now resolves a named path only up to the repository's top and keeps every part inside the repository as typed. A path reached through a link is compared at that path, where it was a file at the base. A named link to a memo outside every repository used to exit 2 with `--baseline <ref> needs a git repository, and <path> is not in one`, though the link stands in one. It is now compared in the repository that holds the link, and exits 1 where rows left; the target, which no commit holds, is listed under `not compared` with the reason `the file lies outside the repository, so no commit of the repository holds it`. A link inside one repository to a memo in a second repository is still compared against the second repository's base only.
