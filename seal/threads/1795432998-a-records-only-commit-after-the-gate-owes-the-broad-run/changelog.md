### Changed

- **Every statement of the broad run's rule says that the work item's records may follow the run (#1596).** The core's row said the sealer guarantees a tree the `Broad gate` command passed "at HEAD", and one clause of `skills/code-review/gate-to-pull-request.md` could be read either way. So an orchestrator that repaired `pr.md` or `changelog.md` after the gate could read that it owed the whole suite again. The sealer's step 1 and the pull request check's broad gate arm already let a commit that changes only files under `seal/threads/<work-item-id>/` follow the newest run, and they keep their code. The core's row is now *No seal without the broad run* and says so. The row *No pull request without a seal* says that only `trail/gate.md` and `guarantee.md` may follow the guarantee's commit. `skills/code-review/orchestration.md` *Orchestrator: the pull request opens once the sealer seals* states the rule for the orchestrator once: a records-only commit after the run owes `seal pr-body` and the sealer again, and a commit of any other path owes the broad run again. `gate-to-pull-request.md` cites it. `skills/implement/orchestration.md`, `README.md` and `README.ko.md` no longer say "at HEAD" alone.
- **`templates/setup/config.md` *Broad gate* says what a command that reads the records misses (#1596).** A Markdown lint over every `.md` file, or a suite case over `seal/threads/`, reads the records as they stood at the run. The pull request's CI reads the later ones where the repository runs the command there.
- **A case pins the broad gate arm and the guarantee arm on a records-only commit (#1596).** `tests/skills/test_chain_check.py` *Test_broad_gate* commits `pr.md` and `changelog.md` after the run: the broad gate arm refuses nothing, and the guarantee arm asks for the sealer again. A further commit of a path outside the records is refused, naming it.
