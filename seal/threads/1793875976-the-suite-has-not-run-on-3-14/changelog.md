### Added

- **CI runs the whole suite on Python 3.14 as well, on ubuntu, beside the 3.12 floor on every platform (#1065).** Since the `arms-grammar` job left with `seal arms`, no CI job had run a Python newer than the floor. `.github/workflows/test.yml`'s `pytest` matrix gains the entry `{ os: ubuntu-latest, python: "3.14", timeout: 15 }`. It runs `pytest tests/` whole as one job, `pytest (ubuntu-latest, 3.14, 15)`, on every pull request, on every push to `main` and on every dispatched run. It is not a required check. Its first run, 42019408766, passed on CPython 3.14.10 in 1 m 44 s, with 6208 passed and 10 skipped. The 3.12 ubuntu job of the same run skipped 9. The one more skip on 3.14 is `tests/skills/test_mutation_check.py`'s case for compiling a mutant without the script's own future flags: it needs an interpreter on which `from __future__ import annotations` refuses more, and 3.14 is not one. `tests/behaviour/test_the_suite_has_a_command_that_is_cheap_twice.py#test_ci_runs_the_suite_at_the_floor_the_runner_holds` now asks that each operating system the matrix names hold at least one entry at the floor, as `CONTRIBUTING.md` says, in place of every entry being at it. `CONTRIBUTING.md` *Running the checks* names the 3.14 job among the jobs CI runs.

### Changed

- **The release table's `ubuntu` leg would have summed the 3.14 job into the floor's minutes; a job at another Python is now a row of its own (#1065).** `.github/scripts/release_report.py` reads a `pytest` job's operating system and Python from the job's name. The `ubuntu`, `windows` and `macos` rows read only the jobs at the floor that `hooks/lib/launch.py#FLOOR` holds. Each job at another Python is a row `` `<os> <python>` leg (minutes) `` after the three, wherever either job list holds it, ordered by system and then by version. A system other than the three gets a row at the floor as well. On the 0.32.5 release pull request, the `` `ubuntu 3.14` leg (minutes) `` row reads `no run found` at v0.32.4, because that tag's run had no 3.14 job.
