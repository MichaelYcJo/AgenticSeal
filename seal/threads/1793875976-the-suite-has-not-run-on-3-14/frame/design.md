## Scope

In:

1. **`test.yml`'s `pytest` matrix gains one entry, `{ os: ubuntu-latest, python: "3.14", timeout: 15 }`, right after the ubuntu 3.12 entry.** It carries no `split` and no `store`, so it runs the whole suite as one job (G7), on every event the workflow runs on, a pull request into any base among them. Its `timeout` is ubuntu's 15, because the leg runs the same suite on the same system and rule (a) of `questions.md` Q6 of work item 1791270165 bases a budget on the leg's slowest measured job. The comment above the matrix is rewritten in place. Its first paragraph says the whole suite runs at the floor on every platform, and on ubuntu at 3.14 as well, which takes the place of `arms-grammar` (#1065). The "at no newer Python" and "has not been measured" sentences go. The timeout paragraph says the 3.14 leg shares ubuntu's base, and Scope 5 adds its first measured job.
2. **`tests/behaviour/test_the_suite_has_a_command_that_is_cheap_twice.py#test_ci_runs_the_suite_at_the_floor_the_runner_holds` holds `CONTRIBUTING.md`'s claim.** It asserts that every operating system the matrix names has at least one entry at `rt.FLOOR_TEXT`, in place of every entry being at it. Its docstring cites the `CONTRIBUTING.md` sentence it holds, and stops citing a `FLOOR` comment that no longer says it (G8). The case is shown red before it is committed, with one operating system's entries moved off the floor in a copy of the workflow text.
3. **`CONTRIBUTING.md` *Running the checks*, the sentence that opens "CI runs these jobs:", names the 3.14 leg**: the suite runs once more on ubuntu at Python 3.14. The floor's number stays stated once in the section (`#test_the_section_states_the_floor_once`).
4. **`release_report.py` gives a leg at another Python its own row.** A `pytest` job's leg is its operating system and its Python, both read from the job name. The three rows of `LEGS` keep their labels and read only the jobs at the floor, which `hooks/lib/launch.py#FLOOR` holds and which the report loads by path, as `run_tests.py` does. A job at any other Python gets a row `` `<os> <python>` leg (minutes) `` after the three, and appears where either job list holds it. The module docstring's `<leg>` paragraph says so. `tests/github/test_release_report.py` gains a case that is red against the old reading, which summed a 3.14 ubuntu job into the `ubuntu` row. Its existing cases stay as they are.
5. **The first run on 3.14 is observed, recorded, and every red it shows is repaired here.** After phase 2 closes, the orchestrator pushes the branch and dispatches `tests` on it (G10). The phase that follows reads that run's `pytest (ubuntu-latest, 3.14, 15)` job. It writes into its phase record the run id, the commit, the job's conclusion and minutes, the summary line's passed, failed and skipped counts, and each failed or skipped case the job's short summary names. It repairs every red case or module in this work item. A case that pins text an interpreter writes is made to hold the behaviour and not one interpreter's wording. A defect in shipped code is fixed in the code. Where a repair is made, a second dispatched run at the repair's commit is read the same way. The matrix comment's timeout paragraph names the run whose 3.14 job is the leg's first measurement and that job's minutes, so the observation stays in the tree after the work item's directory leaves at the settle.

Out:

- **A 3.13 leg.** `arms-grammar` ran one module on 3.13, and no leg takes that over (`plan.md` *Alternatives considered*, G).
- **3.14 on Windows or macOS** (`plan.md` *Alternatives considered*, F).
- **A 3.15 leg, or 3.15 in place of 3.14.** The owner named 3.14, and `questions.md` Q1 carries the question with its facts.
- **A floating `3.x` leg, a non-blocking leg, a scheduled run** (`plan.md` *Alternatives considered*, C, D, E, H; G3).
- **A required check for the new leg** (G11).
- **A case that requires a 3.14 entry to exist** (`plan.md` *Alternatives considered*, M).
- **The budgets of the other legs.** G6 shows today's jobs well under their `timeout`s. Re-basing them is its own judgment, and this work changes none.
- **`publish-release.yml`'s run of the suite at the tag.** It stays at the floor.
- **The version.** `.claude-plugin/plugin.json` is already 0.32.5 (read, the spawn's fact).

## Data & interfaces

- `test.yml`, `jobs.pytest.strategy.matrix.include`: one entry `{ os: ubuntu-latest, python: "3.14", timeout: 15 }`. GitHub names its job `pytest (ubuntu-latest, 3.14, 15)`, the entry's values in order.
- `release_report.py#leg_minutes`: from `{os: minutes}` to a mapping keyed by the leg. A job at the floor's Python keys as its operating system, as today. A job at another Python keys as `<os> <python>`. `PYTEST_JOB` captures the job name's second value, the Python. `#table` prints the three `LEGS` rows as today, then one row for each other key either job list holds, ordered by `LEGS` and then by version. The exact shape is the crafter's.
- No change to `durations_union.py`, `run_tests.py`, `hooks/lib/launch.py` or `ruff.toml`.

## Removes

The work adds one mechanism, a CI job per run on Python 3.14. What it takes the place of is `arms-grammar`, which #1394 removed: two jobs per run on 3.13 and 3.14 that ran one module, now gone with that module. Its catch record was #684's class, an interpreter-dependent defect found by a user (G4). The new leg covers that class for the whole suite, at one job in place of two (G6).
