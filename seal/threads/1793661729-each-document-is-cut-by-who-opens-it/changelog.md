### Changed

- **The core now states that a document is cut by who opens it and at which step, so a party opens only what its step needs (#1312).** A party pays for every byte of each file it opens, on every spawn that opens it. `skills/core/SKILL.md` *The first value: efficient development through the workflow* gains one paragraph after *Each agent judges its own target*. It says that a form two parties exchange has one home that both cite. Text no agent acts on, such as a hook's edge cases, stands in the code's docstring or in a document only a person opens. A skill's `SKILL.md` holds what every invocation needs and names each supporting file with the step that opens it. Every agent receives the core and the contract, so the new paragraph is paid for in the same preload. The core no longer says who puts the routing question; `skills/implement/orchestration.md` *Orchestrator: how the work is routed* says it, and the hook's refusal names that section. Contract rule 20 retires to one line that cites the core's *The rule a mechanism is kept against*. Contract rule 2 no longer spells the orchestrator's gate command, which `docs/running/the-broad-gate.md` and `skills/verify/orchestration.md` hold. The sealer's step 1 cites `skills/code-review/scripts/chain_check.py#follows` for the rule it applies. Measured as `.github/scripts/release_report.py#preloads` measures it, no agent's preload grows against the base: the crafter's is 122 bytes smaller, the framer's 3, the proofer's 121, the sealer's 383 and the tracer's 127. The framer's margin is 3 bytes, so the next edit that grows the core, the contract or `agents/framer.md` puts it above the base.
- **A work item whose subject is the policy root now edits it directly in its pull request (#1312).** `skills/implement/SKILL.md` *Document layout — two roots, three lifetimes* said the policy root is the baseline and a pull request does not edit it. It now draws the line by subject. A work item whose subject is the policy root itself, its structure or its documents' text, edits the root directly, as the settle does. In the same pull request it re-points every unsettled design's `## Rule changes` operation that names a document or a section it moved. A work item whose subject is the code states the rules its work changes in `## Rule changes`, for the settle, so that work items running side by side do not each rewrite the same section. Which subject a work item has is the framer's judgment, and the proofer reads it at review. No script holds the line. This work item is the first kind, and it edits `docs/` in its own pull request.
- **The policy root is grouped into five directories by who opens each document and at which step, and every policy path changes (#1312).** `docs/README.md` stays at the top and holds one table per group, each under its group's reader sentence. `docs/forms/` holds what two parties exchange: `the-round-record.md` and `the-guarantee.md`, both new, and `the-reader-registry.md`. `docs/running/` holds what the orchestrator opens while it runs a work item, and what an agent's definition sends it to: `the-run.md`, new, with `the-agent-set.md`, `the-review-and-parity-arms.md`, `the-broad-gate.md`, `measuring-a-run.md` and `what-a-script-gates.md`. `docs/releasing/` holds `branch-and-release.md`, `issues-and-milestones.md` and `release-checklist.md`. `docs/checks/` holds what a person changing a hook or a script opens: `the-pull-request-check.md`, `the-stamp.md`, `the-fold.md` and `the-unverified-record.md`, all new, with `the-session-hooks.md` and `the-routing-check.md`. `docs/layout/` holds `one-root-by-lifetime.md`, `one-root-by-lifetime.ko.md`, `the-record-layout.md` and `the-pact.md`. `docs/the-review-record.md` is gone. Its *The round record* is now `docs/forms/the-round-record.md`, its *The guarantee* `docs/forms/the-guarantee.md`, its *What the check reads at the pull request* `docs/checks/the-pull-request-check.md`, its *The stamp* `docs/checks/the-stamp.md`, and its *The run* and *The handoff* `docs/running/the-run.md`. *The fold, and what tells it from a deletion* and *The unverified record, and the baseline it is read against* left `docs/layout/the-record-layout.md` for `docs/checks/the-fold.md` and `docs/checks/the-unverified-record.md`. The fifteen other documents moved into the groups above under their old file names, the record layout without those two sections. The moved text is unchanged except for re-pointed paths, four cross-references that now name the document they point to, and two passages that now cite where their text stands, which the item on such passages below names. `docs/experiments/` stays where it is and is no group. A link to a `docs/` file from outside the repository breaks at this release.
- **`seal fold`, `seal rules --check` and a design's rule changes read one level of group directories in the policy root (#1312).** A `## Rule changes` operation's `file:` may now name `<policy root>/<group>/<name>.md`. A path deeper than one group, or one that names `.` or `..` as a group, is refused at its line with "`<file>` is not a `.md` of `<root>`/ or of one group directory in it". A plugin before this release refuses a design that names a group path, so a repository's designs and its installed plugin move together. `seal fold` reads a directory directly in the policy root as a group once a table row of the index names a document in it as a backticked path. It measures each of that group's documents against the ceiling and holds each to one index row. A directory the index names no document of, such as `docs/experiments/`, is not read, and nothing below a group is read. `seal rules --check` and this repository's release report read the documents `seal fold` lists, from the policy root the configuration names. Where `Policy root` names another directory, `seal rules --check` reads that directory's documents and no longer reads `docs/*.md`. `seal rules --check` also reads every Markdown file beside a skill's `SKILL.md`, so a section moved there keeps its check line read.
- **The settle, implement and verify skills are cut, so a party opens the part its step needs (#1312).** `skills/settle/SKILL.md` keeps what every settle needs. `skills/settle/rule-changes.md` holds the rule-change grammar a framer writes to, `local-mode.md` the local-mode settle, `named-directories.md` the directories a person names, and `draft.md` what `--draft` writes. A framer that follows its citation of the grammar opens 7,564 bytes where it opened 43,170. `skills/implement/SKILL.md` keeps what the crafter and the framer read. The batch of questions for a person, the ladder that decides when a work item is required, and the drain of open rows before the broad run move to `skills/implement/orchestration.md`, each under an `Orchestrator:` heading of its own. A crafter's whole read of `skills/implement/SKILL.md` is 5,257 bytes smaller. `skills/verify/SKILL.md` names `skills/verify/seal-arms.md` and `skills/verify/seal-mutate.md` at condition 2, and each command's section moved there. Each supporting file opens with one sentence naming who opens it and at which step. The settle's ceiling sentence and `seal fold`'s message now say a document past its ceiling is split by who opens each section and at which step, in place of by topic along its own headings.
- **A passage that stood in a policy document and in code or a skill now stands on one side (#1312).** `hooks/question-gate.py`'s docstring is the one place for what the question gate reads and each case it lets through, and `docs/running/the-run.md` *The run* cites it. The seal stamp's rule stands in `docs/checks/the-stamp.md`, and `skills/verify/scripts/seal_stamp.py` and `hooks/sealer-stamp.py` cite it. The guarantee's form stands in `docs/forms/the-guarantee.md`, and `skills/code-review/orchestration.md` and `agents/sealer.md` cite it. *The guarantee*'s opening restated the sealer's job from its definition, and now cites `agents/sealer.md` *Job* for it.
- **The reading after the cut was measured (#1312).** `seal fold` names no policy document past this repository's 25,000-token ceiling; the largest is now `docs/releasing/branch-and-release.md`, about 11,884 estimated tokens, where `docs/the-review-record.md` was about 25,387. The Read calls of 540 past spawns of the crafter, framer, proofer and sealer, from this repository's transcripts, were replayed against the tree before this work and against b1880c1db, the tree once every file this work cuts or moves was cut or moved. Against b1880c1db the replayed bytes fell 6.5% for the crafter, 2.0% for the framer and 10.0% for the sealer, and did not move for the proofer. The commits after b1880c1db reword a few sentences in the READMEs, the cut skills, the record layout and two docstrings, `skills/code-review/scripts/chain_check.py`'s and one test's, and touch no agent definition. Most of the framer's reads of the cut skills read a range of lines, and the same range lands on other text after the cut, so the replay does not say what a spawn under this release reads. The first work item run under this release measures that.
