### Fixed

- **The orchestrator's wait on a pull request's checks now waits for the first check to report (#1222).** `skills/code-review/orchestration.md` told the orchestrator to wait on CI with `gh pr checks <N> --watch` right after a push. Run before any check has reported on the pushed commit, that command does not wait. With gh 2.100.0 it prints `no checks reported on the '<branch>' branch` and exits 1, which is also the exit of a failed check. The orchestrator now polls every ten seconds. It reads the pull request's head with `gh pr view <N> --json headRefOid`, counts the checks of its `pull_request` runs with `gh pr checks <N> --json event`, and runs the wait once the commit it pushed last has such a check. The SHA keeps the wait off the finished checks of the commit before the push. The count keeps it off the finished checks of another event's run on the pushed commit, such as a `push` run, over which `--watch` exits 0 at once. A poll that finds no such check within two minutes is not a pass: under `OPEN` and `MERGEABLE`, the orchestrator's report says that no check of a `pull_request` run reported on that commit and names its SHA, and the pull request is not treated as checked.
