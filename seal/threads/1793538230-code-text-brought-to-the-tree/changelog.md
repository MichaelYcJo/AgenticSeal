### Fixed

- **Three of this repository's release scripts now set their streams the way the console module says every entry point should (#1235).** `hooks/lib/console.py#STREAMS` gives the answer: standard input and standard output in UTF-8 with `replace`, and standard error in UTF-8 with `backslashreplace`. `.github/scripts/release_report.py`, `.github/scripts/release_seal.py` and `.github/scripts/rules.py` set standard error to `replace` and left standard input alone. So a path holding a byte that is not valid text printed in an error message as `?` instead of as its escape, such as `\udcff`. Each script now gives the three pairs as the first statement of its `__main__` block. `release_seal.py`'s `main()` no longer changes the process's streams. Each script keeps its own copy of the loop rather than importing the module, because it loads the repository's modules only when first asked, so a module that will not load ends in the script's own message. A case in `tests/hooks/test_console.py` runs each script's `__main__` with stand-in streams and holds each stream to `STREAMS` as read at run time. The scripts' arguments, exit codes and standard output are unchanged, and none of the three reads standard input. `rules.py` is the script `seal rules` runs.
