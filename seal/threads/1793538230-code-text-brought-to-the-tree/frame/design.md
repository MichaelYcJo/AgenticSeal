## Scope

In:

1. **The three release scripts give the console module's whole answer.** `.github/scripts/release_report.py`, `.github/scripts/release_seal.py` and `.github/scripts/rules.py` each make `stdin` and `stdout` UTF-8 with `replace`, and `stderr` UTF-8 with `backslashreplace`. These are the three pairs `hooks/lib/console.py#STREAMS` holds, in its order. Each keeps its inline loop, corrected, as the first statement of its `if __name__ == "__main__":` block. In `release_seal.py` the loop moves there from `#main`, so `main()` no longer changes the process's streams. A comment above each loop says that `hooks/lib/console.py` owns the answer. It also says why this script spells the loop inline: it loads the tree's modules only when first asked, so that a module that will not load ends in the script's own named result. One case in `tests/hooks/test_console.py` *Test_module* pins the answer, parametrized over the three scripts. It runs each `__main__` in process with `runpy.run_path(<script>, run_name="__main__")`, with stand-in streams for all three, `sys.argv` holding only the script and `TAG` removed from the environment. It then asserts that each stream's `(encoding, errors)` equals `("utf-8", errors)` for each pair of `STREAMS`, read from the module at run time. The class: every entry point with its own loop that differs from `STREAMS` in `stderr`. Listed whole by `79252e48:…/phase-2.md` *Command entry* at `bf9efcba`, these are the three.
2. **`hooks/lib/cmdline.py`'s docstring cites its handler by name and says what it does at the base.** The paragraph opening "There is no load fallback here" cites `hooks/dispatch.py#run_gate`, not `hooks/dispatch.py:72`. It says that the handler skips a gate that raised, so that the tool call goes ahead as if the gate printed nothing, and that the failure is written down and said by the `stop` group once per session. No sentence of the paragraph calls the failure "silence". The paragraph's conclusion, no `try` around the import, stays, and its reason is restated at the base: a `try` that swallowed the import's failure would leave nothing for `run_gate` to write down. The class: a `path:line` in shipped code text that cites the tree's own code. The method is `git grep -nE '[A-Za-z_/.-]+\.(py|md|yml|sh):[0-9]+'` over `hooks/`, `skills/`, `.github/scripts/`, `bin/` and `evals/scripts/`. Executed at `1cdde66f`, it lists `hooks/lib/cmdline.py:28` and `evals/scripts/rule_cases.py:809`. The second is an eval case's fixture text (`src/textutil.py:4`), not the tree's code.

## Data & interfaces

No interface changes. The scripts' arguments, exit codes and stdout text are as they were. What changes is how `stderr` degrades a character UTF-8 cannot encode, a lone surrogate. It prints as its `\uXXXX` escape where it printed as `?`. `stdin` becomes UTF-8 with `replace` in each of the three scripts, and none of them reads it (executed: `grep -n stdin`, 0 lines in the three).
