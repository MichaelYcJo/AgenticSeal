### Fixed

- **The plugin's scripts now read `git log` and `git status` the same whatever git configuration the person or the repository sets (#1283).** A script parses fields out of git's output, and five keys change that output. `log.showSignature` prints a signed commit's verification before its fields. `log.showRoot=false` leaves the root commit's paths out. `log.follow` makes a one-path `log` follow a rename into another path's commits. `i18n.logOutputEncoding` re-encodes subjects into another encoding. `status.showUntrackedFiles=no` leaves untracked paths out of `status --porcelain`. Until now three readers in `seal settle` carried their own flags for two or three of these keys, and every other reader carried none. So under `log.showSignature` the pull request check read each commit's hash with the signature text in front of it, and the release workflow read the signature's words as commits and stopped. Under `status.showUntrackedFiles=no`, `seal gate` printed no hint to commit an untracked `trail/gate.md`. One helper, `hooks/lib/gitcmd.py`, now builds every `git log` and `git status` a script under `hooks/`, `skills/` or `.github/scripts/` starts. It sets each of the five keys to git's default with `-c`, which outranks every configuration file, and its docstring is the one place the keys are listed. The settle's per-reader flags are gone. Where a script is run as a copy without the helper beside it, `seal` and `seal settle` exit 2 naming `hooks/lib/gitcmd.py`. Where a `git` call fails in the release workflows, the command they print now opens with the five `-c` pairs.
- **A work item, changelog fragment or test file whose name is not ASCII is no longer left out of what the scripts list (#1283).** Under git's default `core.quotePath`, git prints such a path inside quotes with its bytes escaped, and six readers split that output on newlines and missed the path. `seal settle` read such a work item as unreleased and put its design last in the merge order with no commit. `seal unverified --baseline` did not list its `gaps.md` at the base, so a closing memo of such a work item deleted whole went unreported. `seal layout --moved` did not list such a test file at the base, so a case that imports from it was reported as changed. The release note left out such a fragment, in CI as well. Each of the six now asks git for its paths with `-z` and splits on NUL, so no path is quoted. A repository's sessions get both fixes once the release that holds them is installed, and its pull request check once its `hygiene.yml` pin moves to that release. The settle after the release writes the rule into `docs/what-a-script-gates.md` *Which gate a script holds*.
