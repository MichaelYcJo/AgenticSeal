### Changed

- **A rename or a move is proved by the cases it already has, and owes no case written new and no `seal mutate` run (#1091).** `skills/verify/SKILL.md` *The narrow command still has to be able to fail* gains a row for a change of names or places only: a unit, file or directory renamed or moved, with its body, signature and output unchanged. The existing cases, run at the new name or path, prove it, with a census showing the old spelling is gone from the files no case imports. The census is an entry in the repository's census of old spellings where it keeps one, and otherwise the search for the old spelling and its empty result in the phase record. A unit whose body, signature or output changes beside its name is still the *Logic* row. The crafter reads that table before it builds a phase. It writes a case first and runs `seal mutate` only for a unit that adds behaviour, and for a unit it only renamed or moved it names the proving cases and the census in the phase record. `skills/implement/SKILL.md` *2. Implement test-first* cites the row. The *Regression test* row of `skills/code-review/SKILL.md` no longer counts a missing new case or mutation run against a rename. A unit that was only renamed or moved claims no `seen red`, so the sealer re-runs the cases the phase record names for it at HEAD as an `executed` claim. A new crafter eval case, `evals/behaviour/crafter/rule-crafter-rename/`, renames `shout` to `exclaim` and fails a run that leaves `shout` in any case or inside a name such as `test_shout`, writes a second test function, or calls `seal mutate`. Against the crafter's definition before this change, both of its runs called `seal mutate` on the renamed unit.
- **The phase-boundary run is one command over the cases the phase's plan row names and the test modules that read a path the phase changed, whether they name it, import it or glob the directory that holds it (#1091).** Contract rule 2 states that set, where it said "your module and the ones it touches". The *Phase boundary* row of the verify skill's *Scope* table and the crafter's step 7 cite rule 2. The crafter's rule on finding the runner no longer says to run one module at a time.
