### Changed

- **The plugin ships two hooks again: a `Stop` hook that draws the sealer's stamp, and a `SessionStart` hook that prints the core where a `seal/` root stands (#1430).** `hooks/hooks.json` registers the two entries and no dispatcher. Each command is `python3 "${CLAUDE_PLUGIN_ROOT}/<script>" || py -3 "${CLAUDE_PLUGIN_ROOT}/<script>"`, so an update moves both hooks with the plugin. Once `python3` has loaded its script, `hooks/core-start.py` exits 0 on every path and `seal_stamp.py --stop` exits 0 whatever drawing the stamp meets. Where `python3` cannot load the script and no `py` stands, the command exits non-zero and prints the error, which does not stop the turn, since only exit 2 does. The `Stop` entry has no matcher and runs `seal_stamp.py --stop` at the end of each turn: it draws each stamp waiting in the clone the session works in, once, and says nothing where none waits. The `SessionStart` entry, matched to `startup|clear|compact`, runs `hooks/core-start.py`. Where the session's repository holds a `seal/` root whose `README.md` opens with the marker, the script prints `skills/core/SKILL.md` below its frontmatter, under the line `AgenticSeal core from <path>, plugin <version>.` and above one line naming where work starts: `skills/implement/orchestration.md` *Orchestrator: the order inside a ticket* for a request to change code, and `skills/code-review/SKILL.md` for a request to review. Anywhere else it prints nothing. In a clone of the plugin it prints the clone's core. The Claude plugin directory refuses a plugin that ships a command hook, and it still refuses `dist` on other findings (#1420), so the owner chose to ship these two until a listing is possible.
- **The stamp's launcher leaves, with its four commands and the two questions that installed it (#1430, #1426).** `seal stamp --install`, `--remove`, `--decline`, `--hook` and `--settings` are gone, and `seal stamp` keeps `--from`, `--shape`, `--guarantee` and `--stop`. First setup no longer asks whether to draw the stamp. `/agentic:update` step 4b asks nothing and writes nothing. Where `${CLAUDE_PLUGIN_DATA}/stamp.py` stands, it names under *Needs action* the `Stop` entry of `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json` whose command runs that file, and then the file, for the person to remove by hand. The line `seal stamp --guarantee` prints now says that the plugin's `Stop` hook draws the stamp at the end of the turn, and that `seal stamp --from <path>` draws it where none appears. The launcher's three defects in #1426 leave with it: a root fixed at install, an install the permission check could refuse, and a silent stop when the old cache directory went.
- **The entry skill `start` leaves, and a plain request to change code reaches `implement` (#1430).** `/agentic:start` is gone. Step 1 of `skills/implement/orchestration.md` *Orchestrator: the order inside a ticket* says the session holds the core from the `SessionStart` hook. Where no output opening `AgenticSeal core from` stands in its context, it opens `skills/core/SKILL.md` once. The orchestrator writes and commits `routing.md` before it edits any other file, and no check refuses an earlier edit. `implement`'s description no longer hands a plain request to `start`, and a session orchestrating a review holds the core the same way. A session that never opened `skills/implement/orchestration.md` edits and commits as it would without the plugin.
- **`seal payload`'s session table counts what the `SessionStart` hook prints**, in the row `SessionStart hook: skills/core/SKILL.md`, in place of the entry skill's row.
- **The plugin's version moves from 0.34.1 to 0.35.0** in `.claude-plugin/plugin.json`.

Updating: nothing to do for the hooks, since `${CLAUDE_PLUGIN_ROOT}` follows the install. A person who said yes to the stamp under 0.33.0 to 0.34.1 runs `/agentic:update` once, and its *Needs action* names the `Stop` entry and `stamp.py` to remove by hand, the entry first. Until both are removed, the old launcher runs beside the plugin's hook, and a stamp is still drawn once, since drawing claims the file first. `/agentic:start` now gets Claude Code's unknown-skill answer; ask for the change in your own words instead.
