### Changed

- **The plugin is AgenticSeal, installed as `agentic@agenticseal` (#1051).** The plugin's `name` and the prefix of every agent and skill is `agentic` (`agentic:implement`, `agentic:crafter`), the marketplace is `agenticseal`, and the repository is `MichaelYcJo/AgenticSeal`. The tagline "Specs, sealed" is gone. README.md, `plugin.json` and both `description` fields of `marketplace.json` say what the plugin is in one sentence: a workflow of agents that frames, builds, inspects and seals a change without asking anyone, and ends in a seal bound to a commit. `marketplace.json` maps the old plugin name to the new one in `renames`.
- **A user installed as `specseal@specseal` registers the marketplace again (#1051).** README.md *Install* gives the three commands: `claude plugin marketplace remove specseal`, `claude plugin marketplace add MichaelYcJo/AgenticSeal` and `claude plugin install agentic@agenticseal`. Then `bash install.sh`, or `/agentic:preset-setup`, puts the CLAUDE.md block under its new markers, replacing the block an earlier release wrote. The update command of the old install runs the old names and cannot carry a user across. The three commands are read from the Claude Code reference and have not been run on a machine that holds the old install.
- **The agents are the framer, the crafter, the proofer, the sealer and the tracer (#1051).** The crafter builds what the smith built, the proofer reviews what the warden reviewed, and the tracer finds the original's facts as the scribe did. Each agent's job is unchanged.
- **A work item lives at `seal/threads/<id>/` (#1051).** The frame is `frame/design.md`, `frame/plan.md` and `frame/questions.md`. What the parties hand each other is `trail/phases/`, `trail/rounds/` and `trail/gate.md`, the one broad run. `routing.md`, `changelog.md`, `guarantee.md` and `gaps.md`, the closing memo, stand at the thread's top. A session start of this release on a branch whose tree still holds `seal/specs/<id>/` moves each one into the new layout as staged `git mv` in shared mode, and as renames under the git directory in local mode, for a person to review and commit with `Seal-Routing: no work item`. A branch cut before the move and checked out after it moves at its own session start.
- **A `seal/` is the plugin's root only where its `README.md` opens with the marker line (#1051).** The marker is `# What AgenticSeal maintains in seal/`, the first line of `templates/seal-README.md`. A project's own `seal/` directory without it is not read as opted in, and first setup writes nothing into one. The migration writes the marker into a root an earlier release wrote.
- **No code of the plugin reads a top-level `specs/` or `.specseal/` (#1051).** A repository still on the 0.3.x layout moves by hand, with the commands README.md *Coming up from 0.3.x* gives.
- **Every tool is a subcommand of `seal` (#1051).** `seal gate`, `seal settle`, `seal cost`, `seal mutate`, `seal unverified`, `seal arms`, `seal deferrals`, `seal fold`, `seal pact`, `seal payload`, `seal stamp`, `seal layout` and `seal rules` run what `broad-gate`, `settle`, `session-cost`, `mutation-check`, `unverified-check`, `arm-check`, `deferral-check`, `fold-check`, `pact-check`, `payload-meter`, `seal-stamp`, `test-layout` and `rules` ran, with the same arguments. Each script's usage line and the prefix of each message it prints name the subcommand.
- **A session's commit ends with `Seal-Routing:` (#1051).** `chain-check` also reads `SpecSeal-Routing:` on a commit made before the rename, and the next minor release removes that reading. A `routing.md` written before the rename that answers `Implementation` with `smith` reads as `crafter` through the same release, so the implementer notice still speaks for a work item in flight, and the next minor release removes that reading too.
- **The state files beside the root carry the plugin's name (#1051).** Each `specseal-` file under the git common directory is `agentic-`, `.git/agentic-scratch` among them, and the state under `~/.claude/specseal/` moves to `~/.claude/agentic/`. Every session start renames each one it meets, in a clone that pulled a tree another person moved too, and never over a file already at its new name.
- **The variables `SPECSEAL_LINT` and `SPECSEAL_LANG` keep their names (#1051).** A person sets them in their own environment, which no migration reaches, and a new name would turn the format hook back on, or the guard's prompts back to the locale, for whoever set the old one.

### Removed

- **The thirteen `bin/` wrappers and their `.cmd` twins (#1051).** `bin/seal`, `bin/seal.cmd`, `bin/test` and `bin/test.cmd` stay.
- **The session-start move of the 0.3.x layout (#1051).** README.md *Coming up from 0.3.x* holds the by-hand commands and says they are the only path.
