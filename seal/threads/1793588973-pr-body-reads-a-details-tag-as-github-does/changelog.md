### Fixed

- **`seal pr-body` now refuses a copied record line that holds a `details` tag anywhere outside a code span, in any case (#1218).** The command copies a work item's records into the pull request body inside one fold, and a record line GitHub reads as a `details` tag opens a second fold or ends that one early. Until now it refused only a line equal to `<details>` or `</details>`. A sentence with `</details>` inside it, an indented `</details>`, `</DETAILS>` and `<details open>` passed, and each broke the fold on GitHub. The command now refuses a line holding `<details` or `</details` in any case, followed by whitespace, `/`, `>` or the line's end, once fences and code spans are blanked. The refusal names the record's path and line and the tag as read, and says to write the tag in a code span, the one spelling that passes. The reading goes by characters, not by GitHub's rendering, so a tag GitHub shows as text is refused too where it stands outside a code span, such as in a table cell or an HTML comment. The command's exit codes and the shape of its `refused:` lines are unchanged.
