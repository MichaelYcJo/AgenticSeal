### Added

- **A `PreToolUse` hook refuses an `AskUserQuestion` call while a work item open in the repository reads `Automation` `yes` (#1608).** Before, the rule for such a run stood in `docs/running/the-run.md` *The run*, and the orchestrator read it when it wrote `routing.md`. Nothing put it in front of the orchestrator when it later called `AskUserQuestion`, and in #1608's run it stopped an unattended run twice with a question the tree could answer. Now `hooks/ask-under-automation.py` runs before each such call. It reads the `routing.md` of each work item whose branch is checked out in a worktree of the session's repository, as `git worktree list --porcelain` lists them, through the new `lib/routing.py#open_declarations`. A work item whose directory stands but whose branch no worktree has checked out does not count, so the directories of released work items, which stay until the settle, refuse nothing. A worktree left on a merged branch keeps its work item open. Where an open work item reads `yes`, the hook refuses the call unless each of its questions holds `No default:` followed on the same line by a reason. The refusal carries the rule's paragraph, read from the plugin's own `docs/running/the-run.md`, the open work items with their branches, each named once, what makes a work item open, and that checking out another branch in that worktree or removing the worktree ends the refusal. It also names the questions that do not state why, and the form that lets the call through. A question that holds the marker with its case changed is named as a spelling the hook did not read. The hook does not judge whether a question is one only the owner can decide. It writes nothing, reaches no network, and prints nothing wherever its input, git or a root cannot be read. A session loads it at its next start after the update.

### Changed

- **`skills/implement/orchestration.md` says what the hook decides on the `Automation` row (#1608).** The paragraph that said `Automation` is a record no script decides anything on now says that the plugin's `PreToolUse` hook puts the paragraph of `docs/running/the-run.md` *The run* in front of the orchestrator at each `AskUserQuestion` call while the row reads `yes`. It says what the hook refuses, what lets a call through, with the marker cited as `hooks/ask-under-automation.py#MARKER`, and that the hook does not judge whether a question is the owner's. The pull request's check still decides nothing on the row, and `lib/routing.py` says the same in its comment on `AUTOMATION` and in `parse`'s docstring.
- **The batch of questions carries each *Done when* line that needs a real session, a credential, an outside service or a permission (#1608).** `skills/implement/orchestration.md` *Orchestrator: what needs a person is asked in one batch, before the first edit* now has the orchestrator read the *Done when* of every issue the request names before it puts the batch. In #1608's run a real-session recording stood in an issue's *Done when* from the start, the batch missed it, and the run stopped for it later.
- **A rule that restricts what agents may do in a run comes only from this run's batch or from a policy document (#1608).** The same section now says so. The orchestrator writes such a rule under `## Why this way` in the work item's `routing.md` with its source, the batch question and its answer or the document's path and section. A spawn prompt carries it only as `routing.md` states it, and a rule a person gave for an earlier run is not carried into this one. In #1608's run the orchestrator carried a rule from an earlier release, that no agent starts a real CLI session, into its spawn prompts, and the framer then named the owner as the answerer of two measurements an agent could have run.
- **The count of the plugin's hooks stands once in each README edition (#1608).** `README.md` *What runs on your machine* and `README.ko.md` *내 컴퓨터에서 도는 것* say the plugin ships three hooks and list the `PreToolUse` hook beside `SessionStart` and `Stop`. Every other place that counted them, in both READMEs, `SECURITY.md`, `CONTRIBUTING.md` *House rules*, `lib/launch.py` and `skills/update/SKILL.md`, says "the plugin's hooks" without a number. The `CONTRIBUTING.md` item is now **The plugin's hooks write nothing outside the repository**, and it says the `PreToolUse` hook refuses a call through the deny it prints, after which the session goes on.
- The version moves to 0.38.8.

`docs/running/the-run.md` *The run*, `docs/running/what-a-script-gates.md` *The checks* and `docs/running/measuring-a-run.md` *Where a reading goes* state the hook, the form it reads and the plugin's hooks without a count from the settle after this release, which writes them from the work item's `## Rule changes`.
