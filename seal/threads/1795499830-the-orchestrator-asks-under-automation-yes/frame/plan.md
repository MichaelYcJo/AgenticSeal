The hook follows `hooks/core-start.py`: a thin script that inserts `lib/` on `sys.path`, reads the payload from stdin, defaults the plugin root to `OWN_ROOT` where `CLAUDE_PLUGIN_ROOT` is unset, reconfigures its three streams in `__main__`, and turns every raise into exit 0 with nothing printed. The failure scenario of the chosen approach, six months on: a work item's branch stays checked out in a worktree after its pull request merges, and every `AskUserQuestion` call in that repository is refused until the orchestrator writes `No default:` or the worktree leaves its branch. The orchestrator then writes the marker by habit, and the hook stops putting the rule in front of it. Nothing counts refusals, so the settle cannot weigh the hook's cost from a record. Each refusal names the work item and branch that caused it, which tells the person what to switch or remove.

- **Platforms.** The hook's `py -3` half and the hook on Windows are not run, as for the other hooks (`README.md` *Windows was run on real hardware once*). The pull request names it.
