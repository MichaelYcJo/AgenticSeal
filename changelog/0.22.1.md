### Removed

- **The `Reads:` census and the rider stamps are gone (#964).** No pull
  request is refused any more for a unit with no `Reads:` docstring line or
  for a `RIDER:` comment whose stamp has drifted, and
  `rider_check.py --reverify` no longer exists. A `RIDER:` comment stays a
  comment, with no stamp and no checker. There is nothing to do: a `Reads:`
  line or a stamp left in your own files is read by nothing.
  (`1792129100-the-mechanics-leave-before-the-agents-are-rewritten`, #964)

### Changed

- **The round record's grammar is one table, and a line is accepted only
  where it matches its row whole (#964).** `docs/the-review-record.md`
  §*The round record* holds one row per line kind of a
  `rounds/round-N.md`, and `chain_check.py` loads that table and reads nothing
  else for the grammar. `templates/config.md` points at the table instead
  of listing the labels, and `templates/sdd-round.md` keeps what each label
  means and leaves its shape to the table. Two things are now refused that
  passed before: a finding with no `severity:` line, with two, or with one
  whose value is not `must` or `should`, and a finding with no `answer:`
  line or with two.
  A round record in flight that lacks either line adds it before it meets
  this release's check. Where the table itself cannot be read, because the
  document is missing, a row will not parse, or a row the check reads a
  meaning from stands where the check does not look for it or has a
  `How many` the check cannot keep, `chain_check.py` stops with exit 2
  naming the file, never a pass.
  (`1792129100-the-mechanics-leave-before-the-agents-are-rewritten`, #964)
- **A `## Not verified` row is closed by the word `closed` (#964).** The
  row's Item cell opens with `closed`, lower case, then the item, and the
  second cell says what closed it:
  `| closed how the gates render in a TUI | seen on screen, 2026-08-25 |`.
  `unverified-check` refuses a row that opens with the old check-mark
  emoji, naming the row and the edit to make. It also refuses a bare
  `closed` with nothing after it, and `Closed` or `closed:`, which would
  otherwise read as open. The hygiene step reads every `overview.md` under
  `seal/specs/`, released or in flight, until `settle` retires its
  directory. So before you move your `hygiene.yml` pin to this release,
  rewrite every closed row that still opens with the old mark to open with
  the word, in each of them. A base revision still reads the old mark as
  closed, so `--baseline` keeps comparing every base written before the
  word. An open item whose own text begins with the word `closed` reads as
  closed, and nothing refuses it, so word such an item to open with another
  word. The overview template, `templates/config.md` and the implement,
  verify and settle skills show the word.
  (`1792129100-the-mechanics-leave-before-the-agents-are-rewritten`, #964)

### Changed

- **The stamp is the sealer's, and it is drawn once per work item, at the
  commit of a `guarantee.md` reading `sealed` (#975).** Before this, the
  broad gate drew a stamp when its run went green, before the sealer had read
  anything, so a passing suite looked like finished work. Now git's
  `post-commit` reads the committed `guarantee.md`. Where its `Verdict:`
  reads `sealed`, it writes the stamp's values for your session and prints
  one line: ``specseal: the stamp for <id> is drawn at the end of this turn
  from <path>; where none appears, `seal-stamp --from <path>` draws it``. The
  `Stop` hook draws it after the turn's text, as before. `withheld` and
  `undecided` draw nothing. A re-seal after `withheld` draws the stamp then,
  and a work item that was already stamped draws nothing more, whatever
  commit the new verdict names. That holds in another clone of the same
  branch too, since its history shows the guarantee already read `sealed`.
  It does not hold where another clone, one that never wrote this work
  item's stamp values itself, commits a `sealed` over a history that
  carries no earlier `sealed`: the sealing commit amended or rewritten
  there over its own parent, or a second seal on a copy of the branch that
  had not fetched the first. That clone draws the stamp again, because
  across clones the history is the only record read and nothing beside the
  tree counts stamps. The clone that drew the stamp keeps its values, so an
  amend there draws nothing. A squash or a cherry-pick of the guarantee onto
  another branch draws nothing, and neither does a `sealed` whose
  `Target SHA` names a commit the branch does not hold. That `sealed` still
  counts as the work item's one stamp, and so does a `sealed` that queued
  nothing because a person committed it outside a Claude session, or a
  clone whose git hooks slot is somebody else's committed it: no later
  commit of that history draws the stamp, a corrected row or a re-seal
  from a clone that carries the hooks among them. The history cannot tell
  such a `sealed` from a stamp drawn before a rebase, and #976 carries that
  gap. The stamp's rows
  are what the records at that commit say: the audited commit and its branch,
  the base, the work item, the newest broad run, and the count of round
  records. The suite's counts are no longer on it.

  `seal-stamp --from <path>` is unchanged, and so are `hooks/sealer-stamp.py`
  and the `specseal-stamp/` directory. A clone whose git hooks slot is
  somebody else's (`core.hooksPath`, or a hook file the plugin did not
  write) draws no stamp and prints no line, and neither does a repository in
  local mode, where no commit carries `guarantee.md` (#976). There the pull
  request's check is what says the work item was sealed, and a `sealed`
  committed where the hooks slot is somebody else's still counts as the
  work item's stamp afterwards, as above.

  The sealer's definition changed by one clause, so it was measured again

- **The broad gate's run says `BROAD GATE PASSED` or `BROAD GATE FAILED`,
  and draws nothing (#975).** The `SEALED` and `NOT SEALED` heads are gone:

  report's rows as plain text and the line saying `broad-gate.md` is not
  committed, the same on a terminal and a pipe, with ASCII marks on a
  console that is not UTF-8. It writes no stamp values and draws no disc.
  Its refusals say `run` where they said `seal`, for example "there is no
  command to run". A script of yours that looks for a line starting `SEALED`
  in the gate's output should look for `BROAD GATE PASSED`.
