## 0.23.1 — 2026-10-28

### Changed

- **Each directory of the plugin holds one kind of file (#1060).** `templates/records/` holds the shapes of the records a work item and a release write: `sdd-design.md`, `sdd-gaps.md`, `sdd-guarantee.md`, `sdd-phase.md`, `sdd-plan.md`, `sdd-questions.md`, `sdd-round.md`, `sdd-routing.md` and `process.md`. `templates/setup/` holds the files written into a repository: `claude-md-block.md`, `config.md`, `hygiene.yml`, `pact.md`, `parity.md` and `seal-README.md`. Each file keeps its name. The top of `hooks/` holds `hooks.json`, `dispatch.py` and the 15 gates `dispatch.py` runs, and the 13 modules they read stand in `hooks/lib/`. `hooks/hooks.json` is unchanged, so an installed repository registers the same hooks.
- **A test file stands in the directory of what it tests (#1060).** A module test file stands in `tests/hooks/`, `tests/skills/`, `tests/github/` or `tests/evals/`, by the first directory of the path its `TARGET` names, and `seal layout --check` refuses one that stands elsewhere, naming the directory it belongs in. A test file that declares no `TARGET` stands in `tests/behaviour/` where its cases load or run shipped code, and in `tests/text/` otherwise. Every test file takes the repository root from `tests/conftest.py#ROOT`, and no two Python files under `tests/` share a name. `CONTRIBUTING.md` *The test layout* states the rule.
- **`docs/README.md` indexes the policy documents by subject (#1060).** Its one table is one table per subject, each row unchanged, and every document stays at the top of `docs/`.
- **Two sentences in an installed repository name a path that moved (#1060).** A `seal/README.md` written before 0.23.1 cites `hooks/optin.py#MARKER`, which is now `hooks/lib/optin.py#MARKER`, and the comment `seal mode` wrote at the top of `seal/config.md` cites `templates/config.md`, which is now `templates/setup/config.md`. Nothing reads either sentence, and no migration rewrites them.
- **The preset block on a machine names a template that moved, and the update from 0.23.0 cannot refresh it (#1060).** The block between `<!-- agentic:start -->` and `<!-- agentic:end -->` in `~/.claude/CLAUDE.md`, or in a project's `CLAUDE.md`, tells a session to write `routing.md` from `templates/sdd-routing.md`, which is now `templates/records/sdd-routing.md`. `/agentic:update` run from 0.23.0 compares the block with `templates/claude-md-block.md` in the marketplace clone, which is now `templates/setup/claude-md-block.md`, so its comparison reads no source. After the update, rewrite the block where it stands: `bash ~/.claude/plugins/marketplaces/agenticseal/install.sh "$HOME/.claude/CLAUDE.md"` for the block in `~/.claude/CLAUDE.md`, or `bash ~/.claude/plugins/marketplaces/agenticseal/install.sh --project` from the project's top directory for a block in that project's `CLAUDE.md`. Each writes the 0.23.1 block over the old one and backs the file up first.

### Removed

- **Eight general skills that no record shows used (#1060).** `debug`, `build-fix`, `checkpoint`, `gap-analysis`, `security-audit`, `testing`, `learn` and `audit` are gone, and the plugin ships fourteen skills. The commands `/agentic:security-audit` and `/agentic:testing` no longer exist for a user who types them, and no skill reads a repository's `.claude/audit-rules/*.md`. Git history holds each skill.

### Changed

- **The stamp's mark is the owl (#857).** The sealer's stamp draws a 16 × 16 owl at the centre of its 28-cell wax disc, where it drew a placeholder S from 0.20.0 through 0.23.0. Every cell of the owl is one of the stamp's own reds, and no cell is shaded by its neighbours. The disc's frame and the panel beside it do not change. `skills/verify/scripts/seal-mark.txt` holds the sprite, one letter per cell, and `assets/seals/README.md` gives the owl's entry with the command that draws it again.
- **An installed user sees the owl from their first session after updating (#857).** The stamp is drawn by the installed plugin, so a session still on 0.23.0 draws the S. A stamp queued before the update and drawn after it shows the owl, because what a hook queues carries the panel's values and no disc. Nothing in a user's repository names the mark, so no repository migrates.
- **The plugin has an icon (#857).** `.claude-plugin/plugin.json` names `.claude-plugin/icon.png` as its `icon`, a 512 × 512 PNG drawn from the owl's vector, `assets/seals/owl.svg`. Claude Code ignores the field when it loads the plugin, and Anthropic's plugin directory reads it. The directory takes the icon only the first time the plugin is saved or submitted in its portal.
- **The release note's seal is the plugin's icon (#857).** The publishing job attaches `.claude-plugin/icon.png` as `seal.png`, shown at 256 CSS pixels, where it painted the stamp's disc cell by cell at 168. Where the manifest names no icon, or the file is missing or is not a PNG, the job prints one warning naming the cause, uploads nothing and leaves the note as it was published.

### Removed

- **Pillow is no longer installed (#857).** Its only reader was the release seal's painting, which is now a copy. `bin/test` no longer installs it into `.venv`, neither CI workflow installs it, and the fallback commands in `CONTRIBUTING.md` no longer name it. A `.venv` that already holds it keeps it, and nothing reads it.

### Changed

- **A pull request body routed through the review chain opens with the work item's records, copied by `seal pr-body` (#1044).** The new command `seal pr-body <item> --body <file>` writes the part of the body above the line `## Not from the records`. That part holds the changelog fragment, the plan's phases table and the paths of the phase records, each review round's `target:` line with the `severity:`, `verdict:` and `answer:` lines of its findings, the broad run's record, the *Not verified* and *Not done* sections of `gaps.md`, and every table line of `frame/questions.md`. The command copies lines and writes no count, summary or rewording of its own, and a record that is missing is named by a fixed sentence. It refuses a record line it would copy that holds a closing keyword outside a code span, at that record's line, because the `Closes` line is the orchestrator's alone. Run again on the same file, it rewrites the part above the line and keeps the part under it byte for byte.
- **The orchestrator writes the body after the broad run's record, and writes only under `## Not from the records` (#1044).** It runs `seal pr-body` once `trail/gate.md` is committed, then writes under the line what no record holds: the motivation, the `Closes` line, the broad run's printed figures and the attribution line. Where its part needs a record's fact, it names the record's path instead of restating it. It runs the command again before every later spawn of the sealer and before every edit of an open pull request's body.
- **The sealer checks the copied part and reads only the orchestrator's part (#1044).** Its step 2 first runs `seal pr-body <item> --body <file> --check`. On any exit but 0 the verdict is `withheld`, and its reason is the first line the command printed, which names the body file by its name and a record by its path under `seal/`, so no machine path reaches the committed `guarantee.md`. On exit 0 the sealer reads the part under the line as the orchestrator's account, and the part above it as no party's.
- **Where `Commit and pull request language` and `Record language` differ, a body is in two languages (#1044).** The copied part is in the language of the records, and the orchestrator's part in the language the row names. No repository's config changes.

### Removed

- **The orchestrator no longer writes the body by hand before the broad run (#1044).** Most of a hand-written body restated a record, and in 0.22.x 23 of the sealer's 27 withheld runs named the body. The sealer no longer weighs the whole body as one party's claims, because only the part under the line is written by hand.
