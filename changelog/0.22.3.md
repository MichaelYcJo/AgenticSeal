<!-- specs/1792449518-settle-squashes-specs-into-docs-in-place -->
### Changed

- **`settle --apply` applies each released spec's rule changes to `docs/` in
  place (#953).** A spec states the rules it changes in a `## Rule changes`
  section: an operation line (`- add`, `- change`, `- remove`) and the fields
  `file:`, `section:`, `from:` and `to:`, one per line. The grammar is
  `skills/settle/SKILL.md` §*Rule changes*, and
  `skills/settle/scripts/rule_changes.py` is its one reader. `--apply` works
  in merge order, the later spec winning, and applies a spec whole or not at
  all. It writes no marker, and removes each applied spec's directory whole,
  its process record included. A spec it cannot place, one whose record holds
  an open row, and two that merge order cannot decide at one place (a
  section and a sub-section it holds are one place) are
  refused at their line and stay. So is a `file:` holding `\` or `:`, one
  differing from another document only in case, and a `nothing` line written
  with a hyphen, which is told to use the em dash. `settle` with no flag is
  the dry run.

  `settle --retire` and `settle --retire-process` are gone, and a script that
  calls either gets an argument error, exit 2. A spec with no
  `## Rule changes` section was written before it existed: `settle` names it,
  keeps it, and counts it in its last line.

- **The CI readers tell a settle from a deletion without a marker (#953).**
  `unverified-check --baseline` and `chain-check` accept a directory removed
  whole when, at the merge base, nothing in its record is open and either it
  states no rule (no `spec.md`, or a spec with no `## Rule changes`) or its
  rule changes, replayed over the base's `docs/` in merge order, are what
  `docs/` holds. A `<!-- specs/<id> -->` marker no longer excuses a removal.
  `unverified-check` names such a directory `settled`, where it said
  `folded` or `retired by the rule`.

- **One read is a token row, and a report (#953).** `Document token
  ceiling` replaces `Document line ceiling`, and `Over the ceiling` is no
  longer read. `fold-check` and `settle --apply` name each document whose
  estimate (UTF-8 bytes halved) is past the row as one to split along its own
  headings, and exit 0 on it. A repository that declared a line ceiling has
  no size check until it declares the token row.
- **The policy root is a row, and it has an index (#953).** `Policy root`
  (default `docs`) names the directory `settle --apply` writes and every
  reader of the policy reads; the first `--apply` creates it with an empty
  index. Where `<policy root>/README.md` exists, `fold-check` refuses a
  document no row names, one named on two rows, and a row that names none.
  This repository's index is `docs/README.md`.
- **A pull request does not edit the policy root (#953).** The `implement`
  skill states the model once: the policy root is the baseline, and the
  policy in force is it plus every unsettled spec's rule changes in merge
  order. The framer writes `## Rule changes`, picking each file from the
  index, and nothing gates the rule yet.

### Changed

- **A rule names what reads it on one `check:` line (#941).** The line names
  repository files, eval case directories `evals/behaviour/<agent>/<case>/`,
  or a marker its tests carry as `@pytest.mark.rule("<marker>")`, separated
  by single spaces; a rule nothing can hold writes
  `check: none reader: <who reads it>`. The grammar is
  `skills/settle/SKILL.md` *A rule has one shape*. `rules --check` refuses
  every other spelling at its line, exit 1, naming the spelling it expected:
  `Enforced by:`, another case, a space before the colon, a value holding
  `::`, a comma or an em dash, a reader with a space more after `reader:`,
  and a label with nothing before it but Markdown block markup (a heading's
  `#`, a list bullet or number, a task box, a blockquote's `>`, a table's
  `|`) or emphasis. A consuming
  repository's `Enforced by:` lines are refused until rewritten. `rules
  <doc>` prints each target's module docstring, or for a marker each test
  carrying it.
- **A spec that changes or removes nothing writes the no-change block
  (#941).** In `## Rule changes` and `## Removes`, `- nothing` with its one
  field `why:` replaces `nothing — <why>`. `settle` refuses every other
  spelling of a no-change line at its line, naming the block, and the block
  stands alone in its section.
- **Every policy document under `docs/` states the current rule once
  (#941).** Each keeps its rules, their grounds and their `check:` lines, and
  drops the history, the issue numbers, the section signs and the readers'
  mechanics, which the cases named on those lines hold. Every document fits
  one read, so none is split. `docs/one-root-by-lifetime.md` and its Korean
  edition are no longer the 0.4.0 design record: both state what still rules,
  the root, the dependency rule, the opt-in, first setup, naming and the
  config rows, and its six dated decision sections are gone. Headings that
  carried a dash, a middle dot, a pipe or an issue number are renamed:
  *Registration*, *The PreToolUse reading of a commit*, *Which repository*,
  *The implementer mark and notice*, *The commit gate inside git*, *Review
  arm*, *Parity arm*, *Creation consent*, *Decided before git runs*,
  *Declared work streams*, *Which tree*, *2b. Settle what earlier releases
  left behind*, *3. Verify before committing* and *The opt-in signal is the
  root itself*.
- **`fold-check` no longer reads a rule's shape (#941).** The `Fold shape
  from` row is read by nothing and `--shape-from` is gone; a script that
  passes it gets an argument error, exit 2. `fold-check` holds the policy
  root to one read and one index.

  where that table is missing, a cell is not one code span, a `Means` is no
  label, a spelling is a label or stands twice.
- **The release pull request's title is `release: X.Y.Z symptoms: <the
  symptoms the release answers>` (#1000).** `docs/release-checklist.md`
  §*5* gives the command, and `publish-release.yml` reads the line from the
  tagged merge commit whole, so the release that ships this is the first
  whose session types it. Any other line, the old `release: X.Y.Z —
  <symptoms>` among them, publishes the note under the tag name, exit 0, and
  the job log names the shape it expected and the first `release:` line it
  found. The published title keeps its `X.Y.Z — <symptoms>` form, and no

### Fixed

- **A spec whose `## Rule changes` does not parse now fails its own pull
  request (#1006).** Before this, the section was first parsed at the
  owner's settle after the release. There a section that does not parse
  applies nothing, and no pull request is left to fix it in. `chain-check`
  now parses the section with the reader `settle` uses, in the spec of each
  work item whose `routing.md` it judges, under either `Planning` answer.
  On a pull request that declares a work item, it also parses every work
  item spec the pull request's own commits add or change, since a declared
  work item can edit another work item's section. A refusal names the spec,
  the line the reader names and the reader's reason. It fails a ready pull
  request and prints on a draft. The broad gate's own run prints it, and
  fails on it only where a ready pull request is already open. A spec with
  no `## Rule changes` section, a work item with no `spec.md`, a spec
  another pull request's squash carried, a spec only moved, and every spec
  of a pull request that declares nothing are left alone. Where the reader
  will not load, the check exits 2 and says so.
- **A near miss of the `## Rule changes` heading is refused instead of read
  as a spec with no section (#1006).** A heading at any level whose letters,
  case folded, are those of `Rule changes`, such as `## Rule Changes` or
  `### Rule changes`, and that is not `## Rule changes` itself, is refused at
  its line. Before this, `settle` named such a spec as one written before the
  section existed and applied nothing from it. Now `settle` holds it, and
  `chain-check` refuses it at the pull request. A heading with other
  letters, such as `## Rules changes`, is still another section.

### Changed

- **A rebuilt module's tests stand in one file that names it, grouped by function (#942).** A test file declares `TARGET`, the module it tests, as its first statement after the imports, and holds one class per public function of that module, with cases that accept beside cases that refuse. `bin/test-layout --check` refuses a class that names no function of its target, a function class without both kinds of case, and a helper defined byte-identically in two test files. `bin/test-layout --pairs` names two cases of one class that call the function with equal arguments, and exits 0. The commit flow and the creation flow, which run real git end to end, stand in `tests/e2e/commit/` and `tests/e2e/creation/`. 69 test files declare a `TARGET`. Seven shipped modules have no such file yet, and 114 test files still declare none, each for a reason `overview.md` *Not done* names, so the suite case runs `--check` without `--all` until a later settle frees them.
- **A module whose cases were only moved is decided by a check, not by the record (#942).** `bin/test-layout --moved <base> --from <old files> --to <new files>` exits 0 only where every old case lands once, its body unchanged, its fixtures unchanged, and every name it and its fixtures read defined as the base defined it. It follows a name into another test file and into an import made inside a function body, and prints each failing case with every name it reads apart. Its four limits are stated in `skills/verify/scripts/test_layout.py`'s docstring. A group that passes skips the mutants; a group that fails runs them for each module its failing cases send.
- **A rebuilt module's proof is one batch of decision-point mutants (#942).** `bin/mutation-check <path> --tests <command> --replace OLD NEW`, with `--replace` given once per mutant, runs the baseline once and each mutant once, and prints one verdict line per pair. The old files run only for a survivor, so a mutant that survives both is recorded as a gap the old tests already had. The 178 such gaps are on #1017.
- **A slow case is reported, not failed (#942).** `tests/conftest.py#SLOW_CASE_S` names each case whose call runs past it in one line at the end of the run, and the run exits 0. The failing ceiling and its environment variable are gone.
- **A census runs with its module, and its exemptions sit beside the line they exempt (#942).** `tests/censuses.py` holds each census as a function, `tests/conftest.py#census_case` gives every module's file one case that runs them, and an exemption is a comment line directly above the exempted line. A comment above a line no census flags is refused, and the stored exemption lists are gone.
- **The release table has a row per test file (#942).** `release_report.py#module_rows` reads `.test_durations` at the tag and at the head and prints each file's cases and seconds at both.
- **The suite runs in half the time locally (#942).** `bin/test -q` took 183.9 s over 7,494 items at the base and 91.4 s over 7,726 at 6a54be98, on macOS.
